## 5. RNG 流变动的量化（三态归因）

生成期（normal 模式，生成后立即取；`drawsGen` = SUBSTANTIVE 抽取计数）：

| seed | 指纹（HEAD → WT2） | drawsGen（HEAD → WT2） | D1 外推说明 |
|---|---|---|---|
| 1 | `0bdbadb4:4620` → `757b5338:4684` | 3547 → 2997 | 指纹串长亦变（4620→4684），内容重排而非碰撞 |
| 42 | `912b13f0:4683` → `72ff785c:4670` | 3833 → 4569 | 同上 |
| 2026 | `f0d19429:4701` → `69bdbfee:4683` | 4145 → 2537 | 同上 |
| 999999 | `10b83aff:4612` → `ac0f623f:4767` | 3039 → 7274 | 同上 |

- **WT2 与 WT3 全部数字相同**：同期的毒药水退池（`consumables.json` +`excludeFromGeneration`，
  minDepth=2）对 D1 无可观测影响（D1 本就不会生成 minDepth=2 的物品），归因无混杂。
  深层的退池效应未测（不在本轮范围）。
- **D1（seed 20260914）分布重排**：改动前 Rat×5+Kobold×2、地面 Leather Armor + Wand of
  Teleportation；改动后 Rat+Jackal×2+Kobold×3、地面 4 件（Potion of Strength、
  Scroll of Teleportation、Potion of Invisibility、Dagger）。**既有基线表全部失效**。
- 结构性成因与交付报告一致：Item 创建每件 −1 次抽取（开局道具包在生成早期，错位其后全部
  序列）；Monster 游走/混乱每怪每回合 +1~2 次（改从种子流取）；Creature 的 id 原本就不占
  种子流，改计数器对玩法流中性。100 回合游玩期抽取数示例：seed=999999 为 146 → 469 次/百回合
  （游走抽取消耗显性化），符合机制预期。

## 7. 观察与建议（只列不修）

1. **读档移动玩法流**（交付报告"边界外发现"，本评审复核属实）：`loadSnapshot` 重建怪物
   时走 `Monster` 构造器的 `rng.randPercent(70)` 睡眠判定，读档本身消耗 SUBSTANTIVE。
   P2 做 tick 系统时若要求"读档后流位置与存档时点一致"，需保存/恢复流状态或改免抽取构造。
2. **嵌套 COSMETIC 段限制**（交付报告 §9.4，论证成立）：`Random.ts` 的 `currentRNG`
   无读取接口，成对用法只能"显式恢复到 SUBSTANTIVE"。当前唯一 COSMETIC 使用点
   （GameCanvas 辅助函数 + ItemLoader.initConsumables）不嵌套，严格等价；未来若出现
   嵌套需先给 Random.ts 补接口。
3. **并行会话风险**：本次两会话在同一工作区执行同一任务是用户侧调度问题，建议避免；
   交付会话的"终局快照 vs 逐回合轨迹"测试设计教训（其 §4.1）值得后续轮次引用。
