# 全库「挑 seed 的测试」审计报告

## 1. 扫描口径

- 审计范围是 `src/test/*.test.ts` 的 **88/88 个文件**。先用 `seed`、
  `createHeadlessGame`、`generateDepth`、`find/findIndex`、提前 `break`、快照/基线和
  精确相等断言交叉建立候选集，再逐处读测试的舞台、选样条件、断言对象及反空转
  前置；没有把文本命中直接当成问题。
- 纳入判据严格采用任务书的二联条件：**样本由 RNG 决定**，并且测试把该样本的
  **偶然派生值**当成合同。固定 seed 本身不是罪：手工清空地图、显式 spawn 对象、
  mock RNG，或只断言对所有对象都成立的机制性质，均不列为高风险。
- `.find(` 不能作判据：大量命中是按稳定 id 查 JSON、按对象身份找刚生成的 clone、
  或在人工舞台中找已知对象。`toBe(<数字>)` 同样不能作判据：目录常量、公式边界、
  回合时钟和手工坐标都与生成抽样无关。反过来，AD3 的危险 pin 是 `toEqual([])`，
  两种 grep 都无法可靠发现它。
- 风险等级按任务书定义；“响/哑”描述的是**生成流移动后的主要败法**。若测试已有
  显式非空前置，样本消失会响；若被钉集合本身允许为空并以空数组为成功值，则会哑。
- 本表刻意不把 `generation_baseline` 的设计目的说成错误：它确实是有意的滚动快照；
  但按本轮定义，它仍是“固定 RNG 样本 + 非普遍派生值”，所以必须登记，而建议是
  **保留且明确隔离**，不是删除。

### 审计中排除的主要“看起来像、实际不是”类别

1. `p1_20`、`p1_26`、`p1_29`、`p1_33`、`blueprint_center`、`v_2b_6_keys`
   等均遍历所选 seed 的**全部层/全部对象**，断言可通行、连通、钥匙匹配等普遍性质；
   seed 只是有限样本量，不是从中挑一个走运对象再钉偶然值。
2. `c_1_room_profile` 的 D1 入口房、零频率房型和 draw 计数来自频率表的结构性
   不变量；其中大洞窟 `>10` 还是显式覆盖度守卫，不是精确随机快照。
3. 合成火场、固定 RNG 序列和 `generation_baseline` 不同：前者先人工固定场景，只钉
   算法 RNG 的时序输出；不会因为地牢生成蓝图池变化而换被测对象。
4. 按 id 查背包、数据表、怪物目录的 `.find`，以及按对象身份找 clone，选样与 RNG
   无关，故未逐条塞进风险表。

## 3. 高风险前三条的最小验证

### 3.1 AD3：已由仓库内同口径全扫数据定量证伪，但本云端未能复跑

- 测试自身保留了最近一次全扫记录：5 seed × D1-D26 中共有 **31 个有机器层，
  25/31 层 `A≠B`**，且差值双向出现；这直接证明“首个层的派生集合”不是全体样本
  不变量。
- 当前被选层把 `outsideInterior` 精确钉成 `[]`，因此这条 pin 的循环覆盖数为 **0**；
  它就是已确认的哑败法，而不是假设。
- 尝试执行定向命令时，本工作区没有本地 vitest，`npx` 转而访问 npm registry 并收到
  HTTP 403；遵守 §0，没有扩大到全量门禁，也没有继续耗时联网安装。因此上述数字采用
  测试文件中 V-2b-3 留存的同口径实测，未伪称本轮新跑结果。

### 3.2 滚动生成基线：静态验证 104 个样本、416 个派生字段

- fixture 定义 4 seed × 26 层，即 **104 层**；每层钉 4 个派生字段，共 **416 个
  字段比较**。地形 fingerprint、物种和数量显然不会在所有 seed/层上相同，fixture
  本身也保存了各样本不同的值，故“不具全体样本普遍性”已由数据结构直接确认。
- 这是有意的响式哨兵；风险不是当前假通过，而是每次合法生成变更都要求诊断和重采。
- 定向运行同样被缺依赖/registry 403 阻断。

### 3.3 loopMap 跨局前提锚：未完成动态换 seed 验证

- 最小替换应把读档方由 seed777 换成至少 2 个其他 seed，统计 `sameBefore`；但依赖
  无法安装，未执行，按 §0 的 5 分钟止损要求记为**未验证**。
- 代码层面仍足以定性：被钉的是“两张随机生成地图的完整 loopMap 不相等”，不是
  `loadSnapshot` 的合同；即使碰巧相等也不能推出生产缺陷。因此列高风险，但不捏造
  失败率。

`blueprint_center` 的 `treasuresAtCenter===0` 是明确的**禁止出现**合同，并有机器/扫描量
覆盖；`violations=[]` 也通常配有总量或全体遍历，不能仅因结果为空就误报为空转。

## 5. 建议的修复轮次拆分

1. **单独一轮（最高优先）：AD3。** 它既要拆掉 `A−B=[]` 偶然 pin，又要保住
   machineNumber 往返、`BP_NO_INTERIOR_FLAG` 清零和 interior 外 feature 三种不同合同；
   混在普通清理轮里容易再次“顺延”成空集合。
2. **一轮完成随机舞台去耦：** `p1_31` 的 loopMap/waypoint 两条、`p2_1` 两条、
   `b_4b` 金币拾取。全部只改测试，做法都是人工造 sentinel/怪/金币，不需生产改动。
3. **基线治理单独决策：** `generation_baseline` 不应机械“修掉”。建议只调整测试分组、
   命名和重采流程，使它明确是预期会随合法生成变更响的漂移检测；是否保留在默认门禁
   由维护者决定。
4. **低优先韧性轮：** `armor_display_effect` 人工铺邻格，以及给 life potion 首现区间
   增加逐 seed 诊断/覆盖统计。它们目前没有哑败法。
