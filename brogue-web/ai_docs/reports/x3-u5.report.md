## 2. 命令调度、持久化与 UI

- `auto_rest/search_long/run` 的首步在初始命令中执行，后续每步由原 `stepAutoPath → executeCommand('auto_step')` 调度；每步之间交回浏览器事件循环。`isAutoTraveling()` 包含新的持续行动，GameCanvas 的实际 ticker 与自动化测试时钟都使用该判定。
- 投掷选点期间拦住新自动命令，避免把楼梯坐标误交给投掷确认。每步经过 U4 的 `inAutoTravelStep`、消息打断与安全确认边界；没有另起同步长循环，没有绕过录制或玩家移动防呆。
- 新 `autoAction` 保存剩余步数和 CE 起始判断状态，随 run 快照深拷贝/恢复；无行动时不输出该字段，不影响普通黄金 trace。`inventoryAction` 属于可取消的界面意图，新局/读档/关闭/普通背包入口清空。两项已登记 `scripts/u03-state-contract.json`，存档 schema 未更改。
- 所有新增文案在 `zh_CN.json`；移除的命令栏检视与“等待或下楼”键移入 `zh_CN.legacy.json`，没有遗留死键。触屏新增长休息和长搜索，上下楼按钮明确标为前往楼梯；DPad 中心沿用原纯 wait。
- 窄屏按钮预留快捷键提示空间，长标签可换行。未改 FE-1 的 `ui/commands.dispatch` 边界。
