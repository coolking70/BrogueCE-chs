# U27 完整命令日志与 OOS 校验

## 规格与裁决

依据 `x-0-survey.report.md` §4.3 U27、§2 D23、§3.1 K38。录像格式升为 JSON v2；`loadReplay` 对 v1 和缺少校验字段的 JSON 直接返回 `false`，不迁移。CE `.broguerec` 二进制格式不在本轮范围。CE `Recordings.c:333-366,601-620` 在首次校验失败时停止回放；本实现依照该思路报首个分歧命令号，并按任务书额外比较位置、深度、tick、回合号及 RNG 两流完整状态。

CE `Recordings.c` 的回放确认行为与本轮“确认/取消可重演”要求存在差异：web 的录制保存每次同步确认的布尔结果，回放消费该结果，不弹浏览器确认框且不额外抽 RNG。背包恶意品确认与取消本来是分开的 UI 操作，因此各自记成命令。

## 实现

- `Game.executeCommand` 是用户命令边界。键盘和 AgentControls 经 `handlePlayerAction` 进入；鼠标移动/目标点击、背包装卸、丢、喝、读、投、吃、用、鉴定与附魔选物、命名及确认/取消经同一边界进入。关闭背包也通过 `escape` 命令。搜索、休息、楼梯、自动探索与坠落沿原动作路径进入。
- 自动寻路逐帧执行的每一步记为 `auto_step`。回放时 UI ticker 不自行推进路径，只消费日志中的步骤。
- v2 每事件记录动作、参数、确认结果、位置、深度、tick、`absoluteTurnNumber` 和 `rng.getState()`（两条流的状态与计数）。`replayStep` 每步比较，首个不一致设置 `replayError`、停播并显示 OOS 命令号；seek 复播时也经过相同校验。
- 仅新局开始的日志可导出。读档后继续游戏不会追加可导出的录像，导出时报明原因；新开一局恢复录制。U00 旧夹具直接注入 v1 对象再调用 restart/seek 时仍走新局清理路径；对外 `loadReplay(v1)` 仍拒绝，旧事件不播放。
