## 1. CE 核实与任务书表述纠正

**CE 的 `cellIsFeatureCandidate` 没有 HAS_ITEM / HAS_MONSTER / HAS_PLAYER / HAS_STAIRS 通用排除。** `Architect.c:492–588` 使用 feature 的 personalSpace/occupied、视图、距离和地形/机器资格；`MF_BUILD_AT_ORIGIN` 在 occupied/view 检查前返回。把所有 pending 产物都加进 feature 的 usedCells，或无条件禁止同格，会改变 CE 合法的地形/物品/怪物叠放。按任务书“与 CE 冲突时以 CE 为准”，本轮没有加入该错误门。

| CE 消费点 | 实际占用合同 | 本轮处置 |
|---|---|---|
| `Architect.c:398–434` 房间递归 | 检查每个邻格的 HAS_ITEM；在已访问/chokeMap 界检查之前。另检查非 gate 的 IS_IN_MACHINE | 给 `mapMachineInterior` 传入当前 engine 的 pendingItems 查询；包含最终 interior 之外相邻物品的反例。既有 web 对机器 gate 的更严格规则不在本轮改动 |

### 同格双产物反例与正确的“零”口径

专项构造完整父子事务：父 feature 在 origin 生成地面物品，然后同一 feature 建前厅；前厅也在该 origin 产物。旧实现返回成功且产生两个不同实例的同格地面请求；修复后前厅因 HAS_ITEM 失败，父机器整体回滚，已提交双产物数 **0**。另验“第一个子机器落物 → 父的后续 feature 再建前厅”同样拒绝并回滚。不是在 populateLevel 丢掉第二件来掩盖碰撞。

104 层自然样本按 U25 最终产物记录分开统计地面物品/活动怪物，同类同格多实例组 **0**；入口和最终均为 0：[原始扫描](u-19b-evidence/overlaps-s3.json)、[汇总](u-19b-evidence/acceptance-summary.json)。因此自然样本不充当反例；删除前厅占用后的构造守卫确实红。

**“任何同格双产物都必须为零”与 CE 冲突。** 物品和怪物可共格，BATO 可以绕过 personalSpace，零 personalSpace 不预留格；CE `placeItemAt` 本身不做通用去重。测试显式保留这些正例。未以扩大禁叠范围修复本轮问题。
