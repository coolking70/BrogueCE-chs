# U16 死亡、寄宿、复活与群体继任报告

## 规格与 CE 核对

以 `x-0-survey.report.md` §3.1 K13、§4.3 U16 为准，逐项核对 BrogueCE 的 `Combat.c:1934-2046`、`RogueMain.c:951-981`、`Monsters.c:985-1070,2898-2945,4086-4153`、`Architect.c:3365-3368`。CE 的死亡顺序为携带物掉落、死亡 DF、标记死亡、原格释放寄宿怪并设 200 tick、尸体学习、领袖降级。CE 的 purgatory 条件比任务书“盟友死亡”更窄：仅玩家直属、允许复活、具有武器自动鉴定资格、非管理性死亡者入池。Web 以 `isAlly && leader === null` 表示直属玩家盟友，并以 `leaderlessAfterDemotion` 区分 CE 中普通继任选出的无领袖怪；无生命体仅 `MA_ENTER_SUMMONS` 例外。

## 实现

- `MA_ENTER_SUMMONS` 将召唤者从场上摘除，寄存在最后一个新生随从；无随从时恢复原怪。宿主普通死亡时在原格释放，设 200 tick 并执行落格环境效果。对自身、已处理死亡者和已经在场的异常引用加防重守卫。
- 死亡清扫改按 CE 顺序执行。携带物经现有 `captiveItemDropCandidates` 选择可放置格，避免覆盖已有物品和重复加入；死亡 DF 随该怪的死亡处理触发一次；随后释放寄宿者、处理学习和继任。普通死亡会对当层活跃及休眠怪执行 `demoteMonsterFromLeadership`，跨层随从沿用已实现的“当前层优先，再按层深度”选择，束缚/休眠随从解绑。
- 符合 CE 条件的盟友进入 `Game.purgatory`。该列表及 `doesNotResurrect`、`leaderlessAfterDemotion` 字段已加入 U01 实例字段清单及 U03 整局快照图；旧快照缺少列表时按空列表读取。复活后仍为同一实体，恢复生命、清理死亡/坠落和指定状态；再次存档可还原。
- `DFF_RESURRECT_ALLY` 通过按 Grid 注册的 Game 回调执行，空池返回失败。候选先比较 `totalPowerCount`，同分按 `monsters.json` 中的 CE 物种序号取较大者；落点按可通行且无害地形的最短路径选取，并列随机，路径无候选时按附近格回退。
- CE 的 `RESURRECTION_ALTAR_INERT` 是独立地形，Web 尚未收录。保留目录中 `DF_ALTAR_RESURRECT.tile = null` 的事实登记和目录守卫；仅在祭坛的实际 `promoteTile` 路径将复活成功后的地形表示为现有 `ALTAR`。这保持祭坛单次触发，同时不擅自扩展蓝图机器的生成池。
