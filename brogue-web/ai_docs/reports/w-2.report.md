## 2. autoID 真正评估与未知态

CE `Items.c:5112–5119/5470–5474/5567` 将 autoID 定义为效果观察，`:7397–7405` 才按返回值鉴定。W-1 的两条执行出口现在分别在 `applyBoltResult` 和 `castMonsterBolt` 写入 `{ autoID, casterMovement }`；纯 `computeBoltResult/createBoltResult` 仍是 `outcome=null`，明确区分“未评估”和“已评估 false”。被实墙阻断的怪物 SPARK 也返回已评估结果；如果先激活了电晶体，再受阻，则是 true。

| 观察 | CE 依据与本轮处理 |
|---|---|
| FIRE/LIGHTNING、怪物伤害/物理 bolt | `Items.c:5136–5150`：接触/调用伤害不是按扣 HP 成功鉴定，免疫/反射甚至物理 miss 不一概降成 false。空地无作用不鉴定；实际火地形变化、电晋升（`:5444–5465`）可鉴定。没有为观察再执行一次点火、伤害或随机判定。 |
| TELEPORT | `:5220–5227` **没有设置 autoID**。实际移动目标也不会“用过即亮”；不凭颜色或命中推断成功鉴定。 |
| SLOW/HASTE/HEALING | `:5242–5259/5366–5370`：slow/haste 分支有明确观察，heal 在可观察对象上鉴定（满血也不是强制 false）。玩家原有 heal/haste 仍作用于自己，本轮观察这个实际旧效果；不借 autoID 修正目标或数值。 |
| POISON/DISCORD | `:5312–5340/5390–5404`：合格、可观察目标及被接受的状态施加。现有 status helper 的 false 也可能表示“已有时长不增长”，所以重复接受与真正免疫分开判断，不把 false 一概当失败。玩家 discord 原有 confused 错配保留后续轮。 |
| INVISIBILITY | `:4941–4960/5269–5272`：合格目标；玩家/盟友可鉴定，普通敌人消失不自动鉴定，敌人需要可观察且被 telepathy 揭示的条件。原有空射自隐形仍存在，因真实自施可观察而鉴定，W-9 再改效果目标。 |
| EMPOWERMENT / BECKONING | `:5312–5320/5229–5239`：前者在可见合格目标实际执行强化后；后者在可动、非贴身目标实际移动且移动前/后可察觉时。未实现 CE 完整强化或反向 blink。target 的移动不能冒记为 casterMovement。 |
| NEGATION / TUNNELING | `:5301–5310/5812`：只观察现有实际状态/HP 变化或实际挖掘；不补缺失消魔能力、不改墙在旧轨迹中进不了 path 的问题。 |
| CONJURATION / 尚无效果的类型 | `:5494–5514` 的 CE true 位于实际召唤后。现有 conjuration 只有文案/飘字，明确 false；POLYMORPH/PLENTY/BLINKING 等无执行效果也不能声称 autoID 成功。玩家旧 SHIELDING=telepathy 不冒充 CE 护盾；怪物既有 shielded 状态可被观察，吸伤量仍留 W-15。 |

旧提前鉴定已移除。成功放电先执行、再按结果 `identifyItemKind`，不会主动全鉴实例；空射/失败仍可保留风味、绰号和使用次数。消息中的物品名使用 `displayName`；未知射线帧用中性字符/颜色，未知 miss 与召唤空桩使用通用文案，不由无效果文案泄露真实名称。已识别物品仍保留既有说明。没有新增或修改效果数值、伤害公式、移动算法、状态行为或召唤实体。
