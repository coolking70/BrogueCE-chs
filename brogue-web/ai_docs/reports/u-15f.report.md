# U15f：食物确认与临饿死自动进食

## CE 合同与执行路径

- `Rogue.h:1124-1127`：`STOMACH_SIZE=2150`，`HUNGER_THRESHOLD=350`，`WEAK_THRESHOLD=150`，`FAINT_THRESHOLD=50`。`Globals.c:1577-1579`：口粮营养 `1800`，芒果 `1550`。Web 的 `Player.ts` 常量和 `consumables.json` 数值一致，未修改目录和数值。
- 手动 `apply(FOOD)` 进入 `Items.c:7477-7505 eat`，当 `2150-currentNutrition < food.power` 时询问“还不够饿，仍要吃吗”；等号时不询问。拒绝直接返回 `false`，`apply` 在 `Items.c:7600-7603` 随即返回，故无消耗、回合推进或 RNG。接受则营养加至最多 2150、输出口粮/芒果各自消息、消费背包物品，然后 `Items.c:7633` 结算玩家回合。
- `Time.c:2658-2698` 在每 100 tick 的客观块内调用 `decrementPlayerStatus`。`Time.c:2213-2220`：麻痹时既不扣营养也不检查；携护符时以 20% 门扣营养。其后的 `checkNutrition`（`:927-970`）在营养 `<=1` 时按 `packItems->nextItem` 链表顺序找**第一件 FOOD**，先发“无法控制饥饿而吃……”消息，调用 `eat(theItem,false)`，再调用 `playerTurnEnded()`。不是优先口粮，也不是按营养值排序；本次自动路径不记录 apply 命令。嵌套回合在当前尚未扣完的玩家 ticks 内执行，没有新加一个 movementSpeed 延迟。没有食物且营养为 1 时立即置 0 并发饿死警告；`Time.c:2517-2523` 的主观回合结算每次扣 1 HP，至零死亡。
- CE 此进食路径没有芒果治疗。Web `consumables.json` 的芒果描述仍写“略微恢复生命值”，是既存目录文案与 CE 不符；按任务 §3 禁改目录，登记待另案处理，未实现治疗。

## 实现与取消语义

`Game.eatItem` 在背包物品有效性、食物数据及剩余胃容量确认通过后，才调用共用 `consumeFood` 移除物品、增加营养、输出 CE 对应品种消息并结算回合。确认复用 `requestConfirm → onConfirmRequest`，客户端由 `App.vue:11-17` 接浏览器同步 confirm。取消前没有物品、时间、RNG、营养、鉴定状态变化；`u_15f_food.test.ts` 同时钉住这些量。无钩子的 headless 实例沿用现有默认确认语义。

自动进食在 `objectiveTimeBlock` 的营养递减后执行，先按背包数组顺序选第一件 FOOD，再经相同 `consumeFood` 营养/消息路径消费，随后嵌套执行 `playerTurnEnded()`。进食后同步玩家的饥饿显示档位；无食物时保留主观饥饿伤害和死亡路径。麻痹与护符 20% 门仍在 `Player.tickNutrition`，本轮仅回归，未重写。

## 三条真实入口

1. 背包 `InventoryOverlay.vue:327` 的“吃”按钮 → `performEat:246-249` → `Game.eatItem`。确认被拒时同步对话框返回 false，不消耗。
2. `Input.ts:78-80` 的 `a` 键 → `Game.handlePlayerAction('apply_item'):3134-3136` 打开同一背包 → 同一“吃”按钮和 `eatItem`；`i` 键亦可打开背包。`p1_46_keybindings` 与 `i_1_interaction` 回归入口。
3. 客观时间块 → `Player.tickNutrition` → `Game.objectiveTimeBlock` 的自动扫描 → `consumeFood` → 嵌套回合。新用例实测芒果排在口粮前时先吃芒果，且无饥饿伤害、不弹确认。
