## 2. 偏好图、位置合同与 40 点择点

### 图构建

- **敌方安全图**完全复用 `getSafetyMapForMonster`。察觉玩家时释放私有快照并用全局图；不察觉时只拍一次。隐形玩家仅相邻可察觉；否则看怪物所在格 FOV，CE Monsters.c:2372–2400。U18a 的 `safetyTerrainCosts` 保持原样。
- **盟友安全图**按 Time.c:1707–1775：四层 `genericPathCost`、圣徽、所有敌人源点（不要求玩家可见），玩家格两张 cost 禁入；两次四向扫描，中间 `50*d/(50+d)` 向零取整、乘 -3、IN_LOOP -10。没有误复用以玩家为威胁的图，也没有套敌方图最后的禁格值覆盖。
- **安全地形图**按 Time.c:1935–1984：阻通/密门后继、激活型驻留怪、非秘密的非有害 path blocker 按序禁入；有害格与门不给0源点，普通安全格给0，四向扫描。缺 `turnsSpentStationary` 的限制见 §8。
- **敌人图**按 Monsters.c:3174–3206：阻通格给 -2/-1、avoids 格 -1，距离0是防OOS值但禁格不传播；可走格初值10000；合格敌人格0、cost1，八向扫描。共享 `Pathfinding.ts` 的旧负 -2 对角问题没有被顺手修改：此新消费者独立按 CE 在两个公共邻格检查 -2，其余四向扫描复用原扫描器。旧消费者/生成行为原样保留。
- **目标距离图**按 Dijkstra.c:209–255 的当前地形成本：免伤驻留怪、可使用密门、物理阻通、traveler avoids；四向扫描。`pdsSetDistance` 可以从本身禁入的内部目标格播种，这与一般 batch 输入不同，已专门处理并测试。web 每次所需时重建，不持久化 CE 的 `mapToMe` 缓存，见 §8。

**重新核实出的 CE 敌人图细节**：Monsters.c:3194 是严格 `distance < shortestDistance`；`shortestDistance` 此前已经是第一次选敌得到的最近距离。所以普通可见最近敌人不会被再次设为0源点，常见结果是10000平图、不blink、继续步行。这不是按注释把“不追敌”修成 `<=` 的授权。真实可达的成功路径包括：第一次33%隐形识别失败、第二次扫描识别成功（ALWAYS 在第二次可短路），从而给更近隐形敌人播种；专项覆盖了此路径。

### 固定顺序与收益门

Monsters.c:2269–2370 已直接复核：

1. 本格偏好作为基准；按 N、S、W、E 比较四邻，仅不被 `monsterAvoids` 拒绝且严格更优的值能提高门槛。
2. `perimeterCoords(0…39)`：顶边11点左到右、底边11点左到右、左边9点上到下、右边9点上到下。半径5，无角点重复；目标加施法者位置，允许瞄准点在地图外。
3. 预测最大距离 `staffBlinkDistance(5)=12`。比较的是**冲击位置的偏好值**，保存的是**周界瞄准点**，最终 `zap` 仍对该瞄准点发射。
4. 只有严格更优才替换，因此平局保留最先候选，择点本身 **0 RNG**。
5. 更新最佳值后，若落点与起点切比雪夫距离 >1，或两个“反向”的公共邻格之一阻通，`gotOne=true`；否则清为false。后来的更优邻近对角格可以取消此前已经找到的长跳，不允许偷偷保留旧长跳。
6. 实际施放仍用 E5=12 原轨迹与落位原语；不反射、不接触伤害、不穿生物/物理障碍。隐形敌人会被预测忽略，但实际射线仍截停，这是 CE `getImpactLoc` 与 `zap` 的差别。

`BoltReflection.randomReflectionOffset` 仅改成“原来的一次 `randRange(0,39)` → 共用纯 `perimeterCoords`”；40点映射和值/顺序没变，原 W-4 只回归。
