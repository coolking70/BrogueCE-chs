### 物品不是另一个“每格搬走”分支

`fillSpawnMap` 的物品调用只有火格上的 `ITEM_FLAMMABLE → burnItem`（Architect.c:3262–3268）。Time.c:973–991 的 burnItem 删除物品、刷新/消息，继而调用 `DF_ITEM_FIRE`。本轮实际删除地面卷轴，生成 SURFACE 的 ITEM_FIRE，带 FIRE_LIGHT、promoteChance=3000、后继 EMBERS、FALLEN_TORCH_FLASH_LIGHT；保存后仍是相同地形，晋升后确实变成余烬。

任务书提到的 `T_OBSTRUCTS_ITEMS` 是落位资格，不能据此在 DF 中创造“推开所有物品”规则。`T_AUTO_DESCENT` 的物品坠层、漂流和 `swapItemToEnchantLevel` 属于 Items.c:1209 起的 `updateFloorItems` 时间阶段，**不在 spawnDungeonFeature/refreshDungeonCell 调用链中**。本轮没有为一次 DF 刷新额外运行整轮物品时间，也不宣称已补齐现有 web 缺失的地面物品坠层队列或置换祭坛玩法。新增洞测试同时证明玩家已置 falling、同格地面物品未被虚构的即时搬运删除。

### 警报的半径与来源

按 Items.c:4089–4140，半径使用从警报原点出发的四向路径距离，允许距离计算穿越可发现的密门，不是玩家距离或欧氏圆。效果依次更新 waypoint 0、唤醒/追踪非盟友、去除保持距离和避走廊标记、以 `2*distance` 重写气味。只有原点等于玩家位置时赋值 `AGGRAVATING` 的 current/max，远端警报不会给玩家错误上状态；玩家在声达范围内则发现声源并显示灰色闪光。状态进入既有保存、递减、侧栏和潜行范围消费者。

## 8. 保留边界

- 生成端仍沿用现有“蓝图请求→populateLevel 实体化”架构。事务支持 `refresh=false` 时对真实实体驱离；当前 Architect 构造时尚未实体化的请求没有冒充已存在怪物。完整 CE 的机器实体建造时序是现有 U19 后续边界，本轮未提前重排该生成流。
- web 没有 CE 专用 mapToShore 缓存；shore 端口使现有地形安全缓存失效，不能声称引入了完整 CE shore 算法。AI 也仍沿用现有 HUNTING/waypoint/scent 消费，未伪造不存在的 lastSeenPlayerAt 消费者。
- flavor 已按 CE 的触发位置和刷新条件发送，但复用现有地形名称与消息栏，未移植 CE 全套 tileFlavor 文案和独立底部风味行；部分旧地形的名称仍会落到现有通用名称。description 已接入可见性、每回合资格和中文显示。
- 致死浏览器示例的 HP 为 -49，游戏结束已当场成立；死亡遮罩后的侧栏仍可能显示负 HP，本轮未扩展为通用 HP 显示钳制修复。
- 完全封死的合成地图找不到驱离目的格时，保留实体；CE 此处分支假定目的地存在，直接复制未初始化 newLoc 不适合照搬。
- 既有体积钳制、移动图附加连通性守卫、对象级环境效果中的已登记差异未借此轮批量更改。此报告证明共同事务及当前支持的实际消费者，不扩大为所有 CE 地形/机器都可解。
