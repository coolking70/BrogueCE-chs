## CE 执行路径与本轮改动

- **踏入深水**：CE `Movement.c:1165–1172,1299–1365` 只将 `T_OBSTRUCTS_PASSABILITY` 当物理阻挡；危险确认中没有 `T_IS_DEEP_WATER`。web 的玩家移动分支现在允许无阻挡层的深水，保留 `canMoveTo` 的干地寻路口径及生成期镜像，避免改变生成流。CE `Time.c:84–107` 的 `rogue.inWater` 是光照/视野状态；本轮没有建立此载体，也没有据此虚构护甲或重量游泳惩罚。`Movement.c:2118–2135` 的怪物路径图、`Monsters.c:1387–1493,3768–3770` 的回避及水栖边界已核：怪物从干地回避深水，已在水中不回避；水免疫/飞行/悬浮及免网者的网桥是豁免；`MONST_RESTRICTED_TO_LIQUID` 不走不允许潜水的格。web 的气味、直寻、随机移动与实际提交步现在共用这些深水判据。完整 `monsterAvoids` 的其他地形/占格顺序仍属于 U18a/U12，未在本轮扩改。
- **冲物**：CE `Time.c:549–590,2635,2733–2740` 在每次生物行动后，用该次 `ticks * 50 / 100` 调用百分比掷骰。悬浮、缠网、物理阻挡、水免疫怪物与脚下已有地面物品均挡住此分支。玩家先掷概率，再按背包顺序在未装备物品中均匀选一件；无候选时已消耗概率骰。`Items.c:8463–8495` 把物品放玩家脚下，非武器堆叠只剥一件。怪物只有携带物时才掷概率，随后经 `Monsters.c:4074–4083` 的最近合格路径落物；web 复用现有 `captiveItemDropCandidates`。玩家回合结算和怪物行动结算已接对应消费者；物品实体位置及背包变化走现有快照字段。
- **漂流**：CE `Time.c:1704 → Items.c:1209–1277 → Monsters.c:3960–4019` 在环境更新中处理地面物品；`T_MOVES_ITEMS` 格先找最近环上可放物、无物品的格，抽其中一个；仅抽中相邻格才移动，不能穿墙远漂。web 已在环境更新接地面漂流。水流冲落的物品最初落在原格，下一次环境更新才可能移至相邻格。`T_MOVES_ITEMS` 包含深水与熔岩，沿用 CE 地形旗标。
- **不淹死**：CE `Rogue.h` 的深水旗标只关联冲物，`Time.c:1146–1150` 的坠水零伤害。移除了 web 先前被恒假开关包住的玩家/怪物即死分支及开关；`death.drowned`、`env.player_drowns`、`env.monster_drowns` 从现役中文词表移入 `zh_CN.legacy.json`。这是删除的自创规则；没有引入另一套溺水计时。
- **网**：CE `Time.c:313–340` 接触网时给 `STUCK=3..7`；`Monsters.c:3773–3784` 仅移动空格时挣扎，最后一次挣扎可离开，`Time.c:2293–2296` 离网清计数。U14b 现有实现已覆盖计数、移动挣脱及存档；CE `Combat.c` 的被缠命中处理已有 web `Combat.ts` 消费者。`Time.c:557–560` 还表明网覆盖深水时抑制冲物，本轮水消费者按四层地形旗标补了此条件。未改 U08 网 DF 生成流。
- **开笼**：CE `Items.c:4036–4087` 的钥匙位置/机器绑定和 `Movement.c:616–656` 的消耗判断由既有 `keyMatchingEntry` 路径处理；`Movement.c:728–742` 的 `becomeAllyWith` 是释俘关系收口。web 钥匙开笼原来直接写 `isCaged=false/isAlly=true`，现在调用 `freeCaptive → becomeAllyWith`，与魔法释俘一致，包含领袖降级、携带物掉落、关系字段及日志。开普通锁不会顺带释放附近俘虏。

## 撞红、清单外改动与自检

首次构建的 TypeScript 阶段指出戒指双槽字段名是 `ringLeft/ringRight`，已修消费者。Vite 在沙箱内启动 esbuild 遇 `spawn EPERM`，获执行环境放行后构建通过。`c_4b_dungeon_feature` F2 与 `c_4a_terrain_catalog` E 的源码扫描曾把 `DungeonFeatureCatalog.ts` 的纯注释当作生产调用/字段读取。反查发现该文件在 Windows 工作树为 CRLF，守卫 `line.replace(/\/\/.*$/, '')` 在尾部 `\r` 时未剥去注释；`git show HEAD` 证明这些注释原已存在。只将该文件恢复 LF（Git 内容 diff 为零），两个原样守卫均通过；没有改测试、扫描器、白名单或期望。全量套件还撞到 W-20 CE 对照文本的 CRLF，逐行比较多出 `\r`；同样只恢复 `ai_docs/reports/w-20-evidence/ce-clone.txt` 的 LF，原样 57 条 W-20 用例通过。这两项行尾规范化是 R/S 清单外的工作树文件状态修复。新用例最初在存档恢复时仍 mock 全局随机范围，导致卷轴标题生成空间耗尽；将 mock 仅限冲物动作后通过，这是测试夹具修正，不涉及产品规则。

§3 自检：未移动生成流或重捕获；没有旧档兼容逻辑；`test:drift` 以当前基线验证。新发现：`canMoveTo` 的干地判据仍服务自动寻路与生成期镜像，玩家手动踏水在行动分支单独放行；自动寻路仍把深水当不可走，留给后续路径代价合同处理。冲落物的包/地位置在存读档后保持；X-0 K01 所列全局 RNG 恢复缺口仍会影响**读档后下一次**随机冲物的逐骰重演，不把状态往返误报为完整录像一致。CE 未见护甲重量导致淹死或改变冲物概率的分支，任务书该线索不应派生自创惩罚。
