## 1. 公式及三个边界：编译 CE，再测试实际转队

`brogue/PowerTables.c:45–46` 原函数：

```c
short wandDominate(creature *monst) {return (((monst)->currentHP * 5 < (monst)->info.maxHP) ? 100 : \
    max(0, 100 * ((monst)->info.maxHP - (monst)->currentHP) / (monst)->info.maxHP));}
```

正整数 HP 下，即 `HP*5 < maxHP ? 100 : max(0, trunc(100*(maxHP-HP)/maxHP))`。严格小于，不含等号；除法先乘 100 再截断，不是先截 HP 比例。与杖附魔、次数、CE magnitude=10 均无关。`Math.c:62–64 rand_percent` 为 `rand_range(0,99) < clamp(percent,0,100)`，**0%/100% 也执行一次抽签**。

`scripts/w17-ce-golden.mjs` 从 CE 文件提取两个完整原函数，提供最小 creature 结构和可控 `rand_range`，用 clang 编译；没有在 C 测试里重写公式。最大 HP 为 3/5/7/25/99/100/101/137，遍历各自 HP=1..maxHP+1，共 **485 行黄金值**；每行又枚举全部100个 roll。web 与全部黄金值一致。并单独通过真实 `zapBoltFromPlayer → traceBolt → applyBoltEffect` 枚举三个边界，断言真实 hit 对象、每次抽签范围、转队/状态和 autoID：

| 边界 | CE 概率 | web 实际成功数 / 全部100个roll | 临界判据 |
|---|---:|---:|---|
| HP=100/100，满血 | 0% | **0/100** | roll=0仍失败 |
| HP=20/100，恰好20% | 80% | **80/100** | roll=79成功，80失败 |
| HP=19/100，低于20% | 100% | **100/100** | roll=99仍成功 |

另含非整除分母、超过最大HP的零概率。证据：[C 源文件](w-17-evidence/ce-domination.c)、[485 行结果](w-17-evidence/ce-domination.txt)、[测试](../../src/test/w_17_domination.test.ts)。本轮无需定点幂表；黄金值仍由 CE 原函数生成。

## 2. 无效目标、反射和自动候选

`Items.c:5274–5300` 的硬门只有：**不能是玩家，不能带 `MONST_INANIMATE | MONST_INVULNERABLE`**。它们不掷支配骰、不改任何目标字段、不因该效果 autoID。空射、墙挡、同起终点同样不转队。单独 IMMOBILE、免疫武器并不是支配免疫；已经是盟友/俘虏也不是实际接触的免疫条件。

CE `Globals.c:1025` 的目录反查结果为17种（[逐项行号](w-17-evidence/ce-ineligible.json)）：goblin totem、ogre totem、arrow/spark/dart/flame turret、sentinel、phylactery、spectral blade/sword、stone/winged guardian、guardian spirit、eldritch/mirrored totem、phoenix egg，以及无敌的 Warden of Yendor。`Rogue.h:2093–2094` 的 **MONST_TURRET 复合位含 INANIMATE**；web 没展开此复合位，本轮在支配资格及其候选门内显式识别，未重写全局旗标语义。石像等通常先反射，所以反射与硬门分别测试，不能只凭它反射就算测过免疫。

W-4 路径原语未改：原路反射实际命中玩家，玩家不受支配；随机反射打中旁观者时，只有旁观者转队，原瞄准者/反射者不变。没有按原选靶坐标重新查对象。

`Items.c:6007–6010` 的 **已知支配魔杖自动候选过滤0%敌人**补入 `BoltTargeting.ts`；未知身份仍不泄露满血筛选。手动瞄准满血者允许执行真实0%尝试。候选过滤与实际命中资格分开；俘虏被自动候选视作友方，不等于手动射击无效。没有新增法器身份/config，候选测试用显式测试实例身份。

## 3. 成功转队及观察

实现入口 `Game.applyBoltEffect` 的 DOMINATION case：先资格判断、掷骰；成功后才清 **W-9 的 `discordant`**，再调用 `becomeAllyWith`。没有另造 discord 状态。`dominated` 只是转队来源标记，供新增盟友的还击与形态持久化使用，不是倒计时或状态替身。

`Movement.c:728–742` 的 `becomeAllyWith` 对应为：`isAlly=true`、`leader=null`（本引擎的玩家随从表示）、`isCaged=false`、`seized=false`、`state=WANDERING`。CE 用 MONSTER_ALLY 表示状态，web 由 isAlly 驱动盟友 AI，因此不会让原 ASLEEP/FLEEING 状态妨碍转队。原HP、位置、速度、等待、confused/paralyzed/毒/盾等保留；**seizing 不清**，CE 也只清 MB_SEIZED，不清 MB_SEIZING。

`Items.c:5282–5299` 在成功转队之后检查 `canSeeMonster`，成功与抵抗都能在可观察时 autoID。不可观察成功/失败不 autoID；隐形目标成功转成盟友后，在可见格可观察，隐形状态本身仍在。沿用 W-2/W-9 的观察原语，不扩张 submerged/clairvoyance 模型。

## 4. 俘虏、携物和首领关系

**俘虏**：支配成功直接 `becomeAllyWith`，无需先调用 `freeCaptive`，也不会多打一条感激获救消息；失败保持囚禁和原状态。W-11 的 teleport/beckoning/tunneling 救援继续经 `freeCaptive`，该方法现在是带俘虏门及救援消息的共用转队包装。它本身仍不清 discordant；清除动作属于 DOMINATION case。

**携物**：`Movement.c:730–733 → Monsters.c:4074–4083 makeMonsterDropItem` 明确把原物品放到地面，并清 carriedItem。不是送入玩家背包，不是销毁，也不是继续当盟友私有物品。复用 W-11 的 `captiveItemDropCandidates`：优先合格原格，否则最短路径距离附近格，排除阻物地形/玩家/楼梯/已有物品，允许其他怪物占格，不额外排机器格。落位后调用既有物品放置晋升。测试保持**同一 Item 引用**、钥匙 keyLoc/machine/disposableHere/originDepth，地面旧物不被覆盖；JSON 后钥匙绑定仍保留。浏览器中盟友走开，原格实际露出 `k`。

沿用 W-11 已登记的病理兜底：完全没有安全物品落格时保留携带物，避免 CE `placeItemAt(INVALID_POS)` 在该非法地图上的未定义落位/物品丢失；正常地图按 CE 掉落。没有把物品 fallback 用于怪物移动。

**首领**：`Monsters.c:4103–4160 demoteMonsterFromLeadership`：

- 被支配者原为普通成员：断开它与旧首领的关系；其他成员仍敌对、仍跟旧首领。
- 被支配者有随从：先遍历当前层活动怪，再按层号升序遍历其他缓存层活动怪，排除死亡候选和可能过时的当前层缓存副本。首个非绑定随从成为继任者（leader=null），后续普通随从改指它；后续随从复制原首领 targetWaypointIndex，并清该点 visited 位。只转队目标，**不把整个怪物群变盟友**。
- MB_BOUND_TO_LEADER 随从不参与选举，断开 leader；休眠随从单独第二遍全部断开，既不继任也不重挂。
- CE 首领/mapToMe 的位和缓存在 web 无独立载体；首领由其他对象的 leader 引用表达，计数消费者见下节。

补上 `boundToLeader`，仅从已有 `HORDE_DIES_ON_LEADER_DEATH` 记录元数据，不改落位/数量/RNG。`Time.c:2561–2564` 规定断连绑定敌人在 `playerTurnEnded` 死亡，而盟友豁免；本轮在该入口既有死亡结算前处理，绕盾真正死亡，随后走原 DF/掉落/清扫，测试 die 一次、物品一份、重复回合不重复结算。离层/休眠者待恢复活动再进入该入口。

**前轮缺口与本轮边界**：W-11 原 helper 没有绑定随从载体，且活动/休眠混在一遍处理；本轮修正，未声称此前已完整 CE。P4-2 注释登记的 `carriedMonster` 寄宿/复活尚无 web 实体载体；CE `Movement.c:735–737` 会递归转队该乘客，本轮不存在可递归的对象，不伪造寄宿/复活系统。普通死亡后的全套群体继任仍是旧系统缺口；本轮完成的是**支配/魔法释俘触发的 demotion**。

## 5. “失败不变队”的证明

失败路径只计算概率、抽签、读取可观察性及写结果/日志；没有调用转队 helper，没有清 discordant，也没有写 dominated。可见抵抗导致 autoID、施法扣电/过回合，均不等于修改目标阵营。

新增测试分别让敌方/原盟友目标处于：HP20%、ASLEEP、俘虏、discordant+confused+hasted+poisoned+shielded、seized+seizing、原leader、绑定关系、携带钥匙，并挂一个随从。固定 roll=80 后，**目标所有可枚举字段（Set 展开、leader按ID）、原首领、随从、地面物品逐一与射前完全相等**，转队 spy 调用0；另测满血 discordant 盟友仍抵抗、不被“顺便治好”。这是效果事务的零写入保证；确认施法后的正常客观时间推进仍会按既有规则递减状态，不能把自然过回合误归因于失败效果。

反向变异把清 discordant 移到抽签之前，两个全字段失败测试立即报错。其他变异见§10。

## 6. 存档及旧档兜底

`GameSnapshotMonster` 为普通怪物新增可选 allegiance（isAlly/isCaged/leaderId/boundToLeader/dominated），活动/休眠列表使用同一 serializer。刀刃的阵营继续以 W-16 spectralBlade 为唯一来源，在该标签内扩展 leaderId/boundToLeader；不再额外写 allegiance，缺原标签仍按 W-16 旧档兜底。先重建两份列表，再统一按ID恢复 leader 引用，不按对象顺序猜关系；缺失ID落 null。成功目标另保存 `dominatedForm`：真实 typeId、伤害/基础速度/命中/防御、behavior/ability flags、bolts等，防止用中文显示名推断物种导致读档后失去召唤/特性；变异过或消魔后的当前形态也从实际对象取值。

实际 JSON `toSnapshot → stringify/parse → loadSnapshot` 验证：被支配 goblin conjurer 仍盟友、discordant=0、物种/法术/能力/速度保留；恢复后可真正召出盟友随从。敌方重组选举后的 leader 引用、休眠盟友、落地钥匙绑定都往返。测试房基线/schema与实际 reset 也复用 payload 和第二遍关系恢复。

旧档没有 allegiance：保持既有 isAlly=false/isCaged=false/leader=null/default bound=false，不凭名字或 WANDERING 猜曾被支配。字段缺省按严格 true 兜底；W-16 spectralBlade tag 的旧盟友恢复仍兼容。关系迁移及ID重连不新增抽签；没有声称既有整个 loadSnapshot（含 Monster 构造）的随机状态架构已重写。

**保留原存档范围**：GameSnapshot 只存当前层，不序列化整个 levels 缓存；离层后另层保存再重载，旧层缓存仍不能恢复。本轮缓存内跨层首领重组已覆盖，不能据此宣称多层JSON持久化完整。缺失的旧关系/寄宿信息无法由迁移还原；当前层被支配盟友不受此限制。
