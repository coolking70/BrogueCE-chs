# U21a：展示可见性一致

依据：`x-0-survey.report.md` §4.4 U21、§3.1 K17；本工作树 `BrogueCE-master`。未提交 git，未移动生成流，未修改测试、守卫或基线。

## CE 谓词与冲突

- `BrogueCE-master/src/brogue/Monsters.c:166-177` `monsterRevealed`：催眠、心灵感应（排除无生命）能揭示**位置**。
- `Monsters.c:203-218` `monsterIsHidden`：休眠、非队友的 `STATUS_INVISIBLE` 且不在气体中、潜水可隐藏。固有 `MONST_INVISIBLE` 在 CE 初始化为 `STATUS_INVISIBLE`；临时隐形走同一状态。
- `Monsters.c:229-252`：`canSeeMonster = !monsterIsHidden && (playerCanSee || monsterRevealed)`；`canDirectlySeeMonster = playerCanDirectlySee && !monsterIsHidden`。`IO.c:1268-1281` 对已揭示但仍隐藏者只画白色 `x/X`，不泄漏种类；`IO.c:1320-1333` 气体给隐形者描边；`IO.c:1253-1257` 对已可见的隐形者混入 75% 背景色。
- 因此任务书 §2 的“揭示后都显示”须按 CE 细分：心灵感应/催眠下仍隐藏的敌人只显示位置标记，不进入具名文本、详情或自动瞄准候选。气体或状态结束后可识别，才进入这些出口。这与旧 W/P4 测试的隐形+心灵感应断言冲突，CE 优先。

web 共用谓词在 `src/engine/UI/MonsterVisibility.ts`：`monsterRevealed`、`monsterHidden`、`canSeeMonster`、`canDirectlySeeMonster`、`canDisplayMonster`、`monsterInGas`。目前 web 没有 CE 独立的 `MB_TELEPATHICALLY_REVEALED` 与潜水载体，本轮不新增状态或 AI 资格。
