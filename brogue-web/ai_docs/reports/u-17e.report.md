与任务书的两处差异按 CE／实际代码处理：

1. **发光管道是在生成期铺下，通电消耗后变焦黑**，并非“机器通电才发光”。祭坛下方的旧管道会先因 VANISHES_ON_PROMOTION 清掉，惰性管道随后被祭坛的表面阻挡规则拒绝；普通地板上的管道变成 PIPE_INERT。完整 CE6 房间测试验证了两种结果。
2. 入场代码只有置换地形、标志和目录，没有 `swapItemEnchants` 消费者，见 [HEAD 搜索](u-17e-evidence/head-commutation-search.txt)。因此新增唯一的绝对附魔交换消费者 `Items/Commutation.ts`，复用现有 Item、CharmModel 冷却公式、ItemLoader 鉴定计数和状态模型；未另建物品系统。复活完整复用 U16，只撤掉旧 ALTAR 替身，改用 143 的真实惰性地形与光效。

置换遵守 CE CAN_BE_SWAPPED（不含 wand）、quiver 排除、同机与断路器条件；相同附魔不消耗祭坛；staff 低于 2／charm 低于 1 会碎裂；staff 容量与当前充能钳制、charm 冷却整数百分比、知识迁移、好符文消退／坏符文保留与非负解咒均接现有实例。按 CE `itemAtLoc` 每格只取首件，同格重叠物品不会充当两座祭坛。

## 3. 关键消费者与持久化

- 所有铺装、疏散、占格刷新、wired 晋升仍走 U17a 的 `spawnDungeonFeature`／Promotion 出口。初版曾直接在 Game 调机器激活，被原 c4c A6 源码守卫抓住；已改为 Promotion 内的 `promoteOnCommutation`，**A6 没有修改**。
- CE 图书馆物品通常不是 KEY 类别，依靠 `ITEM_IS_KEY` 与归还位置绑定。BlueprintEngine 保留领养物品原来的锁绑定，再追加自己的归还位；Game 保留 item flags、深度与最大充能知识，并接现有种类鉴定。`keyOnTileAt` 检查匹配的地面物、占格玩家背包或占格怪物携物；离开借物格才关笼。
- `markedForSacrifice` 只从真实 `HORDE_SACRIFICE_TARGET` horde 领袖生成，并进入 U01 Monster 字段合同；光照读取 SACRIFICE_MARK_LIGHT。献祭入口检查标记和 machineHome，同样的未标记／异机怪不会完成任务。
- SACRIFICE_LAVA 的即时死亡使用已有 `T_LAVA_INSTA_DEATH` 语义，保留飞行、火免疫、无敌等原有条件。复活、钥匙、惰性态、标记怪和交换后的物品均有保存恢复断言。
- 浏览器实际丢弃暴露了 Vue 代理与引擎实例身份不一致的问题；InventoryOverlay 的丢弃入口改为 `toRaw(item)`，与现有阅读入口一致。否则引擎单测能置换，但用户按钮无法真正丢下物品。
