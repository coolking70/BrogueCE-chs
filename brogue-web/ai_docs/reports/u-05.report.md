# U05：机器物品实化与 Q 品质筛选

基准 `34e293cfdafd3cfa607f58ab7e0876aa5e51f84d`，2026-09-25。权威为 X-0 §4.3 U05 / §3.1 K11 和仓库内 BrogueCE。未提交。

## 1. CE 复核与任务书歧义

核读 `BrogueCE-master/src/brogue/Architect.c:441–453、1494–1587、1680–1710`，`Items.c:75–107、152–179、209–420`，`Globals.c:1582–1665`，`variants/GlobalsBrogue.c:109、701–726`，以及 web W-5/24/25/26 的资源与目录。

- `generateItem` 分配并返回实例，CE 此处没有 null 返回协议。类别先经 `pickItemCategory`，**单类别和显式 kind 也调用它**；正总权重使用 `rand_range(1,sum)`，零权重 KEY 等不耗骰。随后负 kind 才抽种类，最后生成实例资源。
- 品质循环无条件排除诅咒；`MF_REQUIRE_GOOD_RUNIC` 字面只检查 `ITEM_RUNIC`，没有另抽“好符文池”。“好”来自与未诅咒条件组合。投掷禁止条件是 WEAPON 且 quantity>1。重武器条件是 WEAPON、非 dart/javelin/incendiary dart、基础力量要求>15，**还须 enchant1>0**。
- 去重覆盖 STAFF/WAND/POTION/SCROLL/RING/WEAPON/ARMOR/CHARM，比较 category+kind，不是名称，不仅戒指/杖。列表含本机此前自产和此前成功子机器自产；子机器不继承父亲的列表，领养品不成为子机器自产。
- **failsafe=1000 不是最多生成1000次**：首次生成后，每次先删除/再生成，再检查 `failsafe<=0`，最后递减；最多 **1002 个候选**。耗尽仍登记最后一个候选，即使它不合格；不会返回机器失败。这是按 CE 修正任务书“失败重掷”的含义。
- 领养不重新生成、不重新筛选。外包十次失败/后续 feature 最小数量失败才走机器回滚；既有 U05a 的父子登记和撤销合同保持。

[CE 原文编译脚本](../../scripts/u05-ce-golden.mjs)抽取真实函数和重掷循环，仅替换分配、表和候选供应，得到 [576 组判定及5个边界](u-05-evidence/ce-golden.json)，由新测试逐项比对；[编译输入](u-05-evidence/ce-golden.c)可复核。没有把本轮 JS 逻辑翻译成 C 再自证。

## 2. 实现与所有权

- `Game.spawnBlueprintItem / rollBlueprintItem`：STAFF/WAND 显式 id 和类别请求接真实 ItemLoader；RING/CHARM 类别及显式请求接机器出生资源。掩码按 CE 类别槽序抽签，不递归多抽一次类别；单类别也补齐类别骰。每次 Q 重掷重新执行完整类别→种类→资源流程。
- `MachineItemGeneration.ts`：统一诅咒、符文、投掷、重武器、同种去重和 CE 上界。null 不进入品质循环；实际机器实化若收到 null，向上传播明确错误，不能静默发布少一件物品的机器。**这不是宣称 CE 有 null 失败分支，也不是实现 U19c 的延迟怪物/整图回滚。**
- `BlueprintEngine`：`priorItemIds` 记录生成时的去重作用域，父机器在子成功后接入其自产登记。源 `itemQualifiers`、实例 ID 随领养/外包/携带原样传递。此前的唯一所有者检查仍先于实化。
- `Game.populateLevel`：按实例 ID 缓存，必要时先实化前置创建；所有者最终接同一 Item。读取已实化前置项不重写它的位置；独立探针曾捕获这个真实错误，新增专例后修复。地面、普通怪物、horde 领袖沿既有统一交接流程消费。
- `ItemLoader`：机器戒指出生 `randClump(1,3,1)` → 16%诅咒，非诅咒侧10%长尾；机器护符 `randClump(1,2,1)` → 7%长尾，charges/cooldownRemaining=0、已鉴定。普通戒指/护符生成入口及效果没有扩改。
- 武器/护甲在构造时保存 `identityId`，供去重使用；CE 已抽中但 web 效果尚未实现的符文也保留 `ITEM_RUNIC`，投掷武器事后剥掉它。字段沿 U01 现有编解码保存，无 schema 新增。构造 ID 不能成为装备“种类鉴定表”，回归捕获该外溢后，`identifyItemKind` 已明确排除武器/护甲，原 B-1a 断言不变。

## 3. 类别抽签与 RNG 对齐边界

| 请求 | 每个候选的顺序 | 与 CE 的程度 |
|---|---|---|
| STAFF | 类别1次 → 非显式 kind 按基频1次 → 50%/15%/10%条件尾 | 现有12种目录/槽序/频率沿 W-25；E=初始charges=maxCharges，blinking/obstruction 初始回充1000，其余500 |
| WAND | 类别1次 → 非显式 kind 按基频1次 → 对应初始charges的randClump | 沿 W-24九种范围；empowerment退化区间零资源骰，其余1次；显式id跳过kind，不跳类别 |
| RING | 类别1次 → 非显式 kind 按现有基频1次 → 1..3 →16% →非诅咒10%尾 | 出生资源/调用次序对齐；现目录仅6/8种，缺light/reaping且目录顺序不同，**不等于完整 CE 同seed抽种类** |
| CHARM | 类别1次 → 非显式 kind 按现有基频1次 →1..2 →7%尾 | 出生资源对齐；目录6/12种且顺序不同，speed映射/效果/冷却仍偏离，见§8 U15c |
| WEAPON/ARMOR/POTION/SCROLL | 类别 → kind（若未显式指定）→既有实例模型 | 保留基表、无深度过滤、无计量工作表；药水lichen退池、符文效果空槽等既存差异没有伪装成全CE |
| 混合掩码 | CE类别槽定序的一次加权 → 所选类别kind →资源 | 输入字符串顺序不影响类别槽序；Q重掷重新抽全部三段，不固定首次抽中类别 |
| KEY显式id | 零频类别无骰 →显式构造 | 保持绑定及既有钥匙入口约束 |

web 仍在 Game 的延迟人口填充阶段实化机器物品，CE 在 buildAMachine 特征块中即时生成；怪物和失败机器的随机时序亦未整体搬移。此轮保证每个生成请求及筛选循环的局部顺序、去重作用域和实例归属，不宣称全流程 CE 随机流相等。没有从最终本地化名称反推类别/种类。
