**编码口径的两条说明**：
1. `category: "key_guard"` 承载 CE 的 `BP_ADOPT_ITEM`（`CATEGORY_TO_BP_FLAGS`），故 26/28 号的 `flags` 数组里**不重复写** `BP_ADOPT_ITEM`——与既有 `key_secret_room` 完全同款。26 号另带 `BP_ROOM | BP_PURGE_INTERIOR | BP_SURROUND_WITH_WALLS | BP_OPEN_INTERIOR | BP_IMPREGNABLE`；28 号的 CE flags 只有 `(BP_ADOPT_ITEM)` 一位，故 `flags: []`。`v_2b_4_altars` C6 另用 `blueprintQualifies(bp, d, [BP_ADOPT_ITEM]) === true` / `[BP_REWARD] === false` 双向钉死"category 真的把位注入进去了"。
2. CE 的 **itemFlags 列**（`ITEM_IS_KEY` / `ITEM_KIND_AUTO_ID` / `ITEM_PLAYER_AVOIDS` / `ITEM_MAX_CHARGES_KNOWN`）在 web 的 `FeatureDef` 里**没有载体**——V-2b-2b/2b-3 的前例同样未转录。本轮照旧不硬造，登记为缺口（web 側钥匙由锁具驱动，见 `Game.ts` 的 `needsKey` 机制）。

## 4. 15 号护符双轨的实测数据与处置结论（任务书 §4 必答）

### 4.1 CE 的真实机制（读源码所得，与提示词的默认假设不同）

CE **没有**"直投护符"这回事。`Architect.c:1747-1754`：

```c
// Add the amulet holder if it's depth 26:
if (rogue.depthLevel == gameConst->amuletLevel) {
    for (failsafe = 50; failsafe; failsafe--) {
        if (buildAMachine(MT_AMULET_AREA, -1, -1, 0, NULL, NULL, NULL)) break;
    }
}
```

- `MT_AMULET_AREA` 就是**蓝图 15 号的目录下标**（`buildAMachine` 的 `chooseBP = (bp <= 0)`，传正数即"强制用这条蓝图"，不再抽签）；
- 15 号自己的 `frequency = 0`（`GlobalsBrogue.c:290`）⇒ **它永远不可能被配额抽签抽中**（`chooseBP` 的滚动映射里 freq=0 的条目不推进 `randIndex`，`randIndex <= 0` 永不成立）；它只能由上面那次强制调用建成。
- 护符本身来自 15 号的 `AMULET_SWITCH` feature（`MF_GENERATE_ITEM`, itemCategory `AMULET`, minInsts 1）。

也就是说 CE 的护符是"**50 次 failsafe 的强制建机器**"，不是"必然建成"。

### 4.2 web 现状 + 本轮实测

web 现状是**双轨**：

### 4.3 处置结论：**直投不退位**（并说明为什么这与提示词的倾向不同）

1. **15 号在 web 的建成率 = 0%**（freq=0 且无强制建成调用）；
2. **即便建成也发不出护符**（AMULET 类别无生成分支）。

⇒ 直投退位 = 0 护符 = 致命。**故直投保留**（`v_2b_4_altars` E4 把"D26 直投仍在"钉成守卫），且当前双轨**不可能叠加**（15 号永不建 ⇒ 不存在第二个来源；实测每局恒 1 枚）。护符直投的判定顺序（先查世界/背包有没有 → 再投）本来就带防重发守卫，只是它跑在机器消费之前，无法看见蓝图产出的护符——这一条本轮**不需要**改，因为蓝图侧产出恒为 0。

**登记的两个缺口**（"机器接管"要成立必须补的两个，都归后续轮）：
- **缺口①**：CE `Architect.c:1747-1754` 的 D26 强制建。web 的 `buildAMachine` **没有 CE 的 `bp` 形参**（只有 `requiredFlags`，永远走 chooseBP），且 15 号没有 `BP_ROOM`（CE :290 只有 `BP_PURGE_INTERIOR | BP_OPEN_INTERIOR`），走的是 CE 的**非房间"区域机器"选址分支**（`Architect.c:1145-1219`：随机 FLOOR 起点 + 沿路径图扩张到目标尺寸），web 只有 `BP_ROOM` 的 `findGateRoom` 一条路。补这条是独立的一轮工作。
- **缺口②**：`Game.spawnBlueprintItem` 的 `AMULET` 类别分支。

**双轨不会叠加这件事本身也钉进了测试**：E1（建成 0 台 + 反真空"其它 reward 蓝图确实建成了"）。

**一处诚实标注（守卫力量）**：E1 是**测量**，不是**守卫**——反向验证 RV1（把"freq=0 不可选"改坏成"freq=0 命中即选"）时 E1 仍然**通过**：因为 15 号在 eligible 序列里排在全部正频条目之后，滚动映射根本走不到它。真正的对抗性守卫是 F2/F3（见 §6 与 §7）。

### 6.1 真缺陷：首层前厅梯位会落进机器格

**现象**：`p1_33` 报 `seed999/D1 楼梯落在机器格内`，`p1_37` AD1 报 `seed999/D1 楼梯落在 (39,14) 机器格内`。

**诊断**（不是先怀疑断言）：`(39,14)` 正是 `{DCOLS/2, DROWS/2}`。web 把**首层的上行梯硬编码在地图正中**（`Game.ts` `populateLevel` 的 `else if (this.depth === 1)` 分支）。CE 没有这个硬编码——CE 的 `placeStairs`（Architect.c:3690）在 `digDungeon`（含 `addMachines`）**之后**调用，并**回避 `IS_IN_MACHINE`**（:3712/:3738）。web 的时序与 CE 相同（机器先建、楼梯后放），但正中那一格没做机器检查。本轮新数据把它暴露了：CE 1 号 `reward_mixed_library` 的 gate choke 区间 `[30,50]`（宽）+ `BP_OPEN_INTERIOR` 让机器内部可以长成**数百格的连通体**（实测 seed999/D1 那台 645 格），正中于是落进机器内部。

**这不是"挑 seed 的假保证"**：我用 `applyBlueprint` 挂钩实测复现并定位了是哪台机器（`reward_mixed_library`，door (59,23)，645 格）；且同一份代码在其它种子/层上一直成立。

**修复**（最小、零 RNG、CE 口径）：新增模块级函数 `vestibuleStairPos(grid)`——正中**只要不是机器格就原样用它**（哪怕它是岩石：旧行为就是把楼梯砸进正中），只有正中落在机器内部时才按 Chebyshev 环序就近取第一个"非机器格、可通行、DUNGEON 层是 FLOOR"的格；找不到则返回 null、调用方退回硬编码正中（不静默挪位）。

> **诚实记录一次自己的过头**：该函数的第一版把"可通行 + FLOOR"也当成了正中的准入条件，于是"正中是岩石"的种子也会挪梯位——在 4 个基线种子上造出 **94 处无谓偏离**（实测：换旧池、对比 V-2b-3 基线，从 0 处 → 94 处）。发现后收紧为"只判机器格"，偏移回到 0 处。这正是本节要求的"不粉饰"。

### 6.2 守卫力量下降（登记，不粉饰）

`p1_37` AD3 的 `A−B` pin 原为 `['25,23']`（某层上"落在机器 interior 之外、却带 machineNumber"的格）。池变化把"首个有机器的层"从 424242/D3 挪到别的层，新层的 `A−B = ∅` ⇒ 顺延为 `[]`，**该层上那条逐格循环随之空转**。

我尝试过把选层条件改成"首个 `A−B ≠ ∅` 的层"以保住力量，结果**翻红**——查清后确认**不是实现缺陷**（见 §7 的完整回答）。附带发现该断言的前提**从来就过强**：

- 实测（seed424242/D9，`A−B = 50` 格）：抽样格是 `STATUE_INERT` / `WALL`、`mn≠0`、与最近机器 interior 的 Chebyshev 距离 = 1，对应机器都有 `MF_BUILD_IN_WALLS`（或 CE 26 号的 `MF_EVERYWHERE` 墙）feature；
- CE `Architect.c:1484-1486`「Mark the feature location as part of the machine, in case it is not already inside of it」对**一切** feature 生效，而 `MachineResult` 只暴露 item/monster 布点——**地形类 feature 合法地没有布点指令**；
- 也就是说"每个 `A−B` 格都必须是 item/monster 布点"这个前提**只在上一轮恰好选中的那层上成立**。

要做到非空转需要 `MachineResult` 暴露 feature 落点（归 V-2b-7 的 df/feature 列），本轮**登记不动手**，并已把整段推理写进测试注释。
