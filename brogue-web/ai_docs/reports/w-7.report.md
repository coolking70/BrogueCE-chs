## 2. W-5 / W-6 交接：四个量各自如何变

| 字段 | STAFF | WAND |
|---|---|---|
| `enchantment`（E） | E+1 | 不变 |
| `maxCharges` | **新 E**，与 CE 以 enchant1 为容量一致 | 不变；W-5 的初始次数记录，不是当前次数上限 |
| `charges` | 当前次数+1，不填满旧缺口 | 当前次数+该种 range 下限，可超过 `maxCharges` |
| `staffRechargeRemaining` | **直接覆盖为 `floor(500/新E)`** | 不变，WAND 仍不自然回电 |

例如 E3/容量3/当前1/计时2700，附魔资源操作后为 **E4/容量4/当前2/计时125**。空杖 0→1，满杖 3→4；并非所有情况都充满。刻意分离夹具 E8/容量2/当前1，附魔后 **E9/容量9/当前2/计时55**，证明容量不是盲目旧值+1，也不从当前次数反推 E。

计时是 `500/newE`，不是 `5000/newE`，不是保留旧进度，也不是比例折算。旧 timer 为缺键、-20、0、1、2700、99999 六种情况均重置为同一125。E/容量/次数/计时及 `identified/maxChargesKnown/timesUsed/magicDetected` 在 JSON 往返后保持；W-5 初始抽签、版本标记与确定性旧档迁移未动。

## 3. 与 W-6 归一化循环的交互证据

新增测试直接调用未改动的 `tickStaffRecharge`，并用真实读卷轴路径验证顺序：

| 场景 | 结果 | RNG |

| haste 读卷轴，随后再等半回合 | 附魔后timer125、客观门50；随后才timer115、门100 | 无多算客观块 |

**对 W-6 报告的限定修正**：原文“归一化循环可在 E 改变后生效”对外部改变 E、保留过长 timer 的状态成立；不能据此让 W-7 主动附魔沿用旧 timer。CE 此分支主动写入短计时，正常正 E 下它低于新周期的归一化上界，因此合法附魔不会因为旧长周期而被扣回赠送次数。上表反事实证明循环本身仍有效，实际读卷轴证据证明正确分支不会误触发它。

只有附魔资源变更本身零 RNG。随后正常客观块可能因高 E/智慧到期抽取新间隔；不能把整次附魔行动笼统称为零 RNG。

## 4. 选择、取消、时间与引用稳定性

读取附魔卷轴后显示强制待选背包。选择范围为包内合资格 STAFF/WAND，外加**原规则的当前装备目标**：武器优先，没有武器才是护甲。未开放备用装备、戒指、护符附魔。

- 读前关闭背包为零消耗。**读后不能取消**：CE IC:7824–7835 的 do-while 要求选到合法目标，Esc/空格取消、关闭按钮、背景点击、等待/移动不会丢弃附魔效果。UI 提示明确写出“卷轴已读，需选定目标”，关闭按钮禁用，其它物品操作收起。
- 异步实现中读时移除卷轴并亮其种类；有合法目标则延后本次时间结算。成功选择后先写法器状态，再清待选、推进一次 `movementSpeed` 和 `playerTurnEnded`，保证 W-6 本次回电看到新 E/计时。重复提交不会再次附魔或结算时间。
- UI 在读卷轴、目标资格和目标提交边界均 `toRaw`。引擎用 `inventory.items.includes(item)` 校验原实例，拒绝同 id 克隆、Vue proxy、地面品和已经替换/移除的引用；重排背包不影响目标。
- 新快照可选布尔字段 `pendingEnchantment` 表示已读卷轴的未完成效果，旧档缺键=false，新局=false。待选存档不保存悬空物品引用，读档重开选择，必须使用重建后的背包对象；完成后字段为false。由此避免刷新存档丢掉已消费卷轴的效果。
- `isTimePaused` 显式包括待选状态，正常玩家输入和再次读/施法被挡住。进入附魔入口还检查输入锁、死亡、麻痹和其它待选态。

目标未知态没有被免费鉴定。实例 flags、种类识别表和日志均有守卫，截图中的未知 STAFF `?/3 → ?/4` 保持未知当前次数。
