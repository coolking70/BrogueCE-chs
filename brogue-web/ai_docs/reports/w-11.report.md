# W-11：传送目标安置

基准 HEAD：`0d5ec887f51fb1966813bc5536584aafe6d3719b`。规格按 W-0 的 W-11 行；该行实际位于报告 §2.4（任务书称 §2.3）。本轮实现 TELEPORT 及 W-12 可复用的安置入口，不接 blink/beckoning，不改物品目录和生成流。所有 CE 结论均来自仓库内原码。

## 1. CE 核实：合法位置与失败

| 原码 | 核实结果 / 对应实现 |

| `Monsters.c:650-670` | `forbiddenFlagsForMonster` 从 `T_PATHING_BLOCKER` 起，根据 **info.flags** 清除部分地形禁入位。临时悬浮/火免状态不参与这个选点判据。 |

物种过滤逐项照原码：无敌去除岩浆/自燃/火；原生火免或飞行去除岩浆；原生火免再去除自燃/火；原生水免或飞行去除深水；原生飞行去除深渊/地形陷阱。`MONST_RESTRICTED_TO_LIQUID` 的额外水域限制只存在于 `respectTerrainAvoidancePreferences=true` 分支，**传送魔杖传 false，不添加这项限制**。玩家没有怪物 info 旗标，按基础禁入集处理。

生产实现为 `Movement/CreaturePlacement.ts` 的 `teleportForbiddenFlags`、`teleportCandidates`。遍历全部格子，不再做至多 100 次随机坐标试探；`machineNumber` 与 Game 的机器 footprint 集合都参与过滤；全层 `T_OBSTRUCTS_PASSABILITY` 能挡住 FLOOR 上的 FORCEFIELD，不能用 `layers.includes(FLOOR)` 或缓存 `isPassable` 代替。

**失败证明：**候选数组为空立即返回 false；在写坐标前再调用 `canPlaceCreature`，拒绝越界、非整数坐标、全层阻路和其他活生物；失败不改坐标、不执行落格效果、不刷新视野。没有“保底坐标”、没有把另一个生物挤走、没有杀掉占位者。占位还包括 web 独立 `dormantMonsters` 链，按本任务硬约束比 CE 的 `HAS_MONSTER` 过滤更严格。尸体不占位。已处于墙内的嵌墙俘虏在失败后可能仍在原位，这不是将其安置进另一堵墙。

注意区分两种失败：**传送安置失败**保留坐标；**施法过程**可能已经释放俘虏，且正常确认射击仍消耗一电和一个动作。释放/消耗不回滚，CE 也是这个顺序。

## 2. IMMOBILE、俘虏、抓取与关系

`IMMOBILE` 在 effect 分支先检查，阻止传送也阻止释放；不把 INANIMATE、INVULNERABLE、队伍关系另加成传送免疫。W-4 的路径/反射分派未改，反射可把玩家作为真正命中者；命中坐标快照不随目标落位移动。

`Movement.c:728-758` 的 `freeCaptive → becomeAllyWith` 不只是清囚禁位：降级旧首领、放下携物、成为玩家盟友、清 CAPTIVE/SEIZED，之后发释放消息。新 `Game.freeCaptive` 对已有 web 载体执行：

- 清 `isCaged`、设 `isAlly`、清 `seized`、清旧 `leader`；web 的玩家随从表示是 `isAlly + leader=null`，无 `MONSTER_ALLY` 枚举，因此设为可行动的 WANDERING。
- 当前层与已缓存层的普通随从重选首领；休眠随从脱离旧首领；继任随从的 waypoint 状态按 `Monsters.c:4103-4152` 更新。
- 携物在**旧位置附近**落下，先于传送选点。`captiveItemDropCandidates` 对应 `Monsters.c:4074-4084 → Grid.c:287-360`：优先原格，随后最短八邻域路径、并列随机，最后最近切比雪夫环；不落玩家/楼梯/已有物品，不额外排斥其他怪物或机器。最后物品兜底复用 `randomMatchingLocation`，对应 `Items.c:422-429`，绝不用于生物。
- 病态地图连物品兜底也无处可放时保留携物，避免 CE 随后对 `(-1,-1)` 调用落物造成非法访问。这是物品异常输入保护，与已按 CE return 的传送失败不是一回事。

CE `disentangle`（`Monsters.c:1146-1152`）只清 STATUS_STUCK，**不清 SEIZED/SEIZING**。web 没有独立 STUCK 状态，蛛网挣扎是“从当前网格走路”的行为；魔法移出原格已经摆脱原网，原网仍保留。普通传送不清抓取双方的簿记；玩家后续移动按既有 `findLiveSeizer` 校验距离，远离后抓取失效。俘虏获释时清自己的 seized 是 becomeAllyWith 的独立规则。

未虚构缺失字段：web 没有 `carriedMonster`、`MB_BOUND_TO_LEADER`、`turnsSpentStationary`、`MB_SUBMERGED` 等载体，本轮不新建这些子系统或存档字段；CE 对这些字段的附带处理不宣称已完成。已有 C-5 `falling/preplaced` 完整沿用。

## 3. 通用安置 API（W-12 交接）

```ts
canPlaceCreature(world, target: Creature, destination: Pos): boolean
Game.placeCreature(target: Creature, destination: Pos): boolean
Game.freeCaptive(monster: Monster): void
```

`canPlaceCreature` 是不掷骰、不写格子的物理安全查询。`placeCreature` 负责重新验证、提交坐标、仅结算目标的瞬时地形效果、更新视野，以及玩家落点拾取；返回 true 表示**成功提交移动**，目标之后可能因落格熔岩死亡，或被陷阱再次传送。同格请求返回 false，避免重复触发落格效果。失败为无副作用的 no-op。

**通用性：**安置入口没有随机远距/FOV/机器/楼梯/危险地形禁入策略，没有 IMMOBILE、阵营、法器附魔、释放俘虏或额外耗时的隐式规则。W-12 先算 blink 的终点及效果资格，再调用本入口；因此能落在深渊等危险格并触发真实后果。beckoning 需要的“先释放”和首行动等待由效果调用方显式处理。不能把 TELEPORT 的安全地形候选集拿来限制 blink，也不能用普通玩家移动命令代替本原语（那会多收费、攻击或弹确认）。

安置通过坐标更新占位，web 没有需同步清写的 HAS_PLAYER/HAS_MONSTER 格旗标。旧格查询立即为空，新格查询立即命中相同实体。非伤害、非状态副本，不重新构造怪物。成功随机 TELEPORT 另调用既有 `WaypointSystem.chooseNewWanderDestination`，复用 P4-10 的初始化/抽签语义。

## 4. 地形、视野及 C-5

`Monsters.c:3684-3715` 的顺序是落位 → instant tile effects → 玩家 updateVision → 拾取。新入口使用现有环境结算的 `instantTarget` 模式：

1. C-5 `creatureShouldFall` 先判；玩家置 `playerFalling` 并返回当前格地形结算，怪物置 `falling` 后继续。**不在 placeCreature 内直接调用 playerFalls/monstersFall**。
2. 熔岩按现有免疫处理；单目标模式补全叠层缠绕和灭火地形保护。深水不会凭空造成溺水伤害；非悬浮目标进入水域沿用灭火逻辑。
3. 落格陷阱/压力板和 creature/player-entry 晋升即时执行。CE 目录的 `T_IS_DF_TRAP` 逐层走 fire DF → 普通晋升/接线；用每个 grid 的短期压板集合防止同一客观周期重复触发，在客观环境结算后清除。此集合不入存档、不在生成阶段初始化。悬浮不踩地面陷阱；普通门的 ON_CREATURE 晋升对悬浮仍有效。新入口不用含 ON_ITEM 的宽泛 step 掩码替代 CE 的 creature/player-entry 掩码。
4. 火焰暴露、爆炸及混乱/麻痹气体即时状态只结算移动目标；不会让全图生物多走一个环境 tick。毒气/蒸汽的 gradual HP 伤害留在客观时间，未变成毒状态。
5. 刷新视野，玩家拾取落点物品；拾取不再提交第二次玩家动作。嵌套传送陷阱也走安全安置，内层已结算新格后外层不重复结算。

随机 TELEPORT 对普通物种本就排除深渊/陷阱/熔岩/深水；原生飞行等许可不同。因此不能为了测试坠落而强行让普通魔杖绕过 CE 过滤。对抗测试分别验证随机策略和**通用强制落位**：真实 C-5 玩家回合末换层、怪物 6–12 clump2 随落且只一次、悬浮豁免、叠层 WEB 保护。C-5 的 `playerFalls`、`monstersFall`、`playerTurnEnded` 原文不改。

承接既有环境边界：深水卷物/随机漂移、submerged 和恶心等尚无完整 web 消费链的部分，本轮不补；原有种族自定义气体免疫/抗性也保留。传送后接现有地形系统不等于宣布这些环境欠账已清零。

## 6. 任务 §1 三条线索结论

- **“TELEPORT 没有设置 autoID”正确。** 原 case 不赋值；成功、失败、IMMOBILE、释放俘虏、反射到玩家都不因这个效果自动鉴定。旁路射线地形效果的 autoID 合成机制不改。
- **“释放俘虏”正确，但不能解释成只有移动成功才释放，也不只是清 isCaged。** 详见 §2 的原码调用顺序与关系/携物处理。
- **“W-12 依赖本轮安置原语”是项目设计要求，不是 CE 事实命题。** 按要求实现公共 placeCreature，并用危险格、玩家拾取和嵌套位移测试证明其没有把随机传送策略写死。

任务线索没有发现相当于上一轮“毒气=毒状态”的错误。额外纠正的是旧实现/旧 W-4 夹具：任意 FLOOR 不等于 CE 传送落点；可见格也不合法。
