# W-19：变形

基准 `e6f6e99f7ad51ed142ceb5ad762f503289fac37c`。按任务书与 W-0 **W-19 行**执行（该行实际位于报告 §2.4，任务沿用 §2.3 的称呼）。POLYMORPH 已接入真实射线命中；没有增加 polymorphism 魔杖身份、种类或频率，入池仍属 W-24。

CE 引用均指仓库内 `BrogueCE-master/src/`，不是其它版本。web 路径相对 `brogue-web/`。实现入口为 `Game.applyBoltEffect → Monster.polymorph`，物种抽取/血量在 `Combat/Polymorph.ts`。不存在按深度 spawn、替换数组元素或调用分裂入口的变形实现。

## 1. 物种筛选与非原物种

`brogue/Items.c:4572–4634` 是实际执行函数；`updateBolt:5260–5268` 调用它。

- **受术者资格**：玩家、当前 `info.flags` 含 INANIMATE 或 INVULNERABLE 者立即返回 false；不变队、不清状态、不抽随机数。web 将复合 MONST_TURRET 的 INANIMATE 成员展开判断（`Rogue.h:2093`）。IMMOBILE、武器免疫、NO_POLYMORPH 本身不是受术者禁令；lich、phoenix、mangrove dryad、revenant 均可被变走。
- **输出资格**：每次执行 `rand_range(1, NUMBER_MONSTER_KINDS-1)`，拒绝目录 INANIMATE、NO_POLYMORPH 或与当前 monsterID 相同者，直到合格。没有深度、地形适居性、horde、machineOnly、boss 或频率筛选。不是先缩成候选表再抽一次；无效项与原物种会各消耗一次重抽。
- 当前 CE 有含玩家的 68 行；既有 `monsters.json` 的 67 行恰为 CE 索引 1～67，原序、id、HP、速度逐项与编译出的目录对照。使用这份现有投影，不改数据。包括大小写特别的 `Warden_of_Yendor`，没有按小写重造 ID。
- 输出合格项 47 个。若原物种也在此集合，实际可能结果为其余 46 个；若原物种本就不能被抽出，则仍有 47 个。全部按完整 1～67 范围拒绝抽样。新旧形态比较的是 `typeId`，不是实体 `id`、字符或本地化名字。

20 个输出排除项：`goblin_totem, arrow_turret, ogre_totem, spark_turret, sentinel, dart_turret, lich, phylactery, flame_turret, spectral_blade, spectral_sword, stone_guardian, winged_guardian, guardian_spirit, Warden_of_Yendor, eldritch_totem, mirrored_totem, phoenix, phoenix_egg, mangrove_dryad`。并非笼统“排除特殊怪/首领”：goblin warlord、black jelly、vampire、unicorn、ifrit、dragon 能成为结果；浅层地板上也能变出 eel，**不主动寻找水域或迁移**。

证据：[编译目录](w-19-evidence/ce-catalog.json)、新测试目录全枚举、同物种/炮塔/lich/phoenix/dryad/Warden 连续拒绝后 unicorn 的真实射线用例。每次抽签参数严格为 `(1,67)`，并断言原对象仍在原数组/原格。

## 2. 血量和速度：执行顺序是规格

CE `Items.c:4595–4619`：

```text
fraction = trunc(oldHP * 1000 / oldMaxHP)
previousDamage = oldMaxHP - oldHP
newHP = max(1, trunc(fraction * newMaxHP / 1000), newMaxHP - previousDamage)
```

两次整数截断，比例与原受伤量取较优者；不是全疗、单纯百分比、随机重生，也没有 `min(newMaxHP, ...)` 上限。

| 输入 | 新形态 maxHP | 结果 |
|---|---:|---:|
| ogre 28/55 → jackal | 8 | 4 |
| rat 5/6 → dragon | 150 | 149 |
| dragon 75/150 → rat | 6 | 3 |
| 人工过量 HP 7/6 → dragon | 150 | 174（CE 无上限钳制） |

`scripts/w19-ce-golden.mjs` 提取并编译 **未改写的 `polymorph`、`unAlly`、`initializeStatus` 函数体**，枚举/目录数值和资格表达式也来自 CE 原文；最小结构与画面/关系回调是隔离桩，不能据此冒称完整 CE 游戏差分。9 组 oldMax（3/7/8/19/25/99/100/101/137），各自 HP=1..max+1，8 个输出形态，4 组 haste/slow 组合，共 **16,256 组**。测试把每行同时用于纯 HP 函数及实际 `Monster.polymorph`，逐行比对 HP、移动/攻击速度、清空后的 haste/slow。全部匹配：[C 取证程序](w-19-evidence/ce-polymorph.c)、[黄金值](w-19-evidence/ce-polymorph.txt)。

**CE 先换 info，把 current speed 设为新目录速度，再读旧 HASTED 减半、旧 SLOWED 翻倍（两个独立 if），最后才 `initializeStatus`。** 因此变形后 haste/slow 图标消失，但缓存速度仍保留该调整；不会凭空等一个已清零的计时器到期。web 用 `polymorphKeepsSpeed` 保留这条语义，不让无关状态的施加/到期通过通用 `refreshSpeeds` 提前恢复速度。新的 haste/slow 或其到期恢复正常规则；CE `negate:4508–4515` 无条件按缓存差值还原速度，所以现有消魔入口也清除此标记后重算。

首行动预算为 `max(oldTicks,101)`，不是新物种 movementSpeed，也不是固定赋 101。真实确认用例：原 budget=0，施法客观推进100后目标仍剩1、没有行动；下一个 wait 才行动。已有更长 budget=333 保留333。

## 3. 去盟友、俘虏与 W-17 关系原语

魔杖描述 `variants/GlobalsBrogue.c:704` 的“盟友转而敌视你”成立。真正路径：`updateBolt → polymorph → unAlly`，其中 `Monsters.c:2948–2955` 仅在 ALLY 时把 state 改为 TRACKING_SCENT、清 FOLLOWER/TELEPATHICALLY_REVEALED、自身 leader=NULL。

**驳回“去盟友通常应照 W-17 为原群另选首领”的推测。** 普通 unAlly 不调用 demote：目标脱离自己的首领；别人指向它的 leader 引用不变；不会把整个群一起变敌对，也不会断开它的 bound/dormant 随从。原本敌对的目标连自己的 leader 也保留。web `isAlly=false、dominated=false、state=HUNTING、leader=null` 只在相应转换处使用；bound 标志不擅自清掉。

**只有原目标是 CAPTIVE 时**，CE 在换 info、初始化状态之后调用 `demoteMonsterFromLeadership`，再清 CAPTIVE、设 TRACKING_SCENT；这条分支复用 W-17。把原 `becomeAllyWith` 中的首领降级代码原样抽为 Game 私有方法，W-17 原调用保留；W-19 只从 captive 回调调用它。当前层优先、其它缓存层按深度、bound 随从断连、普通随从首个继任、休眠另遍断连、跳过当前层过时缓存等 W-17 守卫全部保留。

不能调用 `freeCaptive/becomeAllyWith` 代替：它们会转盟友并掉携物，而变形释放俘虏仍是敌对、仍带原物品。captive demotion 也没有顺便清目标自身已有的敌方 leader。bound 盟友去盟友后若成为孤儿，其 BOUND 位保留，下一次原有 `killOrphanedBoundFollowers` 才死亡，不在变形中假造伤害。

状态前置还保留 C 运算优先级：`(FLEEING && (MAINTAINS_DISTANCE || FLEES_NEAR_DEATH)) || MA_HIT_STEAL_FLEE`。偷窃能力者即使 ASLEEP 也转 HUNTING；普通睡眠目标不被额外唤醒。测试覆盖这六种状态组合，以及抽签前已完成去盟友/清 mutation/清 carriedMonster 的顺序。

## 4. 字段逐项核对

参照 CE `creatureType/creature`（`Rogue.h:2172–2194、2260–2319`）与整个 polymorph 函数。以下“保留”不是依据重要性猜测，而是该函数没有写这个 creature 字段。

| 字段/语义 | W-19 处理 | CE 执行依据与 web 表达 |
|---|---|---|
| 实体对象、id、loc、所在活动/休眠/缓存数组 | 保留；不构造、不摘链再生成 | `monst->info = monsterCatalog[...]`，没有 `generateMonster/killCreature` |
| 物种 ID、名字、字符、颜色、描述 | 替换为新目录投影 | 整个 info 替换；描述按新 monsterID 对应词条；名字经既有翻译 |
| maxHP、damageString、accuracy、defense、regenTurns | 替换新种类值 | info.maxHP/damage/accuracy/defense/turnsBetweenRegen；CE regen×1000 为其毫回合量纲，web 保留现有“回合数”量纲，不多乘1000 |
| currentHP | §2 双截断公式 | 不做满血或上限钳制 |
| 基准 move/attack speed | 新目录值 | info 替换 |
| 当前 movementSpeed/attackSpeed | 新基准后先旧 haste/2，再旧 slow×2 | 两个 if，随后状态被清；见 §2 |
| behaviorFlags、abilityFlags、bolts | 整体替换，Set/数组独立 | info.flags/abilityFlags/bolts 全部覆盖；旧突变、强化获得的能力不混进新物种 |
| abilities、onHitStatus/chance/duration、statusImmunities、statusResistTurns | 新目录投影，缺省清空/0 | 这些是 web 既有附加通道；跟随新物种，不能保留旧形态攻击附加/抗性 |
| mutation | 清为 undefined | `mutationIndex=-1`，在抽物种之前 |
| wasNegated | false | :4617；增加明确载体供本轮重置及后续 W-23 使用，未借机实现完整消魔 |
| 全部 statusDurations（含 burning 扩展键） | 清空后初始化新形态永久特性 | `initializeStatus:3907–3924` 先清 status/maxStatus 全数组 |
| burning/levitating/immune_fire/invisible | 分别按新 FIERY/FLIES/IMMUNE_TO_FIRE/INVISIBLE 设1000 | 四个独立旗标分支，永久性由旗标保证；旧状态、旧永久飞行/火免均不会漏留 |
| maxShield | 0 | maxStatus 被清；不只清 shielded 当前量 |
| poisonAmount | 原值保留，但 poisoned=0 时无伤害 | CE 的浓度在 creature 外层，不是 status/maxStatus，initializeStatus 没清；重新中毒仍走既有叠毒入口 |
| regenCounter | 保留 | CE 外层 turnsUntilRegen/regenPerTurn 未重置；web 既有计时表示保留，不用新怪构造器归零 |
| state | 仅 §3 的旧逃跑/偷窃、去盟友、俘虏三类条件改变 | 无无条件唤醒；新物种 NEVER_SLEEPS 不触发构造时的随机睡眠 |
| leader/isAlly/dominated | §3 条件处理，其余指针保持 | `unAlly` 与 captive `demote` 不混淆；dominated 是 web 盟友来源标记，去掉以免存档恢复旧身份 |
| seized、seizing | 两者都 false | 清 MB_SEIZING/MB_SEIZED；不擅自写对方生物的标志 |
| isCaged | 清 false；仅该分支先 demote | :4620–4624 |
| carriedMonster | 丢弃引用，null；不伤害、不刷实体、不掉落 | `freeCreature` 后 NULL，区别于 `killCreature`；测试中载荷自身 HP 不变且未加入活动表 |
| carriedItem | 原引用保留，死后仍由正常掉落出口处理 | CE 没有 `makeMonsterDropItem` 调用；不是 W-17 的成功支配 |
| goldDropChance/itemDropChance | 保留原数值 | CE 无这种死时概率字段；作为 web 既有掉落行为保留，既不替换成新目录掉落也不在变形时造物；不宣称该历史掉落系统已 CE 对齐 |
| ticksUntilTurn | max(old,101) | :4627 |
| boundToLeader、boundToPlayer、doesNotTrackLeader | 保留 | 对应绑定/不追踪 bookkeeping 未被清；普通刀刃原本 INANIMATE，不能借变形越过入口门 |
| deathEffectTriggered、falling、preplaced、isDormant、machineHome | 保留 | 相应死亡/坠落/预置/休眠/机器簿记均非 polymorph 写点；不能把实体当新 spawn 清除 |

web 尚无独立 creatureMode（MODE_NORMAL/PERM_FLEEING）、weaknessAmount、nutrition/maxStatus全表、学习/尸体吸收计数、mapToMe、gender 与部分 bookkeeping；本轮没有虚构这些系统。已有 state 分支按 CE 对应执行；怪物 nutrition=1000 不影响 web 玩家饥饿，不能借机改玩家营养。未来 W-21/22 增加 learning count 时须留意：**polymorph 换 info，但没有清 newPowerCount/totalPowerCount/吸收进度**。

新 fiery/invisible 永久状态的补足只作用于 `polymorphed` 实体；自然生成的构造流程未改成额外初始化/RNG，以免夹带 P1-28 其它物种旧行为变动。

## 5. 实体身份和后续死亡

变形后的 `result.hits[].creature`、`game.monsters` 成员、已有其它怪物的 leader 指针都是原对象；`id`、loc 对象本身不换。native ability/type 完全换成新值，所以原 bloat→rat 后死亡不喷毒，rat→bloat 后死亡喷一次，清扫两次也只掉一次原钥匙。没有“旧物种死一次、新物种再 spawn”的 kill/loot/stat 副作用。

清 carriedMonster 确保没有变形后死亡掉出旧 phoenix/phylactery/vampire 载荷。CE 真死亡的 carriedMonster 展开在 `Combat.c:2018–2036`，变形是先 `freeCreature`，不是触发这条链。web 新增可丢弃的载荷字段，但 **P4-2 原来的寄宿/复活生成流仍未建模**；没有声称本轮补成完整凤凰/巫妖复活。

变形没有 CE `applyInstantTileEffectsToCreature` 调用；失去飞行时仍留原格，后续原有环境门才结算熔岩/坠落。测试明确断言变形接触中不调用环境入口、随后环境调用杀死地面形态。原群其它引用不重写；通用死亡后群体继任在 web 仍是 W-17 登记的旧缺口，本轮没有以变形之名扩写全部死亡关系系统。

## 6. W-8 克隆缺口：登记修法，不修改

`trySplitMonster` 与 HEAD 逐字一致，P4-4 原测试也未改。W-8 的缺口仍有效：从目录 `new Monster` 然后补少量字段，不等价 CE `cloneMonster:574` 的 `*newMonst=*monst`。本轮的形态重置表也**不能**拿去当克隆默认值表：变形清状态/能力，克隆先复制当前真实状态/能力。

W-20 应从当前实体复制全部 creature/info 语义，给 web 克隆分配新的独立 id，再逐项覆盖 CE 克隆例外；Set、状态对象、数组等可变值独立复制，leader 等实体关系用原对象引用/新关系规则，不深复制整个关系图。以本轮新增字段为例：当前实际 form、poison/maxShield、缓存速度及 polymorphKeepsSpeed 必须审计继承；mapToMe/safetyMap、carriedItem、leader/captive、ticksUntilTurn=101 等按 clone 原路径单独处理。不能调用本轮 polymorph 方法复制实体。

还有两处执行代码提醒给 W-20：① CE clone 在整体赋值前仍调用 `generateMonster(...,false,false)`，其初始化耗骰需另读，不可把“本轮变形不构造”套成复制的 RNG 规格；② 当前 CE `:583–587` 虽递归 clone carriedMonster 并将生成体摘链，却没有把 `parentMonst` 再赋给 `newMonst->carriedMonster`（后者先被置NULL）。不要只按“Also clone the carriedMonster”的注释脑补它已挂回去。本轮未修、未改此执行事实。 另需为 W-20 的玩家克隆建立明确的物种身份：CE 克隆对象并非 `&player`，但复制的 info 可仍是玩家 monsterID=0；目前 web 无此类实体，本轮的未知旧档 ID 保护不能被直接沿用为拒绝未来合法玩家克隆变形的理由。

## 7. 共用入口的实际行为变化

1. `Monster.polymorph` 为新增入口；本轮只接玩家射线 POLYMORPH 命中，反射也只作用于轨迹实际命中者。当前怪物目录没有 POLYMORPH bolt，不添加怪物施法种类，不改 `castMonsterBolt` 或其伤害公式。
2. `becomeAllyWith` 内首领降级抽出为私有方法；原 W-17/W-11 调用和行为保持。W-19 captive 才新增使用，普通 unAlly 不使用。
3. 变形过的怪物对 fiery/invisible 的派生状态提供永久性、对清空 haste 后的缓存速度提供保护；未变形者保留原通用状态行为。消魔共用入口额外撤掉该速度保护，使变形者的缓存速度按 CE 恢复。
4. `snapshotForm` 补齐 onHit、抗性、description 的现有字段；普通新快照也保存实际 form。**读档后的普通怪物**现在保留 typeId、真实 behavior/ability flags、bolts、accuracy/defense/基准速度等，不再因缺失 form 退成名字拼出的通用怪。这是确保首次变形前原物种/免疫资格可用所必需的存档行为变更，不能只写“保存变形结果”。其它来源的已保存实际形态也得到这项补齐。
5. 新、旧已识别物种读档可能因恢复的旗标使既有 `Monster` 构造器走不同的初始睡眠条件；state 随后仍恢复快照。种类识别/迁移自身无抽签，**不声称旧架构的整个 loadSnapshot 无 RNG 或跨版本游玩重放不漂移**。新局/直接下层生成与本次新增变形选择不是同一个边界。

没有改 Creature/Combat 通用攻击、生成、召唤、分裂、地形或 UI 实现。详细文件和方法边界由 [boundary.json](w-19-evidence/boundary.json) 对 HEAD 校验。

## 8. 存档与旧档兜底

新增可选 `form` 存当前实际种类/能力；新增可选 `polymorph` 标签只给已变形实体，保存当前速度及保护标记、首行动预算、wasNegated、抓取、绑定、休眠/机器/死亡/坠落/waypoint/safety 记账和原 carriedItem。状态/HP/poisonAmount/maxShield 继续共用现有字段，关系继续共用 W-17 allegiance 的 leaderId，两遍恢复活动与休眠列表。不可把已变形的普通怪物继续标为 dominated 来借用存档。

当前层活动怪、休眠怪、测试房基线/重置出口都接同一 form/变形标签。携物走现有 Item 序列化；load 前的实体 ID 上界计入新保存的携物与变形休眠实体，测试用 carriedItem.id=900000 验证新建实体不撞号。变形后 JSON 往返保留同一实体编号、新物种、速度、leader 引用和后续一次性死亡掉物；恢复的是新进程对象，不能把跨 JSON 的引用等同于内存对象复用。

旧档策略：已有 W-16/17/18 实际形态标签继续优先保留；无 form 的普通旧档，仅用**完整英文原名或当前语言的完整译名唯一匹配**已有目录。恢复其种类/原生资格与其它缺失基准，再以快照已有 HP、伤害、状态等值覆盖；不根据同字形、深度或数值近似猜物种。没有唯一匹配（如已失去源 ID 的旧突变名/另一语言自定义名）则维持原旧档数据，POLYMORPH 入口额外拒绝未知 species ID，零写入/零抽签/不 autoID，防止自称“非原物种”却抽回原形。

这是 web 不完整旧档的兼容保护，CE 正常对象总有合法 monsterID，没有这条未知 ID 分支。无法从历史缺失字段无损恢复原突变/消魔后的旗标，报告不把原生目录兜底说成复原了这些信息。无 polymorph 标签不推断为已变形，不恢复特殊速度或虚构盟友。

内存 levels 缓存保留同一对象，变形不用跨层 spawn；全 levels 缓存仍不在既有全局 JSON 快照中。全层持久化与完整 carriedMonster 寄宿复活仍是既有架构边界，不在本轮偷偷补系统。
