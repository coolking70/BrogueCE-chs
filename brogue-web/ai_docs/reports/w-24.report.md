## 2. 抽签顺序和随机边界

真实链路为 `Game.spawnPopulateItem` 的 WAND 分支 → 对 `ItemLoader.genWands` 按数组原序取 ids/frequencies → `Game.chooseKindFromPool` → `ItemLoader.chooseKind` → `spawnKindById` → `spawnWand` → `rollWandCharges`。`filterPool` 保持原数组相对顺序，无排序、无按 weight/minDepth 二次筛选。CE `Items.c:409–420` 同样按表序消费累计频率；全22张票的区间已逐票验证。

新 kind 必抽一次 `randRange(1,22)`；随后除赋能外各抽一次 clump=1 的充能区间。赋能退化区间不增加 `randomNumbersGenerated`。这里“调用计数”是 Random 的 substantive 范围抽签计数，不把 PRNG 内部 rejection 的底层 ranval 次数混算。

`initConsumables` 洗牌走 COSMETIC，且洗的是完整外观词表，新增4个目录条目本身不多抽 substantive。Game/Generator/Map/Random 的生成算法原样；最终边界审计核对 Game 只修改 `toSnapshot`、`loadSnapshot`。

## 7. 旧档身份与 flavor 兜底

旧版本没有保存 flavor map，`loadSnapshot` 按 seed 调用 initConsumables 重建；因此本轮若仅重排数组，旧魔杖的外观/玩家记忆会错位。新增可选 `GameSnapshot.wandFlavors`：新档保存11种 id→外观，读档先正常初始化，再恢复保存映射；缺失新种类按当前剩余槽确定性补齐，不重复外观。

无此字段的旧档，按原7行顺序 fire、lightning、teleportation、slowness、invisibility、empowerment、beckoning 恢复原槽0–6，再为新增4种分配未用槽。完整外观洗牌表及其之前的药水/卷轴步骤没变，因此同seed这些槽确为旧外观。恢复 helper不调用RNG、不生成物品；真实 load 中身份与电量仍由原反序列化路径恢复，不重新抽充能。原绰号、鉴定、极性集合都按字符串id，不受目录序号变动影响；新增种类保持未知。

测试临时使用真正旧7项列表生成旧映射/存档，删除新字段，经真实 load验证旧外观、耗尽0电、身份/绰号/极性、11外观唯一、新种类未知；升级后再保存/读取仍稳定。另验新档完整map和部分map确定性补齐，helper前后整个RNG对象一致。
