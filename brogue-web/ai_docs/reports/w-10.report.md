# W-10：毒状态闭环

本轮以 `w-0-survey.report.md` 的 **W-10 行**为规格（任务书称 §2.3，现文件实际在 §2.4 效果表），以本仓库 `BrogueCE-master` 为 CE 证据。完成毒杖、浓度/时长、客观毒伤、再生抑制、免疫、死亡与存档；不增加种类或更改 frequency。以下路径除 CE 前缀外均相对 `brogue-web/`。

## 1. CE 规则与公式

`BrogueCE-master/src/brogue/Combat.c:1905–1920` 的 `addPoison`：只有 `durationIncrement > 0` 才生效；浓度加 `concentrationIncrement`，结果为零则设 1；剩余时长直接相加。每次毒杖命中在 `Items.c:5322–5324` 调用 `addPoison(target, staffPoison(E*FP_FACTOR), 1)`。**施毒本身不扣 HP**，不是取最大时长或按剂量分别维护计时器。

落地为 `Creature.poisonAmount` 与 `statusDurations.poisoned`，共用 `addPoison`；通用 `applyStatus('poisoned')` 转到它，其它状态语义不改。`setStatusDuration` 兼容直接设置/清除，清除必清浓度；旧档恢复见 §5。零浓度增量支持建立至少一剂而不增加已有浓度（CE 毒地衣式规则），没有新增地衣入口。CE 的 `maxStatus[POISONED]=maxHP/poisonAmount` 是展示量，本项目无对应 maxStatus 状态条；不把它误当最大时长或封顶规则。

`PowerTables.c:60–71` 核实结果：

```text
i = clamp(trunc(E) - 2, 0, 50)
staffPoison(E) = floor(5 * POW_POISON[i] / 65536)
```

`POW_POISON` 为 CE 的 **51 个固定点整数**，数学近似为 `1.3^i`，没有改用浮点 `Math.pow`。`Combat/Poison.ts` 原样移植整数表；新增测试从 CE 文件独立读取全部 51 项核验，并验证两端 clamp 和 E 小数截断。E2=5、E3=6、E8=24。真实施法从 `resolveCEBoltMagnitude(...,{kind:'staff',enchantment:item.enchantment})` 读取实例 E，不读 charges、maxCharges 或遗留配置 magnitude。

叠加实例：E2+E3 连中得到 11 tick、2 剂，HP 当下不变；下一客观块只扣 2、时长变 10。再命中 E2 得 15 tick、3 剂，下一块扣 3、时长变 14。

## 2. 客观时间与再生

接线为 P2 原有 `advancementLoop → 每100 ticks objectiveTimeBlock → tickCreatureStatuses → resolvePoisonDamage`。`objectiveTimeBlock` 正文未改；新伤害只从这一个状态出口调用一次。每个活体先结算燃烧，再结算毒，再统一递减状态。CE 毒伤参考 `Time.c:2593–2601`、`Monsters.c:1916–1931`：本轮把递减安排在统一状态遍历，伤害仍使用递减前的浓度，所以最后一跳不会漏，结束后浓度清零。毒不经过物理攻击、防御骰或分裂逻辑，伤害无随机数。

**不按玩家动作数的证据**：真实 `handlePlayerAction('wait')` 下，4个 haste 动作（50 ticks）、2个普通动作（100 ticks）、1个 slow 动作（200 ticks），都使玩家中毒损失2 HP、怪物2剂损失4 HP，各递减2 tick。第一个50-tick动作零毒伤；第二个补足块才结算。浏览器亦验证两个50-tick动作从目标50HP/6时长到49HP/5时长。存档保存并恢复原 P2 的半块计时。

玩家 `hunger_regen` 的 **300动作回满、再生光环0.6倍时间、饥饿阈值与回血解耦**保留。再生小数余数只暂停，不丢弃。本动作开始或期间有毒时，`poisonedDuringTurn` 锁存到 `recoverPerTurn`，防止末次毒在客观段结束、随后的主观收尾立刻抵消毒伤。下一动作无毒即恢复。营养0的玩家仍受到饥饿伤害；已死玩家收尾不再回血或被饥饿覆盖死因。

怪物原再生在 `takeTurn`，W-10 将同一计数恢复逻辑移入 `recoverPerTick`，在客观状态块的毒递减之前执行，依据 `Monsters.c:1839–1847`。中毒时计数暂停，最后一跳也不回血；下一块继续原进度。这一共享变化意味着无毒怪物的再生从行动次数改为客观次数，麻痹/被笼住也不再因 `takeTurn` 早退而阻断自然再生；不改变 regen 数值、物种表或生成。新增测试锁定计数2/3在两跳毒期间不动，清毒后下一块回血并归零。

**不复用 W-9 的 `applyBasicBoltEffect`**。五种状态的覆盖/max/速度互斥与毒的两个累加字段、持续伤害、死亡和持久化不同。毒保留独立 CE 公式 helper 与 Creature 状态入口；仍消费 W-4 真正的命中对象，不重新找格子，不以反射器代替实际承伤者。W-9 helper 正文和其它玩家 bolt case 均与 HEAD 相同。

## 4. 免疫、鉴定与死亡只结算一次

`Monster.canBePoisoned` 拒绝 `MONST_INANIMATE`、`MONST_INVULNERABLE` 和死亡对象，依据 `Items.c:5323 / Combat.c:525`。**保留 W-2 已登记的 web `statusImmunities.poisoned` 扩展**（现有 vampire 数据包含该项），不能为了 CE 纯化悄悄移除它。武器免疫不等于毒免疫；隐形不免毒，但不满足观察时不 autoID。成功可观察的重复施毒正常 autoID；miss、墙截断、原点、免疫目标均不鉴定。返回玩家的真实反射可施毒与鉴定。

`resolvePoisonDamage` 以 `hp>0 && poisoned` 入门。毒使 HP 跨到0时，怪物死亡只在此记录一次消息、kills 与既有随机 loot；其它先杀死目标的伤害会使毒段直接早退。毒先杀死后，既有燃烧/环境伤害的死亡守卫也跳过。玩家毒伤置 `lastDamageSource='poison'`，推进立即停止并由统一收尾调用 `triggerGameOver` 一次；不会在另一慢块继续挨打，也不会收尾再生复活或饿死改名。

把原 `playerTurnEnded` 的 carriedItem 掉落/清空/过滤原样抽为 `removeDeadMonsters`，并在 `finishTurnEpilogue` 的 `triggerDeathFeatures` 后补扫，保证客观块内死者同动作退场。死亡 DF 仍使用原 `deathEffectTriggered`；没有新增第二个 DF 出口或绕开原流程。毒死亡借用近战的 `dropMonsterLoot`，没有凭空增加经验系统（本项目无经验字段）。

证明用例：同 tick 火先致死则毒不记 kill/loot；火未杀死、毒致死则恰一次；毒先致死后显式再调用火/毒也仅一次 die/loot；bloat 毒死后随机金币一份、携带品一份、死亡气体一次、同动作移除，重复清扫无新增；玩家毒/饥饿同 tick 致死只触发一次 GameOver。分裂只发生在活体物理受击后，各分裂体的毒独立继续结算。
