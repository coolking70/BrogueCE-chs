# W-15：护盾吸伤闭环

基准 `4e6a2fe`，2026-09-23。权威规格为 W-0 报告的 W-15 行（实际位于 §2.4 效果表；任务书称 §2.3 不影响取用同一行）。所有 CE 依据来自仓库 `BrogueCE-master`，没有借用其他版本。

实现已完成：真正命中者获得护盾、十分之一 HP 吸收、max/衰减/覆盖、绕盾、怪物共用入口和存档；**没有增加 protection 物品身份或进入生成池**。没有把直接环境扣血统一改为 `takeDamage`。最终门禁结果见 §10 和文末逐文件表。

## 1. CE 数值、吸收、max、衰减与覆盖

CE 简称：PT=`src/brogue/PowerTables.c`，CC=`Combat.c`，IC=`Items.c`，TC=`Time.c`，MC=`Monsters.c`，Math=`Math.c`。

| 规则 | CE 核实 | 落地 |
|---|---|---|
| `staffProtection(E)` | PT:57-59：`130 * fp_pow(FP_FACTOR * 140 / 100, enchant / FP_FACTOR - 2) / FP_FACTOR`；`FP_FACTOR=65536` | 新 `Combat/Shielding.ts` 用 BigInt 重现 Math:272-287 的余数反馈和最终舍入；不抽 RNG，不用浮点近似 |
| 量纲 | CC:1811-1819：先比较 `shield > damage*10`，余额分支每 HP 扣10 | `statusDurations.shielded` 存十分之一 HP；`maxShield` 对应 CE `maxStatus[SHIELDED]` |
| 未耗尽 | `shield > damage*10`：盾减少，伤害归0，max不变 | `Creature.absorbShieldDamage` 只修改盾，返回剩余HP伤害；不扣HP、不调用die |
| 耗尽/恰好耗尽 | 否则 `damage -= (shield+9)/10`，current/max同时清0 | `ceil(shield/10)`；例如1点十分之一盾能挡最后1HP，11挡2HP，130受13伤时清空两字段 |
| 覆盖 | IC:5405-5408：current取旧current与新值之大；**无条件将max设为新的current** | 不叠加；弱施法/等强施法也可能重设衰减基准。356受5伤剩306，再上130，得到306/306 |
| 衰减 | TC:2310-2314、MC:1958-1963：current减`max/20`整数除法，耗尽清两字段 | 在既有客观tick状态入口中特判shielded。130每tick减6；并非减1，也并非current/20。max<20时CE确实不自然衰减，未擅加最低1 |
| 最大值含义 | CE max是衰减基准；公式无本轮另加的HP比例或maxHp封顶 | current/max分别保存；吸伤不降低max，只有再施法、清除、耗尽改变max |

用脚本提取**未修改的 CE 三个 C 函数**（fp_round/fp_pow/staffProtection），clang 编译独立核对。E=0…20逐值证据在 [ce-formula-values.txt](w-15-evidence/ce-formula-values.txt)，特别是 **E2=130、E3=181、E5=356、E8=978**。浮点`130*1.4`得到182，已经不是CE整数真值。没有套用W-10毒公式的表钳位，CE这里用的是fp_pow，不是POW_POISON表。黄金值验证的是函数返回值；web状态沿用JS数值模型，不模拟Rogue.h:2299-2300的C `short`窄化溢出（E19起公式值超过32767）。这不是新增数值封顶，也不声称极高E的C溢出行为已经仿真。

## 3. 绕盾规则与伤害处理顺序

确定绕盾：持续燃烧、毒状态、逐渐地形伤害（毒气/蒸汽）、饥饿、互惠向其他目标分摊、报复反伤、即死/自毁/消魔死亡/墙中生物摧毁/熔岩/激活怪坠落。普通爆炸和普通坠落可吸盾。**“火伤”不是单一类型**：火杖直接伤可挡，之后的持续燃烧绕盾；**“毒”也不是单一路径**：毒状态和毒气各自绕盾，毒气仍不变成毒状态。

最初阅读函数名时，我在会话进度中把毒气/蒸汽误说成可吸盾；随后逐行打开TC:616-632确认实参为true，已即时纠正，代码与测试采用绕盾。这里保留纠错记录，不把初步判断当CE事实。

护甲原入口在HP扣完之后“回补减伤”，遇护盾会凭空回血且错误耗盾。三处已有运行期调用（普通近战、几何攻击、怪物bolt）改为传`beforeDamage`，先执行护甲减伤，再按W-10规则将物理毒攻击缩为1点接触伤，最后吸盾。CE次序依据CC:1272→1320→1325。原公开`tryTriggerArmorRunic(attacker,damage)`仍默认兼容事后回补，原直接API测试保留；实际调用传true返回剩余伤害。这也避免原先致死HP归零后再回补的顺序问题。未新增原来没有护甲处理的旧远程分支。

互惠旁伤/报复绕盾、玩家剩余伤吸盾；MA_TRANSFERENCE只用穿盾后伤害计算40%/90%恢复，不能吸到被盾挡掉的HP。护甲既有非CE扩展（dampening随机回补、immunity类别缺失、vitality等）保留条件/公式，只调整已有调用的时序；不宣称完整符文CE对齐。

## 4. W-2错配、玩家施法、怪物行为变化

玩家SHIELDING现在消费W-4轨迹命中的实际Creature，使用物品实例E（与charge/config旧magnitude无关）；空射/墙挡/同起终点不对自己施法，反射可给玩家自己加盾。删除原`applyTimedStatus(this.player,'telepathy',25)`、`+Light`及亮光日志，旧staff.bright_aura键归档至legacy；接触按IC:5412-5413设置autoID，包括隐形/效果数值未变的目标。CE的目标选择禁忌与实际命中后效果门不是一回事，未给命中分支新增INANIMATE筛掉规则。

`staff_of_light`是既有退役自创身份，配置仍映射SHIELDING，因而显式构造使用时也获得真实护盾；它没有被改名或充当CE protection入池。其历史“照亮/致盲”说明本来就不对应旧telepathy，保持退役数据不改，不能据该说明宣称已实现光明法术。真实protection身份/物品描述/池由W-26处理。

怪物的明确变化：

1. goblin mystic/unicorn既有SHIELDING目录magnitude5，现在施加356十分之一HP；原来只是15回合运行时键。
2. 共用Creature吸伤和`max/20`衰减，怪物与玩家一致；有盾仍被`specificallyValidBoltTarget`排除补盾，盾耗尽后恢复可选。
3. 怪物受到近战/投掷/伤害bolt/爆炸/坠落时实际扣盾；中毒、燃烧、气体等继续绕盾。
4. 自爆、消魔即死、墙中生物摧毁不被盾阻止；分裂后继承独立盾量/max，减半HP不减盾。
5. 怪物吸血量改为余伤；三处原护甲调用的前置时序会影响穿盾后的实伤及受击附带效果。随机数没有增加新的来源，运行期既有抽取顺序可能随护甲处理时序变化；不承诺旧战斗回放一致。
6. 怪物爆炸补CE无敌早退，既有爆炸骰/免疫窗/惊醒保持；大盾不能遮掩无敌分支缺口。

没有合并玩家/怪物两个大switch，没有改怪物伤害bolt公式、反射/路径/选敌元数据或移动缓存。**没有照搬W-13重建waypoint**：护盾CE分支无此调用。

## 5. 保存、旧档和界面

新增`maxShield`可选快照字段；current继续走已有`statusDurations.shielded`。玩家、活动怪、休眠怪的JSON保存/加载以及测试房基线/恢复两条怪物出口全部接齐。内存跨层缓存、pendingFallen保存对象本身，两字段随对象保留；没有扩张现有全局存档对未保存楼层的格式范围。分裂只补本轮盾字段，完整克隆其它字段仍属W-20。

旧档有`shielded`但没有`maxShield`时，旧值是倒计时而非HP，**清除该旧显示状态**，不从15回合推断保护量，也不留下max=0永不衰减的假盾。max非有限/非正或current非正时同样清两字段；合法current/max按整数恢复。迁移不抽RNG。旧`telepathy`无法区别药水、状态或旧光明杖来源，原样保留；本轮只是清除未来SHIELDING施法的错误写入，不误删合法心灵感应。

状态配置新增中文“护盾”；Sidebar将current/10显示为HP，避免把十分之一HP当剩余回合。GameCanvas自动化text hook增加current/max，便于复核截图。没有新增渲染层护盾光环；现有bolt动画末帧残留和技能客户端canvas导出黑图沿用既往登记，本轮用整页截图核验实际游戏与侧栏。
