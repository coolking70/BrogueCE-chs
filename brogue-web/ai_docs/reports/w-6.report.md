## 1. CE 依据与落地

本仓库 `BrogueCE-master/src/brogue/` 是依据，无外部版本替代：

| CE 位置 | 行为 | web 落地 |
|---|---|---|
| `Time.c:2025–2032` | 普通杖周期 `5000 / enchant1`，整数除法 | `Items/ArcanaRecharge.ts::staffChargeDuration` 读 E |
| `Items.c:338` | 普通杖初始 recharge mojo 500 | `INITIAL_STAFF_RECHARGE=500`，缺字段时懒读，不修改 Loader/生成 |
| `Time.c:2036–2075` | STAFF 扣进度、到期加次数、抽下一间隔；WAND 无此分支 | `tickStaffRecharge` + Game 的 STAFF-only 调用 |
| `PowerTables.c:72–82` | `1.3^x` 的 16 位定点表，智慧夹到 -10…27 | 照抄有效表段，增量 `floor(10 * table / 65536)` |
| `Items.c:1901–1909, 8714–8716` | 两槽智慧贡献相加；未知正戒指有效附魔有限制 | 每客观块读取 `player.rings()`，只统计智慧；不把种类已知当实例鉴定 |
| `Time.c:2653–2664` | 每 100 tick 的客观块调用回电，然后渐进鉴定 | 沿用 P2 既有 `advancementLoop → objectiveTimeBlock → tickArcanaResources` |
| `Items.c:4720–4740, 7904` | 卷轴 `rechargeItems(STAFF | CHARM)`，全包范围 | `rechargeStaffsAndCharms`，移除随机挑一件和 WAND 范围 |

每个客观块，缺电杖减去智慧增量。到期时 `charges + 1`（不超容量），再加上 `randClumpedRange(max(floor(D/3),1), floor(5D/3),3)`；保留超出的进度，不把计时归零。高智慧一块可回多次；到满电后仍完成本次负倒计时的全部抽签，不能提前 break 改 RNG 足迹。完整正周期满电时停止扣进度，不积攒空闲时间。

保留 CE 对过长倒计时的归一化循环：`remaining > floor(5D/3)` 时扣一当前次数并减 D（无 RNG、无 E/容量写入）。它可在极高 E 或 E 改变后生效；新增 E20/初始500→当前20→19、timer250 的边界守卫。W-7 的主动附魔入口/进度调整尚未实现。

锚点：E2/E3/E8 的 D 为 2500/1666/625；E3 随机间隔 555…2776、clump=3。无智慧增量10，普通初始500意味着首次缺电后50个客观块；后续才是随机周期。智慧+1增量为 **12**（定点舍入），+2为16，-1为7，-10为0，+27及以上为11925，不能用浮点 `1.3 ** E` 替代。

未知正智慧戒指采用当前 web 可表达的 `min(E,1)`；已鉴定用 E，负值完整生效。CE 的 `timesEnchanted + 1` 中 web 尚无戒指附魔次数，现有附魔入口也不能附魔戒指；没有借此新增戒指生成/附魔系统。既有戒指初始 E 仍未修改。

## 2. 与 W-5 ArcanaInstance 的接口

- **读** `enchantment` 算周期，读 `maxCharges` 限制当前次数，读当前 `charges` 判断缺电。
- **写** `charges` 与独立 `staffRechargeRemaining`，绝不把次数或计时写进 E/容量。
- `ArcanaInstance.ts`、`ItemLoader.ts` 未修改；初始 staff E/次数抽签、wand range 抽签、W-5 版本标记和确定性迁移原样保留。旧 `rechargeTurns/rechargeCounter` 仍可存读，但不再驱动回电。
- 新守卫覆盖 E3实际施法与回电、E8/容量2的刻意分离、满电暂停、未知实例旗标；W-5 全文件复跑。
- 已带版本但 E=0 的档仍保留 E=0；自然回电跳过，避免除零或偷偷从容量重建 E。超过正常范围的周期最小保护为1。

## 3. 不按玩家动作数回电

没有新增行动出口回电调用，也没有搬动 P2 调度。`tickArcanaResources` 的生产调用者仍只有 `objectiveTimeBlock`。

新增真实 `handlePlayerAction('wait')` 测试：四次 haste（4×50 tick）、两次普通（2×100）、一次 slowed（1×200）均只推进两个客观块。首个 haste 动作不扣回电倒计时；在同一20点缺电夹具中，三种动作组合均只回一次且下一计时1000，抽签也都一次。背包外的地面杖不回电，CHARM 仍每客观块冷却减1；智慧不加速护符。

## 4. 充能卷轴：STAFF / CHARM 范围

真实 `readItem` 接 `rechargeStaffsAndCharms`，不随机筛选一件：所有 STAFF 充满到已存容量，并将计时重置为 D（满电杖也重置）；所有 CHARM 的 `cooldownRemaining=0`；WAND、戒指、地面物品不变。没有合资格类别时照常消耗卷轴/时间，给出没有法杖或护符的文案。护符-only 背包也有效。

护符仍使用原有 `cooldownTurns/cooldownRemaining`，自然冷却与使用入口未重写；没有迁移为 CE 的 charges 倒计时、没有改变持续时间、能力、生成或附魔公式。本轮只把卷轴“恢复可用”映射为现有模型的 cooldownRemaining=0。

回电/卷轴日志使用 `displayName` 保留未知态；日志在 Vue 以文本节点展示，局部关闭 i18next 插值的 HTML 转义，避免 `[2/3]` 显示为 `[2&#x2F;3]`。详情不再宣称 WAND 可自然回电或 STAFF 固定每N动作回电，也不以数字周期泄露未知 E。智慧戒指和卷轴 JSON 仅修改对应中文描述。

## 5. blink / obstruction 预留

`staffRechargeBaseDuration(identityId)` 为单独扩展口，目前**所有 id 均返回普通5000**。注释定位 CE 的10000及未来初始timer/卷轴reset需一起接线。对显式 blink/obstruction 测试 id 仍返回普通周期，Loader 仍返回 null。没有新增种类、没有启用慢一倍周期、没有实现位移/力场效果。

## 6. 存档与旧档兜底

`GameSnapshotItem.staffRechargeRemaining` 是可选新字段，背包和地面物品共用 serializer/deserializer。新档保存确切剩余点数；0或负值也保留以免丢失已到期进度。缺字段（含 pre-W-5、W-5 档）确定性回落500；非有限值同样回落，绝不从旧递增 counter 换算。旧 counter/turns 原样保留往返，且不抽 RNG、不调用 spawn。W-5 的 E/容量迁移先执行，新计时只处理自己的字段。

新测试揭示 P2 客观门原本未存档，保存于 haste 半块（还剩50 tick）会丢失回电相位。本轮在同一 Game 快照加 `ticksTillUpdateEnvironment?: number`，新档精确往返，旧档缺键回落100，避免依赖读档前的陈局值。验证存档前/后的下一客观块都在补足50 tick后触发。

范围说明：计时迁移 helper 的零 RNG 守卫覆盖 `randRange/randClumpedRange/spawnStaff` 禁调用与完整 RNG 对象不变。**没有声称整局 loadSnapshot 零 RNG**：其既有种子重置/风味初始化未改，也没有扩张为完整 RNG 状态存档。续接测试固定同一后续骰以验证计时和客观门，不冒充完整随机流存读档重放修复。
