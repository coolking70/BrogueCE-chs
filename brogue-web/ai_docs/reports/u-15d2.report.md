# U15d-2 护甲符文效果 CE 化

规格基准：`x-0-survey.report.md` §4.3 U15d、§3.1 K24；事实基准为本工作树 `BrogueCE-master`。本轮只修改效果、提示与测试；`ItemLoader.ARMOR_RUNIC_BY_CE_INDEX` 的缺位仍为 `null`，没有移动生成流或改动 `test:drift`。

## 生产改动

- `Game.tryTriggerArmorRunic` 增加 CE 的 `melee` 入参：`multiplicity` 与 `reprisal` 仅在近战执行；`mutuality`、`absorption`、`immunity`、`burden`、`vulnerability`、`immolation` 在 CE 的近战和投掷命中均执行（Combat.c:1272；Items.c:6822）。现有远程法术不经这条投掷武器入口。web 尚无怪物向玩家投掷武器的运行时出口，因此该差别由显式 `melee=false` 的合同测试验证。
- 补 `multiplicity`：33% 掷骰、`armorImageCount=clamp(trunc(netEnchant/3),1,5)`；克隆攻击者作为 1 HP、零防御、3 回合寿命的玩家谱影，沿用现有克隆/寿命/消魔链。补 `burden` 力量需求递增、`vulnerability` 双倍伤害、`immolation` 的 CE 火焰 DF（100 起始概率、每波减 45、黄色闪光）。火焰 DF 仅在效果侧定义，保持现有封闭生成目录集合；初次加入目录使 C-4b/U08/U17a 四条历史数量/闭包守卫翻红，撤回该前提后复跑均绿。
- `immunity` 改为 `monsterIsInClass(attacker.typeId, armor.vorpalEnemy)` 类别门，复用 U15d-1 物种表；`respiration`、`dampening` 不再在普通受击时掷骰和施加自创效果，保留现有气体和爆炸消费者。`reprisal` 仅在攻击者可见时揭示。
- 修正详情文字、增加本轮消息翻译；废弃的普通受击消息键归档到 `zh_CN.legacy.json`。U01 的 `runicType/runicKnown/vorpalEnemy/strengthRequired` 快照字段已存在，无新增存档字段，不做旧档迁移。

### 旧守卫与 CE 冲突

`armor_runic_effect.test.ts` 的四处旧断言不改：它用攻击者与玩家的距离推断 `melee`，并认定任意类别均可触发 `immunity`。反事实是 CE `applyArmorRunicEffect` 的 `melee` 来自调用方实参，Combat.c:1272 为 `true`、Items.c:6822 为 `false`；该入参仅约束 multiplicity/reprisal。CE Combat.c:1058–1063 的免疫则明确要求 `monsterIsInClass`。因此旧文件的 absorption/mutuality 远距零效果断言和 immunity 无类别全免断言不应作为 CE 黄金值。reprisal 的直接 helper 测试没有传 `melee=false`，也把距离当成 CE 入参。新 `u_15d2_armor_runic.test.ts` 显式验证投掷参数和类别门；验收方可据此裁决旧守卫的前提。

`w_15_shielding.test.ts:233–239` 的 `immunity` 用例通过 helper 建护甲，但未设置 `vorpalEnemy`，却预期免掉 rat 的攻击并保留全部护盾。这与 CE 类别门冲突，生产代码没有为缺失类别的合成物件伪造免疫；该断言仍红，待验收方修订夹具前提。其余三种护甲符文的护盾顺序用例通过。
