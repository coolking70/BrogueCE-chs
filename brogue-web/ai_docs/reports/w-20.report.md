## 1. CE 执行链与本轮实现

依据本仓库 `BrogueCE-master/src/brogue/` 的真实执行代码：

- `Items.c:5374–5388 BE_PLENTY`：拒绝 `MONST_INANIMATE | MONST_INVULNERABLE`，调用 `cloneMonster(monst,true,true)`；成功后双方分别执行 `(currentHP+1)/2`，autoID=true，**不要求可见**。
- `Monsters.c:568–648 cloneMonster`：先 `generateMonster(id,false,false)`，再 `*newMonst=*monst`；不是从目录重造能力。`false,false` 是不配携物、不抽突变，不表示初始化完全不耗 RNG。
- 整体复制后：清 carriedMonster；initializeGender；清 `MB_LEADER | MB_CAPTIVE | MB_WEAPON_AUTO_ID`，置 `MB_FOLLOWER`；清 mapToMe/safetyMap/carriedItem；处理携带生物递归；等待**赋值101**；非盟友清 `MB_TELEPATHICALLY_REVEALED`；按源 leader 决定跟随关系；源是俘虏时 `becomeAllyWith`；选位；玩家克隆改灰色、1–2伤害/clump1、防御0、名clone、ALLY。
- `Combat.c:285–324 splitMonster`：先减半源 HP，调用同一个 `cloneMonster(...false,false)`，再执行**自分裂独有**的学习能力剥离，最后放到群外缘选中的位置。

web 的 `Monster.copyForClone()` 先复制所有实例自有字段（包括私有 TS 速度字段和 W-19 缓存速度），再逐项断开容器、处理 CE 例外。保留 Monster 原型，因此克隆继续走正常状态、AI、伤害、死亡方法。`Game.cloneMonster` 是公共放置/关系入口；PLENTY 和 P4-4 都调用它。不会调用 polymorph、summonMinionsFor、populate/generateDepth，也不在落地时额外结算环境伤害。

CE 指针型缓存 mapToMe 在 web 无字段；safetyMap 对应 safetySnapshot，清空。web 没有独立性别字段、MB_LEADER/MB_FOLLOWER 位、MB_TELEPATHICALLY_REVEALED 位；leader 关系由引用表示，旗标集合中若同时有 MALE/FEMALE 则按 initializeGender 消去一个。**没有拿 telepathy 状态冒充“被心灵感应揭示”位并错误清除**。

## 2. 可变容器逐项审计与反向验证

`Monster` 连同 `Creature` 当前没有 Map 字段。审计不是只搜索 Map/Set 关键字：新测试构造完整实体，动态枚举所有非空对象值自有字段，与15项显式名单严格比较；新增未审计对象字段会直接打红。

| `spawnLoc` | 新 `{x,y}`，保留源值 | 改两个坐标，源不变 |
| `statusDurations` | 独立普通对象，包含 burning 扩展键 | 改全键；另实际 tick/加毒/吸盾，源完整快照不变 |

| `behaviorFlags` | 新 Set | clear，源不变 |
| `abilityFlags` | 新 Set | clear，源不变 |
| `bolts` | 新数组（元素 string） | 改首项，源不变 |
| `waypointAlreadyVisited` | null 或新 boolean 数组 | 改首项，源不变 |
| `mutation` | undefined 或 structuredClone 整个对象 | 名称和下列四数组同时修改，源不变 |

## 3. id、关系、携物、死亡

- 每次复制分配新 `allocateEntityId()`。不把源 id 留下来，也不用 RNG 造 id。位置查询失败先返回，既不分配 id 也不改 HP/列表。
- 源有怪物 leader 时保持**同一个 leader 引用**，不复制整个生物图。无 leader 的敌方源成为新体 leader；源原来的随从仍指源。
- 项目已有约定“isAlly=true 且 leader=null”表示 CE `&player`。这种源的克隆仍保留 null，**不会误绑定到原盟友**。源有明确怪物 leader 的盟友仍保持该引用。玩家反射克隆也采用同一约定。
- `carriedItem=null`。web 在死亡时才掷金钱/物品概率，这相当于尚未兑现的携物权益，因此克隆的 `goldDropChance/itemDropChance` 也归零。源持有的钥匙等仍在源身上；克隆死亡不凭空制造掉落。以后实际得到的携物仍走普通死亡掉落。
- `carriedMonster=null` 是当前 CE 的**执行结果**：MC:574先清，:583–588虽递归生成并摘链，却从未把结果赋回新体。编译探针输出 `carried 1 2 1`（新体字段NULL、分配两体、递归体被摘链）。web 不创建这一无法到达的泄漏对象，不凭注释“Also clone”创造寄宿载荷；源携带生物不变。
- clone 的 `isClone` 标记兑现 CE 清 MB_WEAPON_AUTO_ID：真实玩家近战击杀克隆不推进武器熟悉度；击杀源正常推进。该标签不是阵营/状态/寿命。
- 克隆 hp/死亡旗标是独立值；它受毒、盾、燃烧、死亡DF、清扫的正常链管理。bloat 克隆死亡只触发一次DF，源死亡闸不变；再杀源独立触发。没有共享死亡状态，也没有绕过 P1-24 另建删除通道。

## 4. 奇数 HP 与三个特例

**HP：**C 整数除法的 `(HP+1)/2` 等价正整数 `floor((HP+1)/2)`，不是 floor(HP/2)，也不是把奇数余数只分配给一方。1→1+1，5→3+3，99→50+50；maxHP 不变。PLENTY 是复制后分别减半；自分裂是先改源再复制。通用 helper 自身不减半。

`w20-ce-golden.mjs` 从 CE 原文件截取完整 cloneMonster、initializeGender 和 BE_PLENTY 分支，clang 编译后输出 HP=1..137 的黄金值及玩家/携带/俘虏例。分配、地图、UI 用桩隔离，**不是全 CE 游戏/RNG 差分**。新测试逐行走 web 真正 zap 出口对比137组结果。

**反射玩家：**既有 W-4 射线路径反射回玩家，PLENTY 接触玩家后克隆，玩家和新体当前 HP 向上取半。新体是 Monster，`@`、灰色基础色、1d2、防御0、盟友；保留当前 HP/maxHP、毒/盾/全部共用状态、速度/抓取状态。Player 的 inventory/equippedWeapon/equippedArmor/rings/temporaryImmunities 管理器不是 CE creature 载荷，不复制其物品引用。已有 statusImmunities Set 独立复制。玩家的 fractional regenCarry 换算到 web Monster 再生计数，保留当前进度；不克隆营养/输入/UI管理状态。运行时 `player_clone` 对应 CE monsterID=0，**不增 monsters.json 种类或生成池**；带克隆身份时允许后续 polymorph，JSON 后仍成立。盟友渲染沿用现有绿色显示，基础色仍是灰色。

**俘虏：**先清新体 captive，再依据**源的 captive**调用 `becomeAllyWith`（MC:599，Movement.c:728–743）。仅新体转盟友、leader转玩家、清 seized；seizing 和 discordant 仍保留，未套用 domination 的清discord分支。源仍是俘虏，原钥匙不掉落、不复制。

**无落点：**不是仅检查8邻格。`getQualifyingPathLocNear`（Grid.c:287–360）先搜最近可达合格位置，玩家阻路径、怪物/楼梯仅禁落点；无路径解后调用忽略路径的近邻环兜底，能跨墙找到另一间房。地形按 `avoidedFlagsForMonster(info)`（MC:650–693），不按临时悬浮状态。web 对应 `cloneLocation`：八向距离、对角墙角、x-major同距候选随机、fallback环；休眠怪不占活跃落点。

全图均不合格时，CE 返回 INVALID_POS；**cloneMonster 没检查坐标，仍写 pmapAt、返回非NULL**，BE_PLENTY 的 `if(newMonst)` 不能证明失败安全。本轮防御性修正：先查询落点，失败 return null；不扣HP、不autoID、不分配ID、不留幽灵实体、不掷候选随机数。该病理地图行为是明确的安全扩展，不把 CE 越界路径描述成“本来就安全失败”。

## 6. 召唤、计数与 RNG 边界

- clone 不调用召唤，也不改 P4-2 函数。CE 计数计算当前关系/种类，**没有“出生方式”排除克隆**：一个克隆恰为召唤者直接随从时，敌方 countMinions 应增加；盟友仍统计所有盟友（含自己）。这不是被误记为一次召唤。
- alliedCloneCount 按相同物种、同队、且排除自己；已经有100个其他同队体时 self-split 停止。PLENTY 本身**没有这个上限**，仍可成功，其新体会参与后续自分裂计数。测试在100个其他体时验证此边界。
- 本轮没有改变新局/直接下层的生成入口、目录/频率/蓝图或 RNG 模块。所有新增抽签都在操作路径。copyForClone 不调用旧目录构造器，不再消费原 web 自分裂的随机初始睡眠；CE generateMonster 还会做随机睡眠、40次waypoint初始化等随后被覆盖的抽签。web 当前已有不同的初始化与惰性waypoint模型，本轮**不声称交互RNG逐抽与CE一致**，也不声称战斗后下层与旧web重放相同；W-0的“生成流否”口径是原始生成门禁。

## 7. 持久化与旧档

- 现有 form/status/poison/shield/regenCounter/allegiance 保存继续使用。新增可选 `cloneState` 保存当前速度、101等待、抓取/绑定标记、地图/访问/出生记账、死亡闸等实际运行值，并明确记录是否 polymorphed；没有把“克隆”伪装成“已变形”。读取时独立构造各值容器；leader在active+dormant两表建完后按id恢复。
- 新增普通可选 `mutation` 快照：此前只保存效果数值而丢失来源，读档后无法区分后天学习和突变旗标，会使新自分裂规则错误剥离。保留突变来源但不再次 mutate/乘数值；克隆与源都深拷贝该字段。
- 休眠、当前层JSON、测试房baseline/重建入口包含这些标签。读档预留最大id现在包含**全部**休眠怪（原来只含polymorph休眠怪）、活动怪、地面/背包物品及已保存携物；新分配id在最大值之上。900000和1200000高id往返后再克隆/创建，含玩家都唯一。
- 旧档无 cloneState → isClone=false；不凭名字/字形猜测克隆，不凭空把旧怪变盟友。旧档无mutation不猜来源，不把目录重新套乘。旧档缺旧形态字段的W-19兼容仍保留。
- 原项目只JSON保存当前层，不保存完整levels缓存；CE完整寄宿/复活生命周期、毫回合再生/复制玩家后的C单位差异、跨层召唤/分裂计数仍是既有模型边界。本轮保证现有web状态独立与上述明列行为，不冒充全怪物系统已逐字段模拟CE。
