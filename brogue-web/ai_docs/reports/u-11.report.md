## 3. 死亡只分配一次，不等于全局只学一次

`deathEffectTriggered` 继续只管死亡 DF。新增持久字段 `Monster.deathProcessed`（默认false，登记 U01 MONSTER_FIELDS）覆盖所有普通死亡。先置位再释放/分配；失败抽签、无人合格、之后放弃也不会在另一个清扫入口重抽。没有新增 Game 全局集合，无跨局忘清/代理对象身份问题。处理过的死怪经 JSON 往返再次清扫不分配。

- 玩家真实近战输入、盟友攻击、毒和燃烧致死均验到分配；再重复两次清扫，零抽签、任务不变。
- 同一坐标先后两具可学尸体可给不同盟友任务；不按坐标去重。
- bloat 的毒气 DF 先发生，尸体格因此成为回避地形时不能分配。该用例阻止把学习放到 DF 之前。
- 宿主释放携带怪，200 tick等待、原格安置，再落格效果；释放者能参加宿主分配。乘客被熔岩杀死时，其 FIRE 尸体先分配，宿主随后发现学员已忙，不覆盖成宿主的虚弱能力。
- 休眠者不进入分配；召唤撤离、测试房清场、变形丢弃携带图等行政摘除路径不进入普通死亡清扫。没有将休眠/消失解释为击杀。
- CE cloneMonster 是整结构复制，后续清位没有清 ABSORBING；未引入全局恰一次消费 token。早期离开后及时返回的克隆和原体可各自完成同一位置任务，这是 CE 可观察结果，专项明确验到两者各扣自己的额度。

web 仍沿用原来回合首/尾收集死亡的架构；本轮不是全项目即时 `killCreature` 事件化。多名同时死亡的全局事件次序、掉物安置近似和一般领导继任仍属死亡子系统边界，不能据此次一次性守卫宣称整个死亡链逐指令等价。

## 6. RNG与生成硬约束

分配抽签只有一个生产调用者：Game普通死亡处理。生成/读档/显示/吸收完成没有学习抽签。候选为0时零调用；两遍找不到人时只有抽盟友的一次；选中后两级最多两次randRange。单盟友+单能力虽调用两次，但退化区间不推进随机状态；两个非退化区间实测计数增加2。距离图、倒数、安装和永久同步零学习RNG。

走尸体的非等轴被动移动会按CE额外掷轴向偏好骰；学会后的施法和移动继续使用既有RNG。不能把“学习抽签只在死亡”误写为“整个学习链只有死亡耗随机”。共享SUBSTANTIVE流会因此影响后续交互和未来楼层；尚未进行U02分流/整局RNG恢复。

不改任何生成候选、频率、物种目录或锁文件。新物种动词表仅消息消费者读取。原基线SHA-256由边界审计和最终输入清单双重锁定；本轮`test:drift`独立执行，不重采。
