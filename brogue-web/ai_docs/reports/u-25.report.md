# U25：机器产物追踪与性能观察

规格依据：X-0 勘察报告 §3.1 K33 与 §4.3 U25；本轮只新增观测与报告工具。

## 实现

- 新增默认关闭的 `setMachineObservationHook`。蓝图事务只在挂钩开启时建立 feature 请求、落格、迭代次数与回滚记录；不调用 RNG。成功机器在 `Game.populateLevel` 实化后补上最终物品/怪物实例 id、位置与持有者。延迟物品保留原始机器号与 feature 序号，领养落点另记接收 feature。地形和 DF 同样按 feature 记录。
- `BP_MAXIMIZE_INTERIOR` / `BP_OPEN_INTERIOR` 记录扩张扫描轮数与新增格数；`MF_REPEAT_UNTIL_NO_PROGRESS` 记录每个 feature 的轮数。失败事务记录失败原因，不作为最终机器产物。
- `node scripts/u25-machine-inventory.mjs SEED DEPTH [OUTPUT_PREFIX] [INSTANCE_ID]` 输出 JSON 与可读文本；也可用 `SEED DEPTH --id INSTANCE_ID` 直接查询。JSON 的 `products` / `matches` 可按实例 id 回到机器和 feature；外包产物另有 `sourceMachineNumber`、`sourceFeatureIndex`。实测物品 `#38` 是 seed 424242 / D3 的 CE1 机器 feature `#2` 所产 [JSON](u-25-sample.json)、[文本](u-25-sample.txt)；怪物 `#202` 是同 seed / D11 的 CE14 机器 feature `#5` 所产 [JSON](u-25-monster-sample.json)、[文本](u-25-monster-sample.txt)。

## 一致性

独立守卫 `u25_machine_observation.test.ts` 对 drift 的 4 seed × D1–26，在关/开钩子下逐层比较地形指纹、怪物数、物种集合、物品数和 `rng.getState()` 的两个完整流、当前流及调用计数。通过。原 `test:drift` 未修改，单独复跑通过。关闭钩子时不建立追踪记录；生产路径只作空值判断。

## 串行性能数据

Windows 本机、seed 424242，串行独立进程/单 worker；数值为 wall time。计时脚本只包裹调用并读取时钟，不改变生成算法。慢测前三次之后收紧了关闭钩子时的对象字段，最终代码又单独复跑一次。

| 工作量 | 第 1 次 | 第 2 次 | 第 3 次 | 最终复跑 | 结果 |
|---|---:|---:|---:|---:|---|
| 完整 generation D1–26，`u25-perf.mjs`，最终代码 | 1.844 s | 1.834 s | 1.763 s | — | 26 层均完成 |
| `blueprint_center.test.ts`，44 seed × D1–26 | 301.98 s | 300.50 s | 292.09 s | 291.63 s | 每次 6/6 通过 |

三次 generation 的累计热点（`selfMs`，非互斥函数的总墙钟相加；占比仅在各自调用树内解释）：

| 函数 | 第 1 次 | 第 2 次 | 第 3 次 | 调用数 |
|---|---:|---:|---:|---:|
| `Game.generateDepth` 本体，不含下列包装的子函数 | 818 ms | 812 ms | 775 ms | 26 |
| `Architect.generateLevel` 本体 | 611 ms | 611 ms | 604 ms | 26 |
| `BlueprintEngine.applyBlueprint` 本体 | 162 ms | 157 ms | 155 ms | 76 |

| `BlueprintEngine.findFeaturePosition` | 62 ms | 67 ms | 61 ms | 879 |

`blueprint_center` 的第一轮 worker 约 268 秒 CPU / 302 秒 wall，说明隔离条件下确有约五分钟计算量。历史全量并行门禁中的 900 秒超时不能据此认定为当前生成回归；同一文件本机四次均在 302 秒内完成。历史门禁同时跑多项大样本测试，CPU 争抢足以把约五分钟的单文件任务拖过 900 秒，但本轮未重现对应的全量超时，因此这是基于负载规模的解释，不是对历史每条失败的因果证明。当前全量默认套件曾启动，因未及时给出可归因结果而停止；最终门禁状态以本报告下列定向闭包和 drift 为准。

最后的生产改动让关闭钩子时不向延期指令和 `MachineResult` 附加追踪键，也不创建物品记录或回滚函数；其后复跑了 build、独立开关等价守卫、drift，并重测三次 generation。`blueprint_center` 最终单测在函数创建调整前、对象字段收紧后通过；30 文件闭包是在对象字段收紧期间运行，额外 23 个源码守卫在该收紧后运行。未把这些交错执行写成一次完整默认套件通过。

本轮仅报告热点，不优化生成与测试。没有重采基线、修改守卫阈值或提交 git。
