# U20 物品堆叠与背包容量报告

## 规格核对

以 `x-0-survey.report.md` §3.1 K36、§4.3 U20 与本树 CE `src/brogue/Items.c` 为准。CE `numberOfItemsInPack`（:1023）将武器堆计为 1，食物、药水、卷轴按 `quantity` 计数。`pickUpItemAt`（:867）在已满时只放行金币或 `itemWillStackWithPack`；后者（:806）对非零 `quiverNumber` 只比较编号，实际 `addItemToPack`（:983）才按类别、种类、编号合并。因此同编号异种武器在极少数碰撞时甚至能令背包超过 26。食物、药水、卷轴虽然同种合堆，满包时仍不能拾取；这与任务书“满包收可堆叠物”的概括不同。CE 宝石按 `originDepth` 合堆，但当前 Web `ItemCategory` 尚无宝石，此分支没有可接入的生产实例。

CE 合并不以诅咒、附魔或鉴定状态作等价条件；`conflateItemCharacteristics`（:939）传播指定已知标志、取较高附魔与较低力量要求。金币直接增加账面数且不入包（:875–888）。`throwCommand`（:7146–7165）每次从堆里分一件；`dropItem`（:8463）对非武器多件堆分一件，对武器整堆丢出。没有新增重量或负重惩罚。

## 实施

- `Inventory` 按 CE 的物品数计算 26 上限；同种食物、药水、卷轴合堆，武器仅同种同箭袋编号合堆；保留满包箭袋编号预检的 CE 次序。背包字母首次入包时分配、移除后不重排，空出的字母可复用。
- 金币拾取仅记账。喝药、读卷轴、吃食物从合堆消耗一件。丢弃非武器合堆时复制一件并分配新实体 ID；投掷原有分件路径加了背包成员校验。背包界面展示真实字母和数量。
- `inventoryLetter` 纳入整局快照；堆叠数量及分件 ID 随现有 U03 快照机制往返。旧档中已存在的重复条目不主动合并，避免擅自改写旧档对象引用；X-0 对旧档合并策略标为待确认。

## 反查与反事实

反查了 `snapshotQuantity`、`startingKit`、`b_2_throwing`、`i_1_interaction`，以及 `p1_30_i18n_gate`、`u24_hardcoded_text` 和读取源码的守卫。新增 `u20_inventory.test.ts` 验证满包、箭袋碰撞、合堆标志、字母复用、分丢与存读档。

全量测试中 5 条旧断言与 CE 行为冲突，未修改这些守卫：

| 测试 | 旧前提的反事实 | CE / 当前行为 |
| --- | --- | --- |
| `b_1b_identification_persistence` :327 | 两张同种卷轴仍是两个背包对象 | 同种卷轴合堆；读一张后原堆对象数量减一 |
| `hunger_regen` :176、:188；`p2_3_objective_time` :271 | 新加入的同种口粮对象仍是独立背包项，可直接传给 `eatItem` | 开局口粮吸收它；实际交互应传背包里的合堆对象 |
| `b_4b_item_placement` :341 | 拾取的金币在背包数组内 | CE 金币只进入账面，背包没有金币项 |

反事实由 CE 上述源码、对应测试的构造与断言，以及新增 U20 用例共同确定。依任务书“守卫靠旧规则才绿时先反事实证明、只修前提、交验收方裁决”，这些旧断言保留供验收方裁决；全量门禁不能声明为绿。
