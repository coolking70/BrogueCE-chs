### 47 号 `key_sacrifice_altar`：结构性退化（登记，不是缺陷修复）

**退化后的形态**：47 号**当前完全不会被生成**（下称"退池留形"，D2 口径）。
它的房间、祭坛、铁笼、恶魔雕像数据照 CE 原表全部保留（`v_2b_7_features` G1 钉死旗标不许删），
只是不再被抽为**领养机器**。

**退化原因（本轮实测发现）**：47 号的领养 feature 是 `SACRIFICE_CAGE_DORMANT`（CE :319），
它带 `T_OBSTRUCTS_PASSABILITY`。CE 的领养物品用 `placeItemAt(theItem, {featX,featY})`
**无条件**放在 feature 落格（Architect.c:1531 → Items.c:422-434），之后**铁笼会升起**
（献祭机制 `TM_PROMOTES_ON_SACRIFICE_ENTRY` → `MB_MARKED_FOR_SACRIFICE`），钥匙随后可取。
web 没有献祭机制（任务书 §2.2 明示本轮不实现），铁笼恒锁；而 web 的
`Game.populateLevel` 有一个 P1-43 兜底闸——`isPathingBlocker(terrain)` 的落点物品会被**丢弃**。
两者相遇 ⇒ **父机器交出的钥匙凭空消失**。

**实证（两个复现 seed，均在修复前）**：

- `seed3/D7`：Kennel（10 号）的 cage_key 被 47 号领养 → 丢 → `v_2b_6_keys` F2 红
  （"Kennel 机器 1 无 cage key"）。
- `seed777/D23`：`vestibule_locked`（16 号）的门钥匙被 47 号领养 → 丢 →
  `v_2b_6_keys` F1 红（"锁 (51,3) 无匹配钥匙"）。

**处置**：在 `buildAMachine` 的领养候选过滤里补一条**同类数据不变量**（与 V-2b-6 那条
"候选必须有 `MF_ADOPT_ITEM` feature"同址同性质）：

> 领养 feature 的落点必须**接得住物品**——带 terrain 的，其地形不得是 pathing blocker。

判据是数据驱动的（不是硬编码 id）：实测该过滤在**全库只排除 47 号一条**
（`v_2b_7_features` G2 全等钉死 `['key_sacrifice_altar']`，并断言它在 14 seed × D1-26 里出现 0 次）。
献祭机制落地的那一轮，摘掉这条过滤即可（代码注释里写了这句话）。

**引擎零消费的旗标照带**：`MF_ADOPT_ITEM` / `MF_IMPREGNABLE` / `MF_NOT_IN_HALLWAY` 一条没删
（`MF_KEY_DISPOSABLE` 在 V-2a 有先例）。

## 4. §1.4：那条空转四轮的断言，恢复后的形态与它能抓什么

### 4.1 病灶与修法

`MachineResult` 此前只有 `itemSpawns` / `monsterSpawns`。CE `Architect.c:1484-1486`
（"Mark the feature location as part of the machine, **in case it is not already inside of it**"）
对**一切**成功落位的 feature 打机器标记，而地形类/纯 DF 类 feature（`MF_BUILD_IN_WALLS` 的墙火把、
`MF_EVERYWHERE` 的铺装、DF 列……）合法地落在 interior 之外并带上 `machineNumber`。
于是 `p1_37` AD3 里那条

```ts
for (const k of gridDerived) if (!unionKeys.has(k)) expect(spawnKeys.has(k)).toBe(true);
```

要么**空转**（A−B 恰为 ∅ 时循环体一次都不执行）、要么**必然假红**（格子是 feature 落点，
但机器没有暴露落点记录）。V-2b-3 起连续四轮登记，本轮落地：

- 新增 `MachineResult.featureSpawns: Array<{ pos; terrain?; featureDF?; featureIndex }>`；
- **记录点与 BlueprintEngine 里写 `machineNumber` 的那一行同址**（同一 `if (terrainSucceeded)` 块内），
  所以"网格上的机器格"与"机器自报的落点"同源——这正是这条断言缺的那半；
- `p1_37` AD3 的 `spawnKeys` 并入 `featureSpawns`，并补一条**非空性哨兵**：

```ts
expect(levelResults.reduce((n, mr) => n + mr.featureSpawns.length, 0),
    '机器没有记录任何 feature 落点——A−B 逐格断言会退化为空转（记录点脱钩？）').toBeGreaterThan(0);
```

### 4.2 恢复后的形态（不再是空转）

本轮 RNG 流位移后，`seed424242/D3` 的 **A−B 非空**（六格），逐格断言**真的执行**了：

```

           reward_single_category_library#4 vestibule_locked#5 key_secret_room#8
A−B      = ['10,13','11,21','13,2','31,21','32,23','36,27']   （machineNumber 属 #1/#1/#3/#4/#4/#4）
featureSpawns 计数 = 57, 1, 157, 59, 1, 2
```

六格**全部命中对应机器的 featureSpawns**（其中 #3 就是本轮新落的 42 号 `key_burning_grass`，
它的 157 条落点里包含 `MF_BUILD_IN_WALLS` 的 `PILOT_LIGHT_DORMANT` 与 `MF_EVERYWHERE` 的草铺装）。
pin 从 `[]` 顺延为这六格的**全等**数组（不是长度/包含比较）。

### 4.3 它现在能抓什么（对抗性要求 §6② 的直接回答）

| 实现缺陷 | 现象 |
|---|---|
| `featureSpawns` 记录点被挪进 `if (feature.terrain)`（漏掉纯 DF feature） | A−B 里由 DF 落点造成的格变成"无来源" → 逐格断言红 |

| 整个记录被删（字段/记录点退回 V-2b-6 形态） | 非空性哨兵红（"机器没有记录任何 feature 落点"），不需要等 A−B 恰好非空的层 |

## 6. §3 三股基线成因的分离（受控单变量）

判据：`generation_baseline`（4 seed × D1-D26，fp/n/species/items 四字段）。

| 实验 | 配置 | 偏离处数 |
|---|---|---|
| 基线 | V-2b-6 的 fixture（§3 前） | — |
| **B** | **本轮全量** | **381** |
| **A** | HEAD 蓝图池（48 条）+ **本轮引擎** | **353** |
| C | 本轮全量，但 `CE_CHOKE_COUNT_CAP` 临时改回 41 | 376 |
| E | 本轮全量，但领养过滤临时关闭 | 358 |
| **D** | 本轮全量，但**摘除 `featureSpawns` 的记录** | **0（逐位一致）** |

**能说的**：

1. **③`MachineResult` 扩字段 = 0** ✔（任务书要求"若它不改变生成流，应当为 0"）。
   D 实验是硬证据：只摘掉记录、其余一字不改 ⇒ `generation_baseline` **保持绿**，
   即字段与其记录点是**纯回声**、不消耗任何 RNG。
2. **①蓝图池入池**的贡献 ≥ 28（B − A）。
3. **⑤领养过滤**与**④CAP 上调**各自单独生效时偏离分别为 23 / 5（B − E / B − C）。

**分不开的部分（如实说）**：B/A/C/E 四个数全部落在 353–381 的窄带里，
而这套口径总共只有 4 seed × 26 层 × 4 字段 = 416 个可比字段——
**流一旦在首台机器抽签处错位，其后每个格子的指纹、怪物数、物种串、物品数几乎全部不同，
计数直接饱和（381/416 ≈ 92%）**。饱和之后"少 5 处""少 23 处"是错位位置的偶然差异，
**不是各股成因的幅度**。因此：

- 本报告**只对 ③ 给出"= 0"的结论**（D 实验是逐位一致的强证据）；
- ①②④⑤ 相对彼此的**幅度不可用该计数分离**——受控单变量在"流已整体错位"的前提下失效。
  这与 V-2b-6 §5 的处境相同（当时也是把同源改动归入"在流位移意义下分不开"）。

**重捕获**：`fixtures/generation_baseline.json` 按同口径重采（键序与 seeds 序保持不变），
`note` 记录了四条成因；重采后 `generation_baseline` 单测绿。
