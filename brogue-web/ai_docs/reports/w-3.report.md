## 2. `hits` 的精确定义（W-1 交接）

已执行的 `BoltResult.hits` 现在是**射线实际到达格上、依次接触的存活非休眠生物及其接触位置快照**，可包含玩家，也可包含越过瞄准格后的多个生物。不会把被障碍挡住的指定目标写进 hits；不会把 HALTS_BEFORE 排除的下一格生物写进去；不会因自动候选不合资格就跳过实际碰撞。

它仍**不表示效果成功、HP 减少或最终伤害接收者**。免疫者、未实现效果的接触者，以及旧 P4 伤害反射近似中的反射者都可在 hits 里；后者的伤害可能转给 caster，但本轮不伪造折返 path/hits。`pos` 在施法前快照，beckoning/teleport 改位置后仍保留原接触坐标。

效果消费 hits，不再在落点重新查找一个可能休眠/刚出现的生物来替代接触者。逐格查询占位发生在上一格效果完成之后，因此可反映真实执行过程中的移动/生成。私人 `computeBoltResult` 和不带回调的 `traceBolt` 仍是纯预演：`outcome=null`，不点火、不掷骰；其预测接触不能冒充已执行效果。`applyBoltResult` 会重新执行并替换为实际路径、hits、landing 与 outcome。

`landingPos` 是最后到达格，空路径为 null；旧 `impactPos` 的 origin 兜底仍留在契约中，但空路径不会消费兜底来产生效果。
