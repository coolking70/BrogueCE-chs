## 3. 实现与接口

BlueprintEngine.fillAreaInterior 表示**一次**选址尝试，返回 null 是 tryAgain 的载体。buildAMachine 的区域分支独立管理 locationFailsafe 和外层 failsafe，只有 CE :1210 的固定输入失败才直接终止。BP_ROOM 不消费区域 blocking 复核，前厅的原硬失败语义保留。

距离图使用四层 T_PATHING_BLOCKER 与四向 Dijkstra；secret 层显形后的旗标按照 Monsters.c:1300 判读。Dijkstra.c:102 的 pdsSetDistance 即使起点自身阻挡也入队，但拒绝边框起点；web batchScan 只将正 cost 种子入队，因此对内区 origin 的 cost 单独设 1，边框不播种。随后按 roomSize 掷目标大小、依次洗牌 sCols/sRows、按 k<1000 的外壳次序收集；碰到三种占用之一即退出三重循环，并执行 blocking 复核。

web 的物品/怪物由 Game 稍后实化，没有格上的 HAS_ITEM/HAS_MONSTER 位。本轮在 BlueprintEngine 内记录生成期 pendingItems/pendingMonsters：随成功 feature 指令写入，父子递归可见；休眠怪不占 HAS_MONSTER，外包/携带物品不占地面；随整层备份回滚。这样即使 BP_NO_INTERIOR_FLAG 清掉机器标记，物品/活动怪的占用仍可被区域选址看到。

`randomMatchingLocation` 原签名为 `(grid, dungeonFoundation, liquidFoundation): Pos|null`，是 CE terrainType=-1 的子集，FLOOR/NOTHING 两个参数原本就能表达本轮的基座要求。必要扩展仅为可选 options：isOccupied 回调提供生成期指令占用；acceptLastAttempt 对应 CE 区域忽略 false 的特殊调用。原 autoGen 三参数调用不改语义、范围和 RNG 次数；500 次边界行为有独立对抗守卫。

interiorSatisfiesBlockingFlags 接到区域末端，TREAT 要求返回 0；REQUIRE 要求较小断开区域 >=100；else-if 优先级不变。方法及前厅头注将 9b 的“零活载体”登记明确标为过期：34/39 抽签及 58 强制 autoGen 都是真实消费者；65/66 仍为 CE 原始 freq=0。

有效边界登记：Game 延迟实化导致 horde 的额外随从位置、免伤静止怪的个体代价特判在生成期尚不可查询；本轮占用覆盖单怪指令与 horde 锚点，未前移整个怪群实化。未落地的 WALL_LEVER 显形 tile 继续按阻挡处理，不借区域扫描解锁缺失机制。前厅原 HAS_ITEM 中止仍未读 pendingItems（代码头注已从“无从触发”改为有效待补登记）；本轮不改前厅选址。以上不宣称与 CE 完整实体时序逐位一致。
