## 1. 字段映射与默认值

生产定义见 [Monster.ts](../../src/entities/Monster.ts)，快照登记见 [EntitySnapshot.ts](../../src/engine/Core/EntitySnapshot.ts)。所有字段属于 Monster 实例；不放入物种 `form`，不伪装为状态持续时间或 AI `state`。

| CE `creature`（Rogue.h） | web 字段/类型 | 默认值与语义 | 快照/克隆/变形 |
|---|---|---|---|
| `targetCorpseLoc` :2280 | 同名，`Pos \| null` | `null` 对应 `INVALID_POS`；位置指向当前层尸体格，不是实体引用 | MONSTER_FIELDS 深复制；克隆额外复制坐标对象；变形保留 |
| `targetCorpseName[30]` :2281 | 同名，`string` | `''`；保存已选尸体名字，不在读档时重新从目录推导 | 字符串值复制，变形保留；不模拟 C 缓冲区长度 |
| `absorptionFlags` :2282 | 同名，`string \| null` | `null` 对应 0；CE 选择单个位，web 保存对应的 `MA_*` / `MONST_*` 名称，与现有 Set 载体一致 | 原值保存；不在读档/克隆时安装进 Set |
| `absorbBehavior` :2283 | 同名，`boolean` | `false`；选择的 flag 是行为还是能力；bolt 非 NONE 时忽略此位 | 原值保存，包括暂时无效/残留的值 |

| `bookkeepingFlags & MB_ABSORBING` :2158 | `isAbsorbing: boolean` | `false`；独立进行态 | 原值保存；克隆保留；变形保留 |

CE `generateMonster` 的 `calloc`（Monsters.c:64）使名字、flag、boolean、bolt、counter 归零，`initializeMonster` :106/:124–125 显式清 bookkeeping、两计数和目标位置。web 类字段初始化对应这些默认值，不增加抽签。玩家的 CE 初始化是 RogueMain.c:363 `memset(&player)`，不调用 initializeMonster，因此 `copyPlayerForClone` 显式投影 `targetCorpseLoc={x:0,y:0}`，其余任务值仍为零/空；不能误称玩家克隆初值也为 INVALID_POS。U11 首次计数更新会使这个0计数目标失效。

新七项全部进入 U01 `MONSTER_FIELDS`，其 `Pick<Monster,...>` 自动扩展 `GameSnapshotMonster`；`copyFields` 深复制位置，`restoreEntityGraph` 先分配再按稳定 ID 恢复 leader/carriedMonster/carriedItem。目标尸体是位置与名字，不增加虚构的尸体 ID 或消费 token。当前实例 schema 延续 U01；本轮不提供旧 schema/缺字段的回退或迁移。

`inflictDamage` 中断不依赖最终 HP 损失：近战/U06 法伤会先调用 `absorbShieldDamage`，再以穿盾伤害调用 `takeDamage(..., true)`；所以只在后者检查非零会漏掉全盾。本轮在前者保留原始量并清位，后者覆盖绕盾路径。零输入和无敌只约束吸收中断；没有顺便重写现有伤害免疫、死亡顺序、归因或盾公式。燃烧与藤蔓/蒸汽/腐蚀气的直接扣血入口调用同一原语；坠落/爆炸原有减盾入口自动覆盖。毒、反伤、碰撞、杖/魔杖和致死打击沿用 takeDamage。只有未启用的 D2 `CREEPING_DEATH` 旧直扣分支无 CE 可达对应，本轮未给它新增玩法，归 U15e/K34。

**组合效果不能误写成清整组：** 非无敌坠落伤害（全盾也包括）先清进行态，随后转层只清位置，所以最终通常是 `targetCorpseLoc=null, isAbsorbing=false`；这不代表转层原语清了两个字段。无敌幸存者的测试证明只清位置，进行态仍 true。

**补充纠正旧注释：** 新层 pending 怪的落点可复用 `restoreMonster` 的 placement 思路，但 CE 实际调用 `restoreMonster` 的门是 visited。web 首次生成层的 pending 幸存者不清 counter/进行态，专项测试已经覆盖。缓存层恢复后的目标位置可能还在、计数为 0；让随后更新使其失效是 U11 的责任，本轮不抢先清整组。
