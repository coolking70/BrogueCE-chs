## 4. 实现与随机/回调约束

改动集中在 `Game.startNewGame`。先 `discardInFlightAdvancement` 终止旧迭代器，不执行旧回合 epilogue；注销旧层 grid 的唤醒闭包；再播种、恢复全局与 Game 的 run 初值。新玩家/装备/地牢仍按原次序创建。新增复位全是赋值、容器分配和计数归零，不抽随机数。

旧层的 Map/Set 和 ItemLoader 知识表改为新容器，不能用 `.clear()` 把 A 局已持有的引用也清掉；`machineCells/waypoints` 在开局先换容器，防 test 模式或原地生成覆盖旧引用。日志 reset 同时重置消息 ID，实体 ID 在创建新玩家前重置。未更改 `Random.ts`、存档 DTO/版本、`loadSnapshot`、玩法公式或 CE 源码。

**不多掷骰**：额外脚本 [u00-generation-check.mjs](../../scripts/u00-generation-check.mjs) 用 esbuild 的 onLoad 从入场 HEAD 读取四个生产文件构建旧版，另构建工作树新版，在隔离子进程运行 4 seed × D1–D26。两个版本逐层地形、完整两流状态、已有 SUBSTANTIVE 计数，以及拦截 ranval 得到的两流真实抽取数逐项深相等；包含 seed warm-up、拒绝重抽及 waypoint 临时流抽取。该对照只读 HEAD，不写 baseline。

**不重复绑定**：复用原有每层 `bindDormantAwakener`，没有向新局再追加一份绑定；测试 spy 要求每次新局正好一个非 null 注册，所有旧层登记均为 null；旧 grid 发实际 SHATTERING DF 不能唤醒 B，新 grid 同一事件恰调用一次。
