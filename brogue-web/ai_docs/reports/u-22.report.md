# U22 发现屏、详情与帮助报告

## CE 执行路径与任务书勘误

`Rogue.h:1193–1194` 定义 `?`/`D`；`IO.c:2614–2621` 分派到 `printHelpScreen`/`printDiscoveriesScreen`。发现屏不在 Items.c，而在 `IO.c:4271–4317,4372–4407`。CE 只列五张风味种类表：左列卷轴→戒指，中列药水，右列法杖→魔杖；各表按原表索引顺序，没有排序。护符、食物、武器、护甲不列。已鉴定行白色、前缀物品字符；未鉴定行暗灰，前缀 `magicCharDiscoverySuffix` 的善/恶符号及对应暗色。`printDiscoveries` 先累加未鉴定种类的 frequency，再为未鉴定且 frequency>0 的行打印其在剩余总频率中的整数百分比。CE 这段**打印的是表中真名，即使未鉴定**，且没有“已知/未知”计数，也没有 called 和描述。任务书 §1/§2 的相关叙述与 CE 原码不符。

本轮遵守任务书 §4“UI 不能比游戏知道得更多”：未知行使用已分配外观或绰号，不显示真名、描述、频率、资源值；已知行显示真名、配置频率和描述。计数以种类鉴定集合计算，分别显示已知与未知数。因此信息保护优先于 CE 原发现屏的剧透行为；此偏差需验收方知悉。

帮助源于 `IO.c:4198–4260`。web 仅列 `Input.ts` 有真实映射的移动、背包、使用、投掷、拾取、搜索、等待/楼梯、查看、自动探索、D、?、取消。CE 帮助中 web 尚无键位/行为的命令没有列入。

## Web 实现与不泄漏

- `Discoveries.ts` 固定 CE 五表和行顺序，数量为卷轴14、戒指8、药水16、法杖12、魔杖9。这里依 CE 目录显示缺于 web 模型的种类为匿名 `???`；没有创建物品、改鉴定或移动生成流。web 目录中自创/退池条目不会冒充 CE 发现条目。缺失模型及其外观应由 U15 处理。
- `ItemKnowledge.ts` 集中种类已知、实例已知、极性揭示、容量已知、符文已知的展示判断；发现屏和 `DetailGenerator.ts` 共用。详情的效果描述受种类已知门控；实际伤害、护甲与瞬移距离受实例已知门控；仅容量已知时只报上限，不从 `actualEnchantment` 推导距离。符文说明只在 `runicKnown` 时显示。
- 未知发现行只从风味映射和 `callTitles` 构造；`description` 与 `frequency` 是 `undefined`，未生成资源数值。极性后缀仅复用只读 `magicCharDiscoverySuffix`，不更改极性状态。已知计数只读 `identifiedItems`。`Discoveries.test.ts` 覆盖初始未知、绰号、鉴定以及“已知容量而未知实例”的反事实隐私测试。
- `Input.ts` 新增大写 D 与 ?；`Game.ts` 将两者当纯 UI 动作，不推进回合。`ReferenceOverlay.vue` 用捕获阶段拦截屏内按键，按任意键关闭，避免关闭键同时触发游戏命令；同一组件支持宽屏三列和窄屏单列，并根据语言选择中英文帮助标签。

## 留给 U24 的文字问题

`consumables.json` 的 `potion_of_life` 描述称“完全恢复生命并解除饥饿等”，现有实现只回满生命而不增最大生命；`potion_of_confusion` 的游戏效果走 hallucinating；护符 speed 的现有效果仍给 levitating。`DetailGenerator.ts` 现存武器/护甲符文说明有与实际消费者不符的可能（如 reflection/dampening/mutuality），本轮未修改文案语义。上述由 U24 按玩法稳定后的真实效果核对。
