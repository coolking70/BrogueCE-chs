# W-12：blink 与反向 beckoning

基准 HEAD：`8f78869`。规格按 W-0 的 W-12 行（文件实际在 §2.4，任务书称 §2.3）。本轮完成显式玩家 blink 与玩家/怪物 beckoning。未新增物品或改变生成池；blinking 杖的实际身份、自然获取与回电/瞄准接线仍留 W-25。

“blink 与 W-3 普通射线的遇障前停相同”只能部分成立：**后续格子的 HALTS_BEFORE 共用，但第一格规则不同**。普通射线可接触墙/生物；conjuration 等 HALTS_BEFORE 射线在第一格仍可更新，blink 会先拒绝。晶墙/反射生物也在 blink 停步位置之外，因此没有反射 RNG、接触或伤害。普通 beckoning 第一条射线仍走 W-4 反射，反射回原施法者的零距离接触不会自拉。

反向斜线的固定对抗样本：施法者(4,5)，目标(6,8)，墙(5,7)。朴素反向调优射线立即受阻；CE 反向路径为 `(6,7) → (5,6)`，目标最终紧邻施法者。本轮测试及真实页面均覆盖。

## 2. W-11 复用结论与发现的缺口

**安置核心可复用，但需要补一个时序参数；W-11 的通用性判断有缺口。** `Game.placeCreature(target,destination,options={})` 新增可选 `pickupBeforeVision`，默认 false 保留原 teleport 顺序，blink 传 true。`canPlaceCreature`、整个 `Movement/CreaturePlacement.ts`、`freeCaptive` 和地形入口保持与 HEAD 字节一致。`finishBlink` 只把已算出的落点交给 `placeCreature`，没有新增坐标写入、环境结算或拾物副本。随机传送策略没有侵入 blink。

本轮确实发现 W-11 的拾取判断有缺口：`pickUpItemAfterDisplacement` 原来让金币先进入背包，满包时拒收。W-11 仅用普通食物证明拾取，未覆盖 CE 的金币特例。这不是安置接口不足，但说明此前的拾取验证不完整。已在**原共享拾取 helper** 修正（`Items.c:865-888`）：金币直接加余额、绕过容量、不占背包槽。修正也覆盖 W-11 传送/陷阱落位的金币拾取；普通主动拾取入口没有顺带改写。

CE teleport 的 `setMonsterLocation`（`Monsters.c:3707-3715`）先刷新视野后拾取，blink 的 detonate 顺序相反。最初复用时漏看了这个顺序差异；复核发现拾取可能触发地形晋升（现目录已有 TM_PROMOTES_ON_ITEM_PICKUP 载体），所以不能仅凭返回后都调用过就当成等价。最终通过可选参数分别保留两种 CE 顺序，只有一份共享拾取和安置逻辑。新增两组观察视野调用时物品是否已被拾取的测试，默认调用保留 W-11 行为。潜伏生物挪位/气味回合/独立 STUCK 等 web 无载体的规则仍按 W-11 登记；休眠生物落点按 W-11 更严格的占位规则拒绝，不挤走或杀掉它。

## 3. 近邻、拾取、地形与时序

- 距离≤1 是真正的效果门禁：不位移、不释放、不调整等待、不 autoID；包括斜向相邻。不是移动后再用“没变化”掩盖错误。
- IMMOBILE 同样挡住释放和位移；INANIMATE/INVULNERABLE 本身不是 beckoning 免疫。已有长等待用 max 保留。CE 可见性决定 beckoning autoID，**合格但受阻仍可鉴定**，不再附加“必须坐标改变”的旧条件。
- 玩家 blink、被怪物拉动的玩家都在最终位置自动拾取，无第二次动作或收费；普通物品满包留地，金币满包照收。只捡落点物品，不捡经过格物品。死亡入口不再拾取；嵌套陷阱使用最终位置。
- 穿越熔岩/深渊/陷阱不触发逐格步行效果；落点才通过共享原语结算。测试覆盖落点毒气陷阱、机器格、岩浆 gameOver、深渊标记与真实 C-5 换层、两级传送，以及仅对被移动者结算。退出旧蛛网不删网；SEIZED/SEIZING 不误当 STUCK 全清。
- 真实 W-2/P2 beckoning 确认：一电、100 tick；目标等待101→1，该动作不能立刻行动。显式 blink 本身不偷偷收费；正式 blinking 杖的背包路由留 W-25。
- 物品层沿用现有模型，不在此轮重写通用堆叠/弹药 quiver、护符守卫生成等拾取子系统。这里完成的是 blink 落点拾取入口及已有金币/容量载体的 CE 规则，不宣称整个 Inventory 已与 CE 等价。
