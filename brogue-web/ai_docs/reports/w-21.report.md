## 1. CE 执行路径与目标门槛

本仓库 `BrogueCE-master/src/variants/GlobalsBrogue.c:69,710`：魔杖身份指向 `BOLT_EMPOWERMENT`，目录效果 `BE_EMPOWERMENT`、magnitude=10、forbidden=`MONST_INANIMATE`、flags=`BF_TARGET_ALLIES | BF_NOT_LEARNABLE`。magnitude 不参与强化数值计算。物品目录 frequency 本轮仍是 web 的 **3**，修成 CE 的 1 留给 W-24。

`Items.c:5311–5320`：实际射线接触目标后，先拒绝 `&player`、`MONST_INANIMATE`、`MONST_INVULNERABLE`，再调用 `empowerMonster`，创建 `EMPOWERMENT_LIGHT`，最后以 `canSeeMonster(monst) && autoID` 决定自动鉴定。自动瞄准的盟友标志不构成命中效果的敌友门槛；手动命中敌人同样强化。web 的 `MONST_TURRET` 未展开 CE 复合位，因此本轮显式包含它的 INANIMATE 门。

`Monsters.c:547–563` 的顺序是：改 maxHP、防御、精度、伤害下界/上界 → 两计数各递增 → `heal(monst,100,true)` → 可见时消息。不是先把旧最大生命补满再加上限，也没有“一次性强化”检查。

web 调用链是 `useArcanaItem → confirmArcanaTarget → zapBoltFromPlayer → applyBoltResult → applyBoltEffect → Monster.empower → Creature.heal`。沿用 W-3/W-4 的真实反射、接触与自动鉴定事务。helper 额外拒绝 hp<=0；射线路径原本就不选死体。没有新增 RNG 调用。

## 2. 整数增量、黄金值与累积

每次命中使用**当前**属性：

| 属性 | CE / web 本轮写入 |
|---|---|
| maxHP | `maxHP + 12` |
| defense / accuracy | 分别 `+10`，不按阵营缩放 |
| damage.lowerBound / upperBound | 各自 `bound + max(1, trunc(bound/10))` |
| newPowerCount / totalPowerCount | 分别 `+1` |
| currentHP | 增大上限后调用 100% 治疗，最终等于新上限 |

`Math.trunc` 对应 C 整数除法；所有正常伤害界非负。上下界独立计算，不能先用下界求一个增量再同时加到两端，也不能四舍五入。

| 0 | 1 | 1 |
| 1 | 1 | 2 |
| 9 | 1 | 10 |
| 10 | 1 | 11 |
| 19 | 1 | 20 |
| 20 | 2 | 22 |
| 29 | 2 | 31 |
| 99 | 9 | 108 |
| 137 | 13 | 150 |

## 3. `heal(..., panacea)` 逐项表

CE `Items.c:4664–4706` 首先执行 `min(maxHP, currentHP + percent*maxHP/100)`，然后才看 panacea。W-9 此前只内联百分比治疗，没有 panacea helper。本轮提取到 `Creature.heal`，普通 HEALING 仍传 false；没有改变药水/卷轴/气体的状态入口。

| CE 状态/字段 | 原函数规则 | web 对应及验证 |
|---|---|---|
| HALLUCINATING | 仅 >1 时设为1 | `hallucinating`，0/1不变 |
| CONFUSED | 仅 >1 时设为1 | `confused`，不是立即清零 |
| NAUSEOUS | 仅 >1 时设为1 | web 无该 StatusId/生效通路；未移植，明确登记 |
| SLOWED | 仅 >1 时设为1 | `slowed`，不立即刷新速度；正常下一次倒计时结束后复原 |
| WEAKENED / weaknessAmount | 仅 WEAKENED>1 时：数量0、时长0、调用 updateEncumbrance | web `weakened>1`清0，**=1仍保留**；无 weaknessAmount，战斗仍使用既有固定虚弱倍率；无数量/负重重算可接 |
| POISONED / poisonAmount | 有毒时：时长0、数量0 | 通过已有 `setStatusDuration('poisoned',0)` 同时清除；没有毒时不擅自抹掉残余数量，符合原函数条件 |
| DARKNESS | >0清0；若是玩家，更新矿灯和视野 | web 状态未建模，`Game.refreshMinersLight` 仍固定 darknessStatus=0，未伪造有效消费者；反射强化玩家本就被门槛拒绝 |
| BURNING | 不处理 | 既有运行时 burning 值保留 |
| PARALYZED | 不处理 | `paralyzed` 保留 |
| DISCORDANT | 不处理 | `discordant` 保留，不因强化转队 |
| ENTRANCED | 不处理 | `entranced` 保留 |
| HASTED、LEVITATING、IMMUNE_TO_FIRE、INVISIBLE、TELEPATHIC | 不处理 | 对应时长保留，旗标不剥离 |
| SHIELDED / maxStatus | 不处理 | shielded/maxShield 均保留；CE 全 maxStatus 表不因 heal 改写 |
| STUCK、DONNING、SEARCHING、NUTRITION、MAGICAL_FEAR、LIFESPAN 等其余状态 | 不处理 | 不增删这些未建模载体；玩家营养不改 |
| SEIZED / SEIZING、阵营、能力、突变 | 不属于 heal 状态清理 | 保留原值 |

C 黄金值核对覆盖全部已建模的对应状态；时长1的虚弱、无毒时残余浓度、慢速到期、满HP也解状态、普通治疗不解状态均有断言。未建模的 NAUSEOUS/DARKNESS/weaknessAmount 是既有原语缺口，按任务书 W-9 交接条款在此登记，**不能把本实现称为“全清负面状态”**。

## 6. 反射、免疫、观察与闪光

反射到玩家走真实 W-4 弹道，确实产生玩家接触，但 `instanceof Monster` 门拒绝：玩家HP、状态、毒浓度不变，不产生本效果 autoID。无生命、箭塔复合位、无敌目标同样完全不写属性/计数/状态，仍阻挡这条不穿透的射线，后方目标不被强化；空射不回落到玩家。

强化在不可见目标身上仍生效；自动鉴定使用既有 `canObserveBoltCreature`，覆盖可见、隐身不可见、非FOV、心灵感应、催眠透露位置、隐身盟友。没有把“命中即鉴定”或“hp发生变化”当作条件。

CE `createFlare(...,EMPOWERMENT_LIGHT)` 是独立于 canSee 的半径6光照动画。web 既有系统没有通用 flare 生命周期，本轮在可观察命中后沿现有 BoltFrame 渲染增加180ms绿色目标字形闪光，免疫/玩家/隐藏目标不泄露闪光；保留效果帧到最终路径结果，没有改变射线碰撞或RNG。**这不是 CE 半径6辐射/扩散动画的完整移植**；`LightCatalog` 仅有光源定义不代表已具备动画消费者。完整 flare 仍登记未完成。
