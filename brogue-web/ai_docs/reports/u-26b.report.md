# U26b 结局结算、分数与高分榜报告

## 规格与 CE 核查

依据 X-0 §4.3 U26、§2 D22、§3.1 K37；逐条核对本地 CE：

- `RogueMain.c:1169–1175`：死亡分数为金币加每颗流明宝石 500，简单模式再除以 10。任务书“死亡=金币”是简写，若理解为原金币数则与 CE 冲突；本轮按 CE 实现。
- `RogueMain.c:1305–1337,1373–1377` 与 `Items.c:8861–8873`：胜利从金币起算，背包逐件取非负 `itemValue`；护符 35000，宝石每颗 5000，其他类别 0；超胜利只将护符价值乘 2；简单模式最终除以 10。不存在全分数翻倍、深度/击杀/固定物品加分。
- `Movement.c:2512–2542`：底层传送门携护符触发超胜利，一层上楼携护符触发普通胜利。本轮仅接结算，未改变深层或宝石生成流。
- `RogueMain.c:1151–1167,1364–1376`：死亡描述含深度，胜利榜单描述依 Escaped/Mastered 与宝石数量分三档；均经 i18n 输出。
- `Rogue.h:118,192`、`platformdependent.c:268–318,434–472`、`IO.c:4410–4457`：日期为本地 `YYYY-MM-DD`，最多 30 条，按分数降序，替换最低分时同分可入榜，榜单仅显示正分条目。浏览器用独立 localStorage 键，读写均捕获异常。

## 实施

- `Core/Endgame.ts` 集中实现 CE 物品价值、三类结局结算和宝石数量；`Game.ts` 取消旧深度/击杀/装备固定加分与全局胜利倍数，接普通/超胜利分支。
- `ItemCategory.GEM` 只补结算所需类别槽；本轮不开放深层宝石生成。
- `Core/HighScores.ts` 实现独立榜单持久层；`GameEndOverlay.vue` 展示本局分、日期、名次和描述。结局保存时排除回放；胜利时遵循 CE 排除 wizard 模式。
- 结局状态纳入 U27 命令检查点，回放逐事件核对胜负、超胜利和得分，偏离时报 OOS。超胜利运行态放在实例外 WeakMap 并在开局重置，遵守 U03 已登记的实例字段契约。
- 死因文本接入带深度的 i18n 模板；旧胜利翻译键按 P1-30 守卫移入 legacy 字典。

## 边界

本轮不迁移旧存档或旧榜单，也不实现 D27–40、宝石自然生成与超胜利地图生成。浏览器拒绝 localStorage 时，结局仍显示分数，榜单读取为空且保存失败；运行不抛异常。

## 验收方裁决

- 死亡宝石兑换：CE `numberOfMatchingPackItems(GEM,…)` 计**背包条目数**（matchingItemCount++），同层宝石叠放为一条（Items.c:988–992）；执行方用 quantity 之和。已改 `lumenstoneCount` 计条目，测试黄金值死亡 2234→1734（一堆 2 颗），另增两件单颗 = 2234 对照。胜利 `itemValue` = 5000×quantity 不变。
- 执行方的全仓套件因 Windows 负载中止；验收方在 Mac 完整复跑。
- Mac 全量门禁另暴露 2 处旧前提：`u_06` 死因期望 "Killed by a X." → CE RogueMain.c:1162 带深度；`w_5` 类别覆盖要求 D1–26 出现全部枚举 → 新增 GEM 仅 D27–40（U26a），暂排除。其余均通过（blueprint_center 负载超时单跑通过）。
