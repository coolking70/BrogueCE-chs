# U02a：随机数状态无损存档与 64 位种子输入

基准 `165dd00`；2026-09-25。规格：任务书、X-0 §4.1、§4.2 U02、§3.1 K04/K01；CE 事实以本工作树 `BrogueCE-master` 为准。

本轮实现双流 RNG 无损恢复、uint64 种子输入/保存/显示；保持原生成算法及低 32 位播种规则。读档恢复当前层 waypoint 随机产物，避免恢复 RNG 后又因重洗牌改变怪物行为。未实现层种子隔离、整局跨层存档或旧档迁移。**有限的当前层续跑验证通过不等于任意整局状态已完整持久化；U03 的剩余边界见 §7。**

## 1. 状态结构和存档边界

`Random.getState()/setState()` 使用值拷贝，载荷如下（均可原生 JSON 往返）：

| 字段 | 合同 |
|---|---|
| `version` | 固定 `1` |
| `algorithm` | `brogue-web-ranval32-low32-v1`；U02b 切算法时须重新定义，不得静默读取成新算法 |
| `streams[0/1].a,b,c,d` | SUBSTANTIVE / COSMETIC 各四个 uint32，合计 256 位完整内部状态 |
| `currentRNG` | `0` 或 `1`，保存当前选择器，包括正在选 COSMETIC 的检查点 |
| `randomNumbersGenerated` | 原有 SUBSTANTIVE 非简并 `randRange` 逻辑调用数 |
| `cosmeticNumbersGenerated` | 新增同口径 COSMETIC 调用数；不影响取数 |

计数不是原始 `ranval` 次数：拒绝采样可以多耗原始数但只计一次；20 次 warmup 不计数；`upper<=lower` 不取数、不计数。`randPercent`、clump、rollD、shuffle 沿用现有实现和消费顺序。`setState` 先校验全部载荷，再拷贝；非法算法/选择器、缺字段、稀疏流数组、非 uint32、非法计数一律拒绝且不改变原状态。双向修改 DTO 不影响另一侧。

`GameSnapshot` 的现有 v2 外壳保持，新增**必需** `rngState` 与 `waypoints`，`seed` 改为规范十进制字符串。v1、缺 RNG 载荷的既有 v2、数值型存档种子均拒绝；不补默认 RNG、不靠 seed 猜测旧流位置。版本判断与 App 存档摘要同步（原 App 只认 v1 的陈旧判断一并修正）。localStorage 键仍为 `brogue-web-save-v1`，它是存储槽名称，不是 schema 判据。

`waypoints` 保存当前层的 `coordinates/count/refreshTicker/distanceMaps/coverage`。这些是已消费 RNG 产生的状态，不能用存档时的流位置重新抽取；Dijkstra scanner 仅为 scratch，恢复时置空、下次刷新按原逻辑懒建。**新层生成、重访缓存层、掘地的原 waypoint 构建路径不变**。原私有字段强转保存改用完整 RNG API，以免遗漏新增计数。

## 2. 三个入口的播种规则

| 入口 | 行为 |
|---|---|
| 新局 `startNewGame` | 在清旧局之前校验种子。空输入由 UI 传 undefined，undefined/0 使用 `floor(Date.now()/1000)-1352700000`；保存实际完整种子。两流用低32位同时初始化，各20次 warmup，双计数归零。外观洗牌仍消费 COSMETIC，结束切回 SUBSTANTIVE；随后沿用 U00 的正常初始化/生成顺序。 |
| 读档 `loadSnapshot` | 校验新载荷；从 `rngState` 恢复，不调用全局 `rng.seedRandomGenerator`。`ItemLoader.initConsumables(new Random(snapshot.seed))` 在私有 RNG 上重建外观，恢复已有 wand/staff 显式映射与鉴定态；恢复 waypoint 产物。末尾渲染回调后再次设置保存状态，避免回调的 cosmetic 抽取吃掉已保存的下一次结果。 |
| 录像 `loadReplay/replayRestart/replaySeek` | 录像由最初种子重建新局并依次执行事件，仍统一走 `startNewGame`；seek/restart 重新从开局播种，不用任意存点替代起点。导出种子是字符串；读取额外允许精确、安全、非负 number 的现有录像，统一规范化。超安全整数、超uint64及错误字符串拒绝。 |

构造 `new Game()` 的既有隐式新局会先播种；随后读档覆盖为保存状态，这是构造入口的行为，不是 loadSnapshot 重播种。外观私有 RNG 只负责可重复的初始展示映射，既不改变存档中的实质流，也不抢占已走到中途的 cosmetic 流。

## 3. 64 位输入、存储、显示

新增 `Seed.ts`，输入允许十进制字符串、bigint、安全非负整数 number；统一成 `0…18446744073709551615` 的规范十进制字符串。拒绝负数、小数、指数/十六进制写法、尾随垃圾、超范围及已经丢精度的 number。前后空白与前导零规范化。

MainMenu 保留文本输入，使用数字输入提示，不经过 `parseInt/Number`；非法输入禁用开局并标记 `aria-invalid`，显示范围提示。App、开局日志、存档摘要、`currentSeed`、录像 JSON、`render_game_to_text` 都传递完整字符串。

U02a 算法边界唯一缩窄处是 `Number(BigInt(fullSeed) & 0xffffffffn)`：

- `1099511627783`（2^40+7）与 `7` 的 RNG 序列和开局世界完全相同；存档/显示的 seed 不同且各自完整。
- `9007199254740993`（2^53+1）与 `1` 同流；最大 uint64 与 `4294967295` 同流。
- **先判断完整 seed 是否为0，再取低32位**。`4294967296` 的低位为0，但它是确定性 seed，不触发时间播种。真正输入0仍使用时间种子。

没有启用 CE 的高32位 XOR，故本轮高位不影响生成，这不是完整 CE 64 位生成对齐。

## 6. 给 U02b 的精确施工说明

**CE已核源码：** `Math.c:90–112,125–136,160–194`、`RogueMain.c:232–313,675–817`、`Rogue.h:2577`；对应SHA在audit中。关键事实：

1. `raninit(uint64_t seed)`：a=0xf1ea5eed；b/c/d取低32位；**c再异或高32位**；20次ranval。U02b在当前Random的raninit边界传入完整uint64（BigInt拆hi/lo），不能先缩为number。仍保留已有32位无符号运算和拒绝采样。
2. `rand_64bits()`：对当前选中的流**先hi、后lo调用两次原始ranval**，返回`(hi<<32)|lo`；SUBSTANTIVE只增加**一次**randomNumbersGenerated，无range拒绝采样。不能用两次randRange(0,UINT32_MAX)替代。建议对外仍以精确uint64/规范字符串边界保存。
3. `initializeRogue`先切SUBSTANTIVE并播种，初始化levels时遍历`i=0…deepestLevel`（含末端槽）。若`rogue.seed>>32`非零，levelSeed=rand_64bits；否则保持CE旧分支：先rand_range(0,9999)，再加10000×第二次rand_range(0,9999)。结果为0时改i+1。**每轮随后还有下梯坐标拒绝采样、向下一层传upStairsLoc；不能先批量只抽全部levelSeed而省掉中间消费，却宣称与CE逐骰同构。** 后续才初始化waypoints、cosmetic地形色、shuffleFlavors等。
4. `startLevel`新层分支：从当前主流 `do oldSeed=rand_64bits(); while(oldSeed==0)`；`seedRandomGenerator(levels[depth-1].levelSeed)`同时重置两流；接入该层预落怪/物→`digDungeon/placeStairs`最多50次→`initializeLevel`→`setUpWaypoints`→`shuffleTerrainColors`→缺护符补偿；之后 `seedRandomGenerator(oldSeed)`同时回切两流。**这是从抽出的oldSeed重新初始化，不是恢复进入层前的8个uint32。**
5. oldSeed回切后才做新层50步环境预热。重访层走map/items/creatures/scent恢复及setUpWaypoints，不进入新层的oldSeed/levelSeed播种支路；公共环境补跑最多100步，随后放玩家。不要把回切移动到预热之后，也不要把重访误当新生成。
6. **CE的seedRandomGenerator不清randomNumbersGenerated**；计数清零发生在Recordings.c:720的initRecording及:1428初始化回放。web现函数每次播种都清计数是旧行为，U02a有意保持；U02b要拆开“初始化流”和“新局/录像计数归零”，否则每层两次seed调用会错误抹计数。

**web精确接线点：** `Game.startNewGame`初始化层种子表并保持完整原始seed；`generateDepth`的`cached`/首次生成分支划清：Architect.generateLevel、populateLevel、机器/物品/怪物/落梯与waypoint构建纳入层流；回切须覆盖第一层和后续层。现在waypoint位于两分支汇合处且自身隔离，U02b必须有意识地拆分该调用时机、让新层setUpWaypoints真正消费层流；不能沿用当前的waypoint-only快照隔离当作CE oldSeed路径。`pendingFallenByDepth`实化/落位在当前populate之后，和CE预载顺序不同，应逐步标出对应边界；U03负责其完整持久化。

U02b还须明确当前web未实现CE的预分配上下梯坐标、颜色洗牌/环境预热等完整时序，决定哪些在该轮闭环、哪些留后续，不能仅加一个levelSeed字段便称CE同种子地图一致。保持本轮RNG载荷算法标签的版本边界；层seed表与visited关系须进未来整局schema。测试覆盖high=0/high≠0、生成出的levelSeed=0和oldSeed=0重试、首层/后层/重访、玩法插入不同抽取仍不改变未生成层的地形随机输入。

**预计漂移面：** 高位XOR会改变高位seed两流；初始化层seed/楼梯预抽、oldSeed抽取、所有新层流隔离即使对旧32位seed也会改变生成顺序。地形、机器/物品/怪物、waypoint、外观及后续玩法计数均需逐阶段独占归因。全局计量等状态仍可影响后层产物，不能将“随机输入隔离”夸成“交互完全不影响后层一切产物”。保留U02a原基线证据，U02b单独核准并捕获漂移，禁止混捕。

- [x] 不做旧存档兼容、不做整局跨层存档；未触碰levels、meteredItems/foodSpawned/goldGenerated、pendingFallenByDepth保存。
