# W-22：强化后的学习——依赖核实与暂缓

基准：`b66d0e0`，起始工作树干净。权威规格为 [W-0 的 W-22 行与表后两段](w-0-survey.report.md)，执行 [W-22 任务书](../tasks/w-22.prompt.md)。本轮采用任务书 §1、§8 明确允许的“做不到忠实则停下写清楚”分支，**没有启用学习，没有消费任何待学次数，也没有修改生产代码、数据或现有测试**。

**empowerment 状态：数值已对齐、学习未完成。** 数值部分仍受 [W-21 报告](w-21.report.md) 中 panacea 未建模状态、伤害分布及闪光表现等边界约束。不能标为“数值与学习均对齐”，也不能把本轮审计通过称为“学习部分已实现”。

## 1. 为什么暂缓，以及候选处理的取舍

读到实际执行代码后，W-0 登记的两项外部依赖仍然成立：

- `BLINKING`：`Monster.specificallyValidBoltTarget` 明确拒绝；`tryUseBolt` 没有另一条 blink 调度。W-12 的玩家 blink 和共用安置原语不能代替 CE 的安全图、敌人图、气味图择点。CE `Monsters.c:2299–2370` 的 `monsterBlinkToPreferenceMap` 比较四邻格、40 个周界瞄准点和冲击位置，实际 `zap`；`moveAlly` 在逃险、逃敌、追敌、追领袖等不同位置调用。
- `ANCIENT_SPIRIT_VINES`：`MONSTER_BOLT_TABLE` 仍是 `effect:null`；`castMonsterBolt` 直接返回，`tryUseBolt` 也拒绝。W-1 仅保存了 DF 名字。web 的 DungeonFeature/Terrain 目录没有对应的古灵草/藤蔓执行项；CE `Globals.c:525–526,684–685` 的藤蔓包括缠绕、伤害、可燃及晋升行为，不能用现有网格图案或 `BoltEffect.NONE` 代替。

这些不是只会出现在人工夹具中的死项。CE `Globals.c:1086,1114` 的 dar blademaster、imp 可提供 blink；`:1163–1164` 的 mangrove dryad 可提供 vines。它们不是 INANIMATE/IMMOBILE，且没有必须优先学习的合法旗标；普通强化盟友遇到这些尸体就能抽到缺失能力。吸血鬼亦有 blink，但先学缺少的 TRANSFERENCE；winged guardian 则因 INANIMATE 整体不合格。

CE `canAbsorb/anyoneWantABite` 只检查“尚未拥有 + NOT_LEARNABLE”，没有“web 可执行”条件；完成时直接安装所选能力、`newPowerCount--`，没有重抽或补偿规则。因此：

| 备选处理 | 对抽签/行为的影响 | 本轮决定 |
|---|---|---|
| 预先删除缺失的 bolt，或跳过含它们的尸体/盟友 | 改能力分母，可能连盟友分母也改变 | 不采用 |
| 保留候选，抽中缺失项后重抽 | 将原缺失项概率转移给其它能力，并改变 RNG | 不采用 |
| 抽中后作废、退款、永久等待依赖 | 额外引入 CE 没有的失败/等待规则，改变尸体占用与完成时间 | 不采用 |
| 正常完成但仅写说明或 bolts 列表 | 花掉次数但无法执行 blink/vines | 不采用 |
| 同轮完成怪物 blink 和整个藤蔓旁支 | 超出 W-0 明列的本轮子集边界，需要独立实现与验收 | 拆分后再做 |
| 整体暂缓学习运行时，维持 W-21 计数及现状 | 不产生新增抽签，不伪造子集玩法为 CE 对齐 | **采用** |

“可执行子集验收”可以限制验收声明，但不能自动提供上述未就绪候选的忠实运行时策略。本轮交付审计与复现证据；没有把“零新增能力”包装成子集完成。

## 2. CE 触发 → 资格 → 选择 → 走向 → 吸收 → 完成/放弃

位置均基于当前附带 CE 源码，不照抄旧报告的漂移行号。

1. **死亡触发**：`Combat.c:1934` 的 `killCreature` 先以 `MB_IS_DYING|MB_HAS_DIED` 防重复。非玩家普通死亡先处理掉落/死亡 DF、设置 HAS_DIED，再在非 administrative、非 dormant 条件下释放 carriedMonster、应用其落格效果，最后 `:2038 anyoneWantABite(decedent)`。不是仅玩家击杀，也不要求死亡者敌对。`Monsters.c:925–950` 迭代器跳过 HAS_DIED，死亡者不能选择自己。
2. **尸体早退**：没有任何可学旗标且 bolt 列为空、尸体格阻通、SPECTRAL_IMAGE、INANIMATE 或 IMMOBILE 则返回。即使 bolt 全部不可学，只要列表非空仍会进入资格扫描；不可学筛选在后面。
3. **盟友资格**：`Combat.c:1632 canAbsorb` 要 ALLY、`newPowerCount>0`、自己的 `targetCorpseLoc` 无效、盟友和尸体均非 INANIMATE/IMMOBILE、`!monsterAvoids(ally, corpseLoc)`、距离图值 `<=10`，再要求至少一个未拥有的可学能力/行为/bolt。不是直线距离；已有目标检查也不是全局“这个坐标是否被其它盟友占用”。web TURRET 是未展开的复合标记，未来移植必须补足其 INANIMATE/IMMOBILE 含义。
4. **距离图**：第一遍对每名 ALLY（即使没有待学次数）`fillGrid(0)`，再 `calculateDistances(... forbiddenFlagsForMonster(&ally->info), NULL, true, true)`。`Dijkstra.c:209` 的两个 true 分别是允许秘密门、八方向。`traveler=NULL`，没有把整张图逐格套 `monsterAvoids(ally)`；尸体目标格另由资格函数检查。`Monsters.c:650` 根据飞行、火免、无敌、水免调整禁止地形，不能统一成普通 passable 或玩家距离图。
5. **两级选择**：先 `rand_range(1,盟友数)`；成功定位盟友后立即保存尸体坐标/名字、计数20，再选能力。先按位号递增列 abilities，再列 behaviors，放在同一池均匀抽一个；只有没有缺少的可学旗标时才从尸体 bolt 原有顺序抽一个，排已有 bolt 和 BF_NOT_LEARNABLE。不是“旗标/bolt 两类各50%”，也不是从整个 boltCatalog 随机获得魔法。
6. **走向尸体**：`Monsters.c:3050 moveAlly` 前面的逃险、逃敌、施法、近敌追击有更高优先级。到 `:3217` 的尸体支线才检查无中毒、未燃烧或有火免，调用 `moveMonsterPassivelyTowards(..., false)`；站到尸体且没有 MB_ABSORBING 时重新设20并设置 MB_ABSORBING。中毒/燃烧不会取消选中的尸体，可能耗尽赶路期限。
7. **持续吸收**：`monstersTurn:3337` 在即时落格效果、麻痹/催眠/俘虏及普通 AI 前先调用 `updateMonsterCorpseAbsorption`。站在目标且 ABSORBING 时先减计数；每次 `ticksUntilTurn=100` 并返回 true，完成的最后一次也消费该行动。不是20个玩家输入，更不是每客观 tick 无条件减一次。开始吸收的中毒/燃烧门没有在此重复检查。
8. **完成**：`:3266–3309` 清 target，若 absorptionBolt 非 NONE 则追加，否则按 absorbBehavior 写对应旗标；仅 `newPowerCount--`，清 ABSORBING，补永久状态，最后清 absorptionFlags/absorptionBolt。total 不减。反复强化的学习次数逐次消费。
9. **放弃**：未处于“原地且吸收”分支时先 `--counter`；`<=0` 清 target/ABSORBING/待学能力。若仍有 ABSORBING（已离开尸体），清该位，并在**递减后** `counter<=15` 时放弃；17→16保留、16→15作废。放弃不扣 new，不将尸体重新广播给另一盟友。`Combat.c:1823` 的 `inflictDamage` 在护盾处理后无条件清 ABSORBING，连被盾完全挡住的此次调用也清；不能只在实际扣血时中断。重新开始吸收还会重置20。

## 3. 两次遍历与 ourBolts：原函数运行证据

[w22-ce-audit.mjs](../../scripts/w22-ce-audit.mjs) 从原文件提取 `canAbsorb`、`anyoneWantABite`、`updateMonsterCorpseAbsorption` 和原枚举，编译后运行断言；生成 [C 源码](w-22-evidence/ce-learning.c)、[输出](w-22-evidence/ce-learning.txt)、[29条非哨兵 bolt 原表行](w-22-evidence/ce-bolts.json)。距离图、随机返回值、世界/UI 是受控桩，**这是原选择/吸收函数测试，不是完整 CE 游戏差分，也没有验证真实 Dijkstra 地图生成**。

**第二遍使用同一张 grid 分配，但内容是第一遍最后一名盟友的距离图。** 第二遍没有重新计算，既不是“每名盟友还用各自的图”，也不是“第一遍整段只算一次”。最后盟友即使 new=0、已有尸体目标，也会覆盖 grid。这是可观察的 CE 选择缺陷，不能在移植时偷偷改成收集候选数组再均匀抽样。

| 原函数受控输入 | 原函数结果 |
|---|---|
| 第一遍 A/B 各自距离2，最后图 A=20、B=2；抽签1/2 | 选 B；两次 rand_range 调用 |
| 同上，抽签2/2 | 找不到第2名；无人得到目标，仅一次 rand_range 调用，无重试 |
| 第一遍 A 自己图距离20，B 自己图 A/B均2 | 第一遍仅数出1名，第二遍却选到 A |
| 最后 B 的 new=0，但其图令 A距离20 | 第一遍数出A，第二遍无人合格 |

不同飞行/火免等禁止地形使这类距离差异具有实际来源；探针用直接注入距离值隔离选择逻辑，不冒称做了真实地形端到端复现。web 本轮未移植；恢复实施时应保留上述行为并用回归锁住，另案修 CE bug 才能改变。

**ourBolts 并非每次 canAbsorb 都填。** 只有前面的资格条件通过，且没有缺少的可学 ability/behavior 时，才清数组、写入当前盟友全部已知 bolts，然后检查尸体 bolt。旗标成功早退或资格失败时，数组可以保留上一名盟友的内容。探针验证这种“脏值保留”。但被最终选中的盟友若走旗标抽签，根本不用 ourBolts；若走 bolt 抽签，刚才成功的资格调用必然已重建它。因此在正常单线程、两调用之间 info 不变的执行路径中，这不是“用上一名盟友的 bolts 排除当前候选”的 bug。注释里的“没有可学旗标”要理解成**没有尚未拥有的可学旗标**。

## 5. 尸体一次消费、保存恢复、换层和克隆

CE 没有持久化“尸体物品列表”。一次普通死亡只调用一次选取，至多给一名盟友安装待学任务；失败或放弃没有二次分配。其基础是 killCreature 的死亡位守卫，不是尸体坐标去重；两只怪物先后死在同一格不能合并成同一尸体。

web `triggerDeathFeatures:7254` 的 deathEffectTriggered 只覆盖 MA_DF_ON_DEATH：它在没有此能力时直接 continue，**不能直接拿它当所有死亡学习分配的一次性守卫**。`removeDeadMonsters:7671` 掉携物后过滤死怪；目前没有 anyoneWantABite。若恢复实施，必须在实际死亡/清扫链保证玩家攻击、怪物互攻、毒/火/其它环境致死只分配一次，并区分行政删除、休眠怪与携带怪释放，不能在两个回合清扫入口各抽一次。

`Rogue.h:2280–2286` 的恢复载体应包含 targetCorpseLoc、targetCorpseName、absorptionFlags、absorbBehavior、absorptionBolt、corpseAbsorptionCounter，以及 MB_ABSORBING、当前 learned flags/bolts 和 ticksUntilTurn；new/total 为既有数值字段。web 尚未加入这些吸收字段，**本轮未验收“吸收中保存再读”**。存档不能重新选择能力、重置20、重新广播尸体或额外消费次数。普通旧档可默认无目标/非吸收；活动/休眠怪、测试房 reset、内存层缓存和 JSON 恢复都应逐条覆盖。现有 levels 全量 JSON 持久化边界仍见 W-21，不因本轮报告变为已实现。

`Time.c:1567` 坠落幸存并换层时、`:2119 monsterEntersLevel` 到达新层时，CE **只在该处清 targetCorpseLoc**，没有同时清全部吸收字段；后续计数更新再处理残留。未来不能把旧层坐标带到新层当新尸体，也不能说 CE 这两行已清空整个任务。

当前交付对生产代码零改动，因此新增学习 RNG 调用为0，**并非因为探针没造出尸体而猜测为0**。没有改 frequency、种类、生成候选或基线。
