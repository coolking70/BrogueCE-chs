## CE 核验发现

CE `FP_FACTOR / 20` 是整数除法。现有 `LightCatalog` 黑暗下限写成 JS 浮点除法，原 CE 编译值在 base=65536、满黑暗时给半径 4，旧实现给 5。仅补整数截断，原 C-7 守卫原样通过。此项属于任务要求的 light 定点对齐，并进入 light 阶段；没有修改 C-7 期望。

“命中充能”按 CE 收窄为近战 `attack()`，不是所有直接伤害。CE 的护符分支还有 `charges>0` 前提，因此诅咒收割不会把已就绪护符重新变成冷却。这两点以 CE 为准，均有反例。

终验前复核 `Rogue.h:1397–1406` 后，将 C oracle 宿主结构的 enchant2/charges/enchant1 改为原声明的 short，并将组合由 1,296 扩到 1,944。新增 `wisdom=0, multiplier=-3200, charges=1, remaining=3000` 先红：旧 JS 给 0 充能/1680 周期，原 CE 因 short 写回溢出再走正向循环，给 3 充能/1099 周期（19 次间隔抽样）。代码现于减增量后立刻执行同样 short 写回；原 W-6/7 守卫不改。先红记录 [short-timer-before-expanded.json](u-15b2-evidence/short-timer-before-expanded.json)，修复与负例结果单独留存。此次发生在最终冻结前，已停止尚未启动的自动终验；不计为最终通过。
