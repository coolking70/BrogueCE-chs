# U19c：机器实体即时实化与失败回滚

执行 `ai_docs/tasks/u-19c.prompt.md`，参照 X-0 §3.1 K28/K32、§4.3 U19c，并逐段核对本仓库 CE。**实际 Game 建层已把机器怪物和物品移到 feature 内创建；失败会删除本次及递归子机器的实体，成功的机器不会在 populateLevel 再生成一遍。** 未调整目录、频率或退池资格，未提交。

本轮验证的是 **feature 调用位置、现有生成器的 RNG 消费时机、真实占用和实体事务**。不是完整 CE 建层或 `generateMonster` 内部的逐骰一致性证明；已发现而明确保留的边界见 §7。

三份生产文件：

- [BlueprintEngine.ts](../../src/engine/Generator/BlueprintEngine.ts)：实体 adapter、feature 内调用、递归事务、部落关系、失败所有权检查及 U25 回滚记录。
- [Architect.ts](../../src/engine/Generator/Architect.ts)：向整层同一 BlueprintEngine 传递实体 adapter。
- [Game.ts](../../src/engine/Core/Game.ts)：adapter、物品实例注册/交接/回滚、即时 horde、populate 复用、建层时玩家离图、提前绑定 DF 消费口、楼梯实际占用、最终产物观测。

Game 的每次新建层尝试均安装 adapter；成功网格沿用建造前注册的 DF 回调，不再重复注册；生成期间临时借用玩家离图位置，并在 `finally` 中恢复，环境预演和最终落位各自保持原合同。成功层的实体不再被旧的“fresh state”重置擦除。**独立 `new Architect` / `new BlueprintEngine` 未传 adapter 时保留地形/请求预览模式**，支持现有地图算法测试及手工 `populateLevel` 消费夹具；真实 Game 生产路径不走该延迟模式。

U05 的资格重掷算法未改；实化位置移动。CE 对机器 feature 的 placeItemAt 不套用普通散落物的拒绝条件，本轮即时物品按该位置放置；既有领养落点可达性检查及资格过滤仍保留。U04c 的 machineCells 仍从最终 grid 机器号派生。快照 schema、物品/怪物编解码未改变。

## 2. 独立守卫与反例
