# U19a：蓝图 IN_VIEW_OF_ORIGIN 视图约束

本轮执行 `ai_docs/tasks/u-19a.prompt.md`，以本仓库 CE 为准。修正蓝图视野的整数斜率边界；两个旗标的候选门、逐 feature 快照时机沿用已经合并的 U18a-3 接线。未修改机器资格、目录频率、玩家日常 FOV、pendingItems/pendingMonsters 或 horde 时序。未提交。

## 1. 现状与 CE 规格核对

X-0 K32 的“MF_IN_VIEW_OF_ORIGIN 无消费者”描述已被 U18a-3 部分解决：入口时 `BlueprintEngine.featureView` 已在每条 feature 开始时计算并缓存，`cellIsFeatureCandidate` 已过滤视图外候选。因此本轮不是再次接入一个此前不存在的门。

真正剩余的偏差是 **web 通用浮点 shadowcasting 不等价于 CE 机器使用的整数斜率扫描**。例如 origin=(35,14)、唯一障碍=(37,12) 时，旧实现接纳 (38,10)，CE 拒绝；两种旗标都有此反例。新增 [MachineView.ts](../../src/engine/Generator/MachineView.ts)，仅替换 BlueprintEngine 的视图计算调用。

| 事项 | CE 源码与本轮行为 |
|---|---|
| 普通视图 | `Architect.c:1344–1351`：`T_OBSTRUCTS_PASSABILITY \| T_OBSTRUCTS_VISION`。门挡视线；透明但不可通行的地形也挡 |
| 可通行视图 | 同处：`T_PATHING_BLOCKER`，定义见 `Rogue.h:1948`。门不挡；密门、深水、熔岩、深渊、陷阱、火、自燃地形挡；植被仅挡视觉时可穿过 |
| 两旗标并存 | CE 的 `if (MF_IN_PASSABLE_VIEW_OF_ORIGIN)` 优先，使用 PB |
| 遮挡层 | 汇总全部四层地形旗标，不取单一显示层 |
| 半径、其他阻挡 | `max(DCOLS,DROWS)*FP_FACTOR`，本树为 79 格；`forbiddenFlags=0`，不以玩家/怪物/物品占用阻挡；`cautiousOnWalls=false` |
| 边界算法 | `Movement.c:2714–2878` 的八象限变换、32768 斜率精度、C 除法向零截断、列推进与圆形边界。阻挡格本身照亮；origin 由 `buildAMachine` 显式置真 |
| 时机 | 每条未跳过的 feature、前序 feature 写图之后、本 feature 第一次候选扫描之前计算；重复轮次和该 feature 的全部实例共享快照；下一 feature 重新计算 |
| 候选门顺序 | `Architect.c:518–535`：`MF_BUILD_AT_ORIGIN` 早返回在 view 门之前；其余候选须在视图内。已有 hallway/perimeter/room-origin 规则保留 |

**按 CE 纠正任务书的表述边界**：PASSABLE_VIEW 是以 PB 遮挡的视图，不是可达性 flood fill，也不承诺墙内 feature 本格可站立；两种视图都包含遮挡端点。视图是 feature 建造时快照，后续 feature 可以再写门、墙或危险地形。DF 受约束的是候选 anchor，不是随后扩散的全部 footprint。机器生成约束也不等价于玩家光照可见性、暗杆已发现或整机谜题可解；这些边界没有被自行扩大成 CE 没有的规则。
