# U01：实例快照字段合同与往返验收

基准：`1c1136d`；规格：任务书 §1 用户裁决及 X-0 §4.1、§4.2 U01、§3.1 K02。实现采用 **version 2**；version 1 在修改当前局面前拒绝。没有实现旧档迁移、缺字段推断或旧档修复。W-24/W-25 的 flavor 恢复代码原样保留。

K02 的判断成立。除了 flags、钥匙绑定与普通怪的 runtime，本轮还修复 quiverNumber/vorpalEnemy、carriedMonster、玩家 ID/行动债/抓取/免疫/饥饿事件等遗漏。**这是当前层及从该层实体出发可达的引用图合同，不是整局、RNG 或跨层存档完成声明。**

## 1. 字段全枚举与分类

[AST 枚举](u-01-evidence/entity-fields.json)：Item 37、Creature 16、Monster 自有 46、Player 自有 13，共 **112 个声明字段**。含继承后 Monster 62、Player 29；另纳入 Inventory 的 items/capacity。Item 的 identityId、consumableId 原来由 ItemLoader 动态写入；description 原来由详情面板动态读取，本轮显式声明。没有把可选字段、私有字段或未激活留形字段排除。

表中“修前”指入場 HEAD；“当前/分类”是最终合同。所有已声明实例值均需要保存：**本轮没有把任何实例字段列为可重建缓存或不属于存档**。尤其 safetySnapshot 虽叫地图快照却是历史知识，waypointAlreadyVisited 是历史访问位，hungerTransition 是待消费事件；把它们重算会改后续行为。getter/方法/原型不是实例字段；它们由类原型保留。undefined 可选值在 JSON 丢键后读回 undefined，和显式 false/0/null 分开处理。

依据均来自本工作树 CE 与实际 web 消费者。CE 总入口：`BrogueCE-master/src/brogue/Rogue.h` 的 item/keyLocationProfile、creature（含 leader/carriedMonster/carriedItem、machineHome、ticksUntilTurn）；`Items.c:4036–4063`、`Movement.c:616–656`、`Monsters.c:4075–4083`。web 简写 G=Game、M=Monster、C=Creature、P=Player；下列消费者未改玩法。

## 2. 图、顺序与统一合同

- `EntitySnapshot.ts` 注册平面值字段、Set 字段和引用字段；普通、突变、变形、克隆、玩家克隆、谱影、休眠怪走同一合同。移除 polymorph/cloneState/entrancement/allegiance/spectralBlade/dominatedForm 多套条件性 runtime；保留实例上的对应事实位。
- `toSnapshot` 从 active+dormant 出发，遍历 leader/carriedMonster/carriedItem；地面、背包和装备物品并入图。当前表中的条目保留在原数组；仅额外可达的怪/物放入 `entityGraph`。不会将脱离占格的携带怪塞入 active 表，也不把同一物品复制成不同对象。
- 第一步恢复全部 Item 和 Monster（Map 按 ID）；第二步连接 leader/carriedMonster/carriedItem；再建 Player 并连接装备与背包、恢复 active/dormant/ground 顺序。W20 原来的“实体建完后恢复领袖”原则复用并扩展为全部引用，不依赖数组顺序，支持循环与共享引用。
- 玩家 ID、活跃/休眠/脱离表怪物及所有物品的最大 ID 都进入 `ensureEntityIdAbove`。独立 `deserializeMonster` / 测试房重置使用同一合同，携带独立 graph；重置后再次连接根实体关系。高位玩家/携带怪/携带物 ID 均验证。
- 分配 Monster/Item 使用原型加显式值恢复，不跑目录生成构造器，不重新抽睡眠，不重翻译名字，不再次赋永久状态，不修正 poison/maxShield。容器递归复制支持 Vue Proxy；Sets 显式复制，不用不能接收 Proxy 的 structuredClone。
- Player 构造只建立 Inventory/原型，随后所有实例值覆写；hungerTransition 使用窄快照接口读写，避免消费待处理事件。

这次只在已有 Game 私有方法包装下收拢实体合同，不实施 X-0 的整文件 UR 重构。测试房原有第三套手抄字段改为同一序列化入口，防止再次漏字段。没有改变生成、战斗、开锁、掉物、休眠与复制规则。
