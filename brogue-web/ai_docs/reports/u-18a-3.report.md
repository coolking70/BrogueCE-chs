## 2. U04：楼梯与 CE66

- 新增只读候选模块 `Generator/Stairs.ts`。墙龛检查 WALL、三面 P、一面非 PB 且 arc<2、背角与邻域机器；额外拒绝本格机器/延期产物占用，以维持最终落位合同。
- 以 U02b 预抽坐标为目标，先最近切比雪夫候选圈，再 `P|ITEMS|DESCENT|DEEP|LAVA|DF_TRAP`、无 LIQUID、arc<2 的非机器回退格。严格保留 CE 回退掩码，不能把它误写成完整 PB。
- `Architect.prepareStairLoc` 放入口两侧火把、暴露花岗岩、加固邻壁；候选清除区保留 CE 上界不含 `x+5/y+5` 的不对称性。`installStair` 只写 DUNGEON、清 LIQUID/SURFACE，保留 GAS。写层职责仍在已有 Architect 白名单内。
- `generateDepth` 同一层 RNG 流内执行最多50次 `dig → placeStairs`，成功后才 population/50轮环境初始化。记录实际坐标，并把实际下梯传给下一未访问层的上梯计划。50次失败抛错且不标记 visited；第3次成功的对抗用例断言只 population 一次。
- `populateLevel` 只消费已经安好的楼梯。早期保留的“直接调用就再安梯”分支使合成机器场景失败，已从代码删除；机器效果测试的可解性断言未改。
- **D26 是护符层，最深层是 D40**（CE `Architect.c:3690–3759`、`GlobalsBrogue.c`）。D26 继续有下梯，D40 下梯位为 DUNGEON_PORTAL。补齐其 home/draw/flags/appearance/light，以及各 HAS_STAIRS 消费点；无护符拒绝通行，有护符复用胜利流程，不生成 D41。宝石、CE 超胜利计分等 U26 内容未扩入本轮。

CE66 在单独的 s6g 阶段回池：只移除隔离集合中的66，目录 frequency=0 与强制 autoGenerator 调度不变。自然验收固定包含旧反例种子26、42，另有424242、777、20260913、31337，共156层；10次 CE66 调用中5次成功并提交、5次失败，失败地图逐格哈希均回滚。

| 自然样本 | 结果 |
|---|---|
| seed42 / D12 | CE66 成功，结果对象进入真实 population handoff |
| seed424242 / D8 | CE66 失败，grid cells 前后哈希相同；RNG 正常消费 |
| 全部156层 | 上下梯实际地形正确、机器号0；玩家入场全层 PB=0；网页端移动图上上下梯互达 |

证据：[closures.json](u-18a-3-evidence/closures.json)、[执行脚本](../../scripts/u18a3-closures.ts)。没有更换旧失败种子来绕过错误，也没有通过清除危险层伪造落位安全。

**连通性口径限制**：网页端 `Connectivity.ts` 原本就是不限制挤角的八方向图，CE Dijkstra 的对角限制更严。额外严格 PB 探针在156层中有15层不可达（完整列表在 closures 的 ceDiagonalDistance）；该探针同时采用更严格的 PB 掩码与对角规则，**不能把15层全部单独归因于对角规则**。例如424242/D15，网页端存在无深水/深渊/熔岩的路线，严格 CE 图不可达。未声称整个地图几何已与 CE 等价，也未为了让探针绿而新增 CE 没有的安梯后重挖条件。原有 P1-26/29/33、C-3/C-8 等游戏连通与机器可解合同继续运行。将同一严格PB查询加载到未修改的 s0 生产源码、同6种子 D1–D25（旧D26无下梯）也有8/150层不可达，见 [原实现对照](u-18a-3-evidence/topology-before.json)；此对照证明该严格合同原先就未普遍满足，不用于掩盖最终15层的具体结果。
