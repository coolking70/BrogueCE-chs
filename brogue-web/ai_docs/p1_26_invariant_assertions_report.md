## 一、退役方案与理由

**选择 `it.skip`（保留用例体），不物理删除。** 处理方式与同文件 levels 段及
`p2_*_baseline` 的退役完全一致：

- 用例体与其比对的 `p2_3_baseline.json` play 段是 P2-3 阶段「当时玩法状态」的
  **可查证据**，留着不占任何运行成本（skip 不执行）；
- 任务书禁止删 fixture，删用例会让 play 段变成无引用死数据；保留 skip 用例
  使 fixture 每一段都仍被引用；
- skip 用例的注释（20 行）写明为何退役：相位快照当回归闸门，任何有意改动必红
  （P4-8 已撞过一次），抓不出真回归，只制造「顺手刷新基线」的压力；
  并指明接管者：`p1_26_invariants.test.ts` 的不变量 + `generation_baseline.test.ts`
  的滚动基线。

## 二、新增不变量与各自能抓的故障

文件：`src/test/p1_26_invariants.test.ts`，5 种子（`424242, 777, 20260913, 31337,
20260916`＝4 个既有基线种子＋验收方探针中坏层最多的 20260916）× D1–D26 = 130 层。
判据：**直接调用 `Game.canMoveTo` 本体**（只读转型，harness 同款做法），
8 向泛洪（游戏移动是 8 向）。每条不变量对应的「具体的、合理的错误实现」：

| 不变量 | 能抓什么故障（对抗性） |
|---|---|
| 1. 楼梯存在：D1–D25 上下齐全；D26 有上无下 | 生成器停止放楼梯（`floorTiles` 耗尽、深度条件写错）；D26 误放下楼梯（护符层语义被破坏） |
| 2. 上楼梯 → 下楼梯（**留痕断言**：不可达层数**恰好等于 11**） | 就是我们今天真实拥有的 bug：缺 CE 湖泊连通性验证（P1-29 待修）——它此刻就在失败边缘被按住；任何新增的不连通回归也会撞线 |
| 3. 可走格占比 ∈ [3%, 40%]（占全格 79×29=2291） | 生成器彻底失灵：凿不开洞（接近 0 可走）或忘了墙（大面积可走）。实测 7.8%~22.5%，两侧留约 2 倍余量 |
| 4. D1–D26 全部生成不抛异常 | 生成器在某个 seed/深度崩溃（下标越界、除零等），原始栈直接指向出事层 |
| 5. 同种子两次生成 130 层指纹逐一一致 | `Math.random` 混入生成路径、跨实例共享状态等破坏决定性的改动 |

留痕断言的实现要点（按任务书要求）：`KNOWN_UNREACHABLE_STAIRS_LEVELS = 11`，
用 `toBe`（恰好等于）——**变好变坏都翻红**；断言名与失败消息都写明
「已知 bug P1-29 待修，修复后必须改回严格 0」，失败消息还会动态列出当前坏层明细，
P1-29 落地时照着改即可。

## 四、反向验证（4 条，全部真实失败后还原）

**RV1（任务书强制项）：把连通性判据从 `canMoveTo` 换成 `isPassable`** ——
失败输出（节选）：

```
× 上楼梯能走到下楼梯——已知 bug P1-29 留痕：当前恰好 11 层不可达，…
AssertionError: 下楼梯不可达层数与留痕值 11 不符（…）。
坏层明细: : expected +0 to be 11 // Object.is equality
```

`isPassable` 判据下坏层明细为**空**、测得 **0** 层不可达——11 层真实坏层全部
"隐形"，与 phase_c 文档 §四 的自我纠错记录完全一致。这就是深水
`isPassable === true` 的坑，现在被测试侧的判据选择钉死：本文件的可走性判据
只此一家（`realMoveRule` → `Game.canMoveTo`）。

**RV2：注释掉楼梯存在性判定** —— 失败输出（节选）：

```
× 每层楼梯存在：D1-D25 上下楼梯齐全；D26（护符层）有上楼梯、无下楼梯
AssertionError: 楼梯存在性被破坏：
seed424242/D1 缺上楼梯
seed424242/D1 缺下楼梯
seed424242/D2 缺上楼梯
seed424242/D2 缺下楼梯
…
```

存在性断言确实在读真实地形数据，不是恒真：检测一坏，130 层全线翻红。

**RV3：8 向泛洪改成 4 向** —— 失败输出（节选）：

```
AssertionError: 下楼梯不可达层数与留痕值 11 不符（…）
坏层明细: seed424242/D8: …；seed424242/D20: 329/430；seed777/D15: …；
seed20260913/D17: …；… : expected 14 to be 11 // Object.is equality
```

4 向口径测出 14 层坏（多出 424242/D20、777/D15、20260913/D17）——泛洪拓扑
被「恰好等于」钉住，判据实现本身的偏差也翻红。

**RV4：把占比上限从 0.40 压到 0.10（低于实测最大 22.5%）** —— 失败输出（节选）：

```
AssertionError: 可走格占比越界的层数=123（生成器可能彻底失灵）
明细: seed424242/D1: 可走 304/2291 格(13.3%，区间 3%~10%)；…
: expected 123 to be +0 // Object.is equality
```

占比断言确实在量可走格数，越界即红。
（附注：先试过另一思路「用 test 模式的大厅生成冒充 normal」，但其可走格 359 =
15.7% 恰好落在区间内、占比断言不红——说明该区间对"换一种正常形状的地图"
有韧性，这正是"只抓彻底失灵"的预期行为，故换用 RV4 的口径破坏法。）

四条改坏均已还原；还原后 `grep "临时改坏"` 无残留，5 条用例复跑全绿。
