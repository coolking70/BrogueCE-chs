## 背景一句话

web 版的 i18n **架构是好的**（i18next 的「键 + 插值」，没有 C 版那种"翻译已拼装句子"的模板匹配），但 `defaultValue` 提供了一条**无声的降级通道**：缺翻译时不报错、不告警、测试也不查，直接渲染英文。实测 281 个被引用的键里 **60 个缺失（21%）**，且绝大多数是最近几轮新加的——**漏洞在持续扩大**。

实测渲染效果（中文名嵌在英文句子里，两头不靠）：
```
combat.monster_splits  → "The 粉色果冻 splits in two!"
death.bloat_gas        → "The 膨胀怪 releases a cloud of caustic gas!"
combat.backstab        → "You backstab the 老鼠 for 7 damage!"
```

## 必做

### 一、★ 机制性修复：键存在性红灯（本轮最重要的一件事）

新增测试：**扫描 `src/` 下所有源码里的 `i18next.t(...)` / `$t(...)` 调用，断言每个静态字面量键都存在于 `src/locales/zh_CN.json`。**

这条测试的价值在于：从此任何人新增一条消息却忘了补翻译，**测试立刻红**。没有它，本轮补的翻译会在几轮后重新腐化。

**实现上的两个坑，请认真处理**：

1. **动态键不能误报**。代码里存在 `i18next.t('name.' + name, ...)` 这类拼接（见 `ItemLoader.ts:16`）。扫描器必须能识别并跳过，或改用"前缀白名单"处理。**你自己设计方案，但必须在报告里说明如何避免漏报与误报。**
2. **扫描范围**要排除测试文件自身，但**不要**排除 `.vue`（界面文案也走 i18next）。

扫描器还要能输出"翻译文件里从未被引用的键"清单——第四节的归档要用它。

### 二、补齐缺失键

先自己跑扫描器得出**当前真实的缺失清单**（不要照抄我的数字，代码可能已变），逐条补进 `zh_CN.json`。

**翻译质量要求**：
- 参照文件里既有的中文风格（简洁、口语、句末用中文标点）。
- 保留 `{{}}` 插值变量名不变。
- 注意**中文语序**：英文的 `The {{monster}} splits in two!` 不要直译成"这 {{monster}} 分裂成两个！"，应作"{{monster}}分裂成了两个！"（中文不需要冠词，主语后一般不加空格）。
- 参考同类既有键的处理，保持一致。

### 三、变异名：8 个，且要解决语序

实测现状：
```
explosive  变异后的怪物名 = "explosive 老鼠"
juggernaut 变异后的怪物名 = "juggernaut 老鼠"
```
根因是 `Monster.ts:402` 的 `this.name = m.name + ' ' + this.name` 直接拼接未翻译的变异名。

**不要简单地给变异名加个 `name.*` 键就完事**——那样会得到"爆裂的 老鼠"（多一个空格）。中文的形容词+名词组合不需要分隔符。请：
1. 给 8 个变异名各设一个键（键名前缀由你定，例如 `mutation.explosive`）。
2. 修正拼接逻辑，使中文下产出 `"爆裂的老鼠"` 这样的结果。
3. **必须有测试**断言拼接结果不含多余空格、且不含英文。

CE 对应的是 `mutationCatalog` 的 `title` 字段（`Globals.c:1396` 起），请核对 8 个变异的英文原名，确保译名贴合其机制（例如 `juggernaut` 带 `MA_ATTACKS_STAGGER`、`grappling` 带 `MA_SEIZES`、`vampiric` 带 `MA_TRANSFERENCE`——这些在 P4-5 已实现，译名应与面板里的能力描述呼应）。

### 四、清理 C 版遗留的死键（本轮已获授权）

项目负责人已明确：**brogue-web 是独立项目，不与其他项目共用文件**。验收方已核实
`src/locales/zh_CN.json` 是 C 版 `BrogueCE-master/bin/assets/zh_CN.json` 的**副本**
（该文件 2289 键全部被 web 副本包含，web 另有 516 条独有键），**删键不影响 C 版**。

请把**代码从未引用**的键从主文件移出，归档为 `src/locales/zh_CN.legacy.json`
（**归档，不是删除**——留作查证）。当前实测约 2584 条（92.1%），其中 592 条含
`%s`/`%i` 是 C 的 printf 约定，i18next 用 `{{}}`，**永远不可能命中**。

注意：
- 归档前先跑一次扫描器确认清单，**动态键的前缀（如 `name.*`）不能被误判为未引用**
  ——`ItemLoader.ts:16` 的 `'name.' + name` 会用到全部 190 个 `name.*` 键。
  这是本轮最容易误删的地方，误删会让怪物名/物品名集体变英文。
- 归档后必须**实跑一局**确认没有新的英文残留（可复用你为第一节写的扫描器 + 一个
  跑若干回合的冒烟用例）。
- 报告里给出归档前后的键数与包体大小对比。

### 五、写进项目常识
