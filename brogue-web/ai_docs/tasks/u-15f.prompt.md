## 1. 线索（**全部请自行核实**，读到执行路径）

- CE 吃食物的入口：营养不足时直接吃；"不够饿"时的确认问句与阈值（`STOMACH_SIZE`、`HUNGER_THRESHOLD` 一类常量——读 CE 实际数值）
- 确认被拒：**不消耗物品、不消耗时间**
- CE 自动进食：营养降到哪个阈值、从背包里**优先选哪种食物**（遍历顺序）、消息、是否耗时、在客观时间块的哪个位置执行
- 没有食物时的饥饿伤害/死亡路径（web 已有部分，核对不回退）
- 芒果与口粮的营养值（CE 目录）；**CE 此路径没有"芒果微量治疗"**（X-0 E06 已纠正历史错误前提），不要加
- 确认 UI：复用现有 `requestConfirm`/`onConfirmRequest`（W-25 blink 熔岩确认的先例）

## 2. 验收标准

- 饱时吃：弹确认；拒绝 → 物品/时间/RNG 全不变；接受 → 正常进食
- 饿时吃：不弹确认
- 自动进食：营养到阈值且包里有食物 → 按 CE 顺序自动吃，消息与耗时按 CE；无食物 → 原饥饿链
- 麻痹、护符饥饿节流等既有行为只回归
- 真实入口：背包点击"吃"、快捷键、自动触发三条路径
