## 0. 并行安全边界（硬约束，先读）

本轮与 **V-2b-9c**（闪电/黑暗/泥潭，四条蓝图）**同时**在跑。那一轮会新增
`TerrainType` 成员、改蓝图池并重捕获 `generation_baseline.json`。

而 `c_7_lighting` / `r_1_appearance` / `c_4a_*` 的穷举表按**索引**键控。
两轮若都追加枚举成员，合并时索引会错位。

**所以本轮铁律：**

- ❌ **不许新增或改动 `TerrainType` 任何成员**
- ❌ **不许碰 `src/test/fixtures/generation_baseline.json`**
- ❌ **不许改 `src/data/blueprints.json`**
- ❌ **不许改任何会移动生成流的东西**（`src/engine/Generator/`、
  `src/engine/Map/` 下的目录与落位逻辑）
- ✅ **只改测试文件**；若你确信必须动生产代码，**停下来在报告里说明，不要动手**

**自检**：交付前跑 `npm run test:drift`，它**必须绿**。红了说明你碰了不该碰的。

## 1. 三条（全部来自 `ai_docs/reports/audit-seedluck.report.md` §2，先读它）

### 1.1 AD3：`p1_37_machine_flag_i18n` 的 `A−B` 逐格循环在空转（**高**）

**现状**：该用例固定 seed 424242 逐层生成，在**首个 `results.length>0` 的层**
`break`，然后断言该层 `A−B`（网格 machineNumber 集 − `∪mr.cells`）精确等于 `[]`。

**病灶（审计原话）**：*哑*——生成流一动就可能换成另一个 `A−B=∅` 的层；
`A−B` 为空时上方那条"每个 A−B 格都必须是机器自己的布点"的逐格循环**执行 0 次**。

⚠️ **前几轮已经做过部分工作，先读代码再动**：
- V-2b-7 加了**非空性哨兵**（约 `:344-348`）——钉"机器必须真的记录了 feature 落点"，
  这条**保留**，它守的是记录点脱钩，和 A−B 是两回事；
- 当前注释（约 `:359-372`）**如实登记了守卫力量下降**（"本层 A−B 为空 ⇒
  上面那条逐格循环在本层是空转"），并说明"每个 A−B 格都是 item/monster 布点"
  这个前提**从来就过强**。

**审计给的方向**：

> 删除偶然的 `A−B` 快照；对 5 seed × 26 层的每一台机器分别量化序列化/反序列化合同。
> 若确需覆盖 interior 外 feature，另加"命中数 > 0"及专门样本，不把它混入往返合同。

⇒ **把"往返合同"与"interior 外 feature 覆盖"拆成两条用例**：
前者对 5 seed × 26 层的每台机器量化（样本大、不挑层），后者单独选样并带
**命中数 > 0** 的覆盖门。**不要保留那个偶然的单层 `A−B` 快照。**

### 1.2 `p1_31_35_placement_snapshot.test.ts:255-276` 的 stale loopMap（**高**）

**病灶**：用 seed42 的存档读进 seed777 的实例，**前提锚**是"读档前 777 的
`loopMap` 必须与 seed42 网格重算图不相等"。两张随机图偶然相等时前提锚先红，
而**被测性质本体没坏**。

**审计给的方向**：*用人工构造的两张必异网格，或直接污染一个确定格再读档；
避免用两局随机地图制造 stale state。*

⇒ 改成**确定性污染**：直接把某个确定格改成与重建结果必然不同的值，再读档。
被测性质（读档后 stale cell 必须为空）**一字不改**。

### 1.3 `p1_31_35_placement_snapshot.test.ts:292-305` 的 waypoint（**高**）

**病灶**：断言"读档后的 waypoint 坐标 JSON 必须不同于 seed777 的旧坐标"。
两局 waypoint 巧合相同时这条否定 pin 会红（*响*，不会哑，但仍是挑 seed）。

**审计给的方向**：*人工写入一个不可能由重建产生的 sentinel waypoint，再读档；
或只比较 load 后状态与从目标网格新建的 oracle。*

⇒ 用 **sentinel waypoint**（例如一个坐标上不可能由重建产生的值），
这样"读档确实覆盖了旧状态"就变成确定性事实，不再依赖两局的运气。
