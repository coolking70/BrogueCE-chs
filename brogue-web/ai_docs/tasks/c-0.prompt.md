## 为什么这一项先做

web 的地牢是**树状**的：房间靠走廊串成一棵树，任意两点之间只有一条路。CE 不是——`digDungeon` 第 3 步就是 `addLoops(grid, 20)`（Architect.c:2897），把树变成带环的图。

没有环路，**已经落地的三件事都在空转或代偿**：

1. **P4-9 的 safety map**：`if (IN_LOOP) safetyMap[i][j] -= 10`（"有环路可绕的地方更安全"）。web 的 `Game.ts:4954` 目前是 `isInLoop: () => false`，这一项**恒不触发**——怪物逃跑少了一条腿。
2. **P4-10 的 waypoint 巡逻**：树状地牢里巡逻等于来回折返。
3. **P1-29 的湖泊闸门**：树状地牢里几乎任何像样的湖都会造成割点，闸门只好频繁拒绝，深水总量比修复前少了 45%。**环路落地后应当回升**——这是判断本轮是否真正生效的重要旁证。

另外 **P1-33**（机器阶段把 `LOCKED_DOOR` 放在割点上，导致 2/260 层不可达）也可能因环路而自然消失，请在报告中实测汇报。

## CE 事实（已逐条打开核实）

### 一、`addLoops(grid, minimumPathingDistance)` —— Architect.c:340-396

调用点是 `digDungeon` 第 3 步：**`addLoops(grid, 20)`**（Architect.c:2897），在 `carveDungeon(grid)` 之后、grid→pmap 转换之前。

```c
const short dirCoords[2][2] = {{1, 0}, {0, 1}};   // 只试水平、垂直两种门

fillSequentialList(sCoord, DCOLS*DROWS);
shuffleList(sCoord, DCOLS*DROWS);                  // 随机顺序遍历全图

copyGrid(costMap, grid);
findReplaceGrid(costMap, 0, 0, PDS_OBSTRUCTION);   // 值 0（花岗岩）→ PDS_OBSTRUCTION
findReplaceGrid(costMap, 1, 30000, 1);             // 值在 [1,30000] → 代价 1

for (i = 0; i < DCOLS*DROWS; i++) {
    x = sCoord[i]/DROWS;  y = sCoord[i] % DROWS;
    if (!grid[x][y]) {                              // ★ 只考虑非地板格
        for (d = 0; d <= 1; d++) {
            newX = x + dirCoords[d][0];  oppX = x - dirCoords[d][0];
            newY = y + dirCoords[d][1];  oppY = y - dirCoords[d][1];
            if (在图内 && grid[newX][newY] == 1 && grid[oppX][oppY] == 1) {   // 两侧都是地板
                fillGrid(pathMap, 30000);
                pathMap[newX][newY] = 0;
                dijkstraScan(pathMap, costMap, false);
                if (pathMap[oppX][oppY] > minimumPathingDistance) {   // ★ 绕行距离 > 20
                    grid[x][y] = 2;        // 变成"可能的门位"
                    costMap[x][y] = 1;     // ★ 同步更新代价图，影响后续候选
                    break;
                }
            }
        }
    }
}
```

要点，逐条对照实现：
- **只试正交两向**（水平门、垂直门），不试对角。
- 候选必须是**非地板格**且**两侧都是地板**。
- 判据是"绕开这堵墙走过去要多远"——`> 20` 才开门。这保证只在真正绕远的地方开，不会把地牢挖成蜂窝。
- 开门后**必须同步 `costMap[x][y] = 1`**，否则后续候选算出的绕行距离是过时的。
- `grid[x][y] = 2` 是"门位"而非"地板"。`digDungeon` 随后把 2 转成
  `(rand_percent(60) && depth < deepestLevel) ? DOOR : FLOOR`（Architect.c:2903）。
  **web 若没有这一步转换，请一并对齐**，别直接铺成地板。

**注意 `PDS_OBSTRUCTION` 是 −2、`PDS_FORBIDDEN` 是 −1**（Rogue.h:2782-2783）。
web `Pathfinding.ts:8-9` 里那两个同名常量是 30000/29999，**与 CE 不符但在该文件内部自洽、有别的调用方**——沿用 P4-9 的处理：**不要去纠正它**，新代码用 CE 字面值（可参考 `SafetyMap.ts` 的 `CE_PDS_*` 或 `WaypointMap.ts` 的 `WP_PDS_*` 做法）。

### 二、★ 另一半：`IN_LOOP` 标志 —— `analyzeMap`，Architect.c:192-250

**只做 `addLoops` 是不够的**：safety map 消费的是 `IN_LOOP` 标志，而它由 `analyzeMap` 计算，是独立的一步。不接上的话，环路造出来了、`isInLoop` 仍恒 false，P4-9 那一项照样空转。

```c
// 1) 初始化：可通行且非密门 → 置 IN_LOOP；阻挡格 → 清除
for 每格:
    if (T_PATHING_BLOCKER && !TM_IS_SECRET) { flags &= ~IN_LOOP; passMap = false; }
    else                                    { flags |=  IN_LOOP; passMap = true;  }

// 2) 逐格 checkLoopiness：把"其实不在环上"的格子的 IN_LOOP 剥掉
for 每格: checkLoopiness(i, j);

// 3) auditLoop(0,0,grid) + 去除多余标记：
//    IN_LOOP 格若四周找不到"既不在 grid 里、又不在环上"的邻格，则剥掉
```

`checkLoopiness`（Architect.c:57-118）的判据请**完整读一遍**再实现：从一个"非环"邻居开始**顺时针**扫 8 邻域，统计环邻居构成几段连续串；**多于一段就保留 IN_LOOP**（说明该格确实连着两条不同的通路），否则剥掉。注意它用的是 `cDirs`（顺时针表），不是 `nbDirs`。

`analyzeMap` 在 CE 的调用点：Architect.c:1081（`buildAMachine` 内）、1736（`addMachines`）、Time.c:2555（运行期 `staleLoopMap` 时）。**web 至少要在生成完成后算一次**，并把结果接到 `Game.ts:4954` 那个 `isInLoop: () => false` 上。运行期是否需要重算由你判断并说明。

`analyzeMap` 还负责 chokepoint（Architect.c:246 起）——**本轮不做**，只做 IN_LOOP 部分，`calculateChokeMap` 对应的分支显式跳过并留痕。

## 测试要求

1. 每条断言必须能在某个具体的错误实现下失败。禁止"跑通了就算过"。
2. **全部行为断言必须打在真实生成的关卡上**，不接受只在人造场景里验算术——P4-9 的 7 条对抗性测试全绿，而真实关卡上 safety map 是整张平图，就是这么漏掉的。
3. **对抗性测试至少五条**，报告写明各自捕获哪种错误实现：
   - `minimumPathingDistance` 判据写反（`<` 而非 `>`）→ 地牢被挖成蜂窝，门数暴涨
   - 漏掉 `costMap[x][y] = 1` 的同步更新 → 后续候选用过时距离，门数偏多
   - 试了对角方向 → 出现对角门
   - 候选格没检查"两侧都是地板" → 门开在无意义的位置
   - `IN_LOOP` 计算漏了 `checkLoopiness` 的剥离步骤 → 整片可通行区域都被标成环上
4. **环路真的存在**：断言真实关卡上存在至少一对地板格，它们之间有**两条不共边的路径**（或等价判据，例如移除任一单格后仍连通的格子比例显著上升）。这是本轮的核心验收，不能只数门的个数。
5. **反向验证（强制）**：至少两条真的改坏、跑出真实失败输出、粘进报告、再还原。
6. **决定性**：同种子必须生成同一张图，要有测试锁住。
7. **连通性不得退化**：`p1_26_invariants.test.ts` 的楼梯可达断言必须仍然通过（开门只会增加连通性，若反而变差说明实现有误）。
