## 二、要做什么

### 1. 先定位 CE 的表（我没找到，交给你）

`Globals.c:50` 只有 `const autoGenerator *autoGeneratorCatalog;` 这个**指针声明**，
注释说它是 **variant-specific**、表在别处按变体赋值。
**请自己找到 brogue 变体的实际表、条目数与赋值点**，并在报告里给出出处。
结构定义在 `Rogue.h` 的 `typedef struct autoGenerator`（terrain / layer / DFType /
machine / requiredDungeonFoundationType / requiredLiquidFoundationType /
minDepth / maxDepth / frequency / minNumberIntercept / minNumberSlope / maxNumber）。

### 2. `runAutogenerators` 本体

`Architect.c:1780` 起。要点（自己读完确认）：
- 按 `buildAreaMachines` 分两趟（`gen->machine > 0 == buildAreaMachines`）；
- 深度约束；
- 数量 = `min((minNumberIntercept + depth * minNumberSlope) / 100, maxNumber)`，
  再叠 `while (rand_percent(frequency) && count < maxNumber)` 的追加；
- 落点要满足 `requiredDungeonFoundationType` / `requiredLiquidFoundationType`。

### 3. ★ 先做载体盘点，再决定接哪几条

**这是本项目的硬规矩**（`SESSION_HANDOFF.md`「这一轮做了会不会是空壳？」）。
自动生成器条目会引用**地形、DF、机器**——web 未必都有。
G-2/G-3 靠这条盘点各挡住了四五条空转链，C-4c 的硫矿"每回合掷骰 11 次全部缓办"
就是没盘点的下场。

**逐条给出"web 今天有没有载体"，只接有载体的，其余登记。**
