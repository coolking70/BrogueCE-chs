## ★ 最重要：CE 源码里有一处会让你做反的陷阱

`Rogue.h:2120-2122` 的三条注释里，**前两条被写反了**：

```c
MA_ATTACKS_PENETRATE    = Fl(13),   // monster attacks all adjacent enemies, like an axe   ← 注释错
MA_ATTACKS_ALL_ADJACENT = Fl(14),   // monster attacks penetrate one layer of enemies, like a spear  ← 注释错
```

- `handleWhipAttacks`（Movement.c:855 起）门控 `MA_ATTACKS_EXTEND` → **鞭，远距离**

**请你自己先把这三处代码读一遍确认**，再动手。如果照注释实现，矛和斧会完全做反。报告里请写明你的确认结论。

## CE 事实（已逐条核实）

### 涉及怪物（`Globals.c` monsterCatalog，注意不在 `variants/GlobalsBrogue.c`）

| 旗标 | 语义 | 怪物 |
|---|---|---|
| `MA_ATTACKS_PENETRATE` | 矛：直线穿透 2 格 | goblin (1042)、goblin warlord (1128) |
| `MA_ATTACKS_ALL_ADJACENT` | 斧：横扫全部相邻 | naga (1081)、dragon (1124) |
| `MA_ATTACKS_EXTEND` | 鞭：远距离单体 | salamander (1083) |

### 一、斧 / 横扫 —— `buildHitList`，Combat.c:2049-2092

怪物侧入口在 Monsters.c:3877-3888：

```c
buildHitList(hitList, monst, defender,
             (monst->info.abilityFlags & MA_ATTACKS_ALL_ADJACENT) ? true : false);
for (i = 0; i < 16; i++) {
    if (hitList[i] && monsterWillAttackTarget(monst, hitList[i])
        && !(hitList[i]->bookkeepingFlags & MB_IS_DYING) && !rogue.gameHasEnded) {
        attack(monst, hitList[i], false);
    }
}
```

`buildHitList` 的 sweep 分支：

```c
dir = NO_DIRECTION;
for (i = 0; i < DIRECTION_COUNT; i++)
    if (nbDirs[i][0] == newX - x && nbDirs[i][1] == newY - y) { dir = i; break; }

if (sweep) {
    if (dir == NO_DIRECTION) dir = UP;
    for (i = 0; i < 8; i++) {
        newDir = (dir + i) % DIRECTION_COUNT;
        newestX = x + cDirs[newDir][0];
        newestY = y + cDirs[newDir][1];
        if (coordinatesAreInMap(newestX, newestY)
            && (pmap[newestX][newestY].flags & (HAS_MONSTER | HAS_PLAYER))) {
            defender = monsterAtLoc({newestX, newestY});
            if (defender && monsterWillAttackTarget(attacker, defender)
                && (!cellHasTerrainFlag(defender->loc, T_OBSTRUCTS_PASSABILITY)
                    || (defender->info.flags & MONST_ATTACKABLE_THRU_WALLS))) {
                hitList[i] = defender;
            }
        }
    }
} else {
    hitList[0] = defender;
}
```

**一个 CE 怪癖，请自行确认**：`dir` 是用 `nbDirs` 算出来的下标，却拿去索引 `cDirs`——这两张表顺序不同（`GlobalsBase.c:38-39`，`nbDirs` 正交优先、`cDirs` 顺时针）。净效果是 8 个邻格**全部覆盖**（i 走满 0..7），只有**命中顺序**受影响。所以行为上"横扫所有相邻敌人"是对的，不必为了对齐顺序去精确复刻这个混用；但**请不要**顺手"修正"成统一用一张表然后声称对齐了 CE——如实说明你的取舍即可。

注意：横扫**只打 `monsterWillAttackTarget` 为真的目标**（即不会误伤同阵营），且墙里的目标除非 `MONST_ATTACKABLE_THRU_WALLS` 否则不打。

### 二、矛 / 穿透 —— `handleSpearAttacks`，Movement.c:917-1010

- `range = 2`；方向 `dir`；目标格 = `attacker->loc + (1+i) * nbDirs[dir]`，i = 0..1。
- 起步要先过 `diagonalBlocked` 检查（贴着墙角捅不出去）。
- 逐格收集：有怪、且（该格不阻挡通行 或 目标带 `MONST_ATTACKABLE_THRU_WALLS`）、且 `monsterWillAttackTarget` → 进 hitList。
- 遇到 `T_OBSTRUCTS_PASSABILITY | T_OBSTRUCTS_VISION` 的格子就 `break`（穿不过墙）。
- `proceed` 条件：`i == 0`（贴脸那格无条件算数）**或**（目标未隐藏 且（攻击者不是玩家 或 玩家看得见它））。
- **★ 攻击顺序是反的**：

```c
// Artificially reverse the order of the attacks,
// so that spears of force can send both monsters flying.
for (i = h - 1; i >= 0; i--) {
    attack(attacker, hitList[i], false);
}
```
即**先打远的、后打近的**。这条很容易写成正序，请务必照实现并用测试锁住。

### 三、鞭 / 延伸 —— `handleWhipAttacks`，Movement.c:855-912

- 先过 `diagonalBlocked`。
- `getImpactLoc(&strikeLoc, originLoc, targetLoc, 5, false, &boltCatalog[BOLT_WHIP])` —— **射程 5**，取沿途第一个受阻点。
- 只打 `monsterAtLoc(strikeLoc)` 这**一个**目标，条件：存在、（攻击者非玩家 或 玩家看得见它）、`!monsterIsHidden`、`monsterWillAttackTarget`。
- CE 用 `zap(originLoc, targetLoc, &theBolt, ...)` 走 BOLT_WHIP 实现表现与结算。web 没有 CE 的 zap/boltCatalog 完整移植——**不要为此新建 bolt 系统**；用 web 既有的近战结算路径打到那一格的目标即可，并在报告里说明这个简化。
