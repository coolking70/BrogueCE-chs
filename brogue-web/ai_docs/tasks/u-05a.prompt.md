## 1. 线索（**全部请自行核实**，读到执行路径）

- CE 的物品生命周期：生成 → `spawnedItems[]` 登记（**构建失败时统一删除**）→ 放地上 / 外包给子机器
  （`MF_OUTSOURCE_ITEM_TO_MACHINE`）/ 交给怪物（`MF_MONSTER_TAKE_ITEM`）——**三者互斥**
- 子机器领养父机器的物品（`adoptiveItem`）：只领养一次；子机器构建失败时该物品怎么办？
- 火把持有者（约 :1705）：先删旧携带物再换——"最后携带者"规则
- web 的延迟实化（BlueprintEngine 只产出指令、Game 再 spawn）是本问题根因：**指令层要表达"同一实例"**，
  否则 Game 无法知道两条指令是同一物品
- 递归失败回滚：父机器失败时，子机器已产出的物品/怪物指令是否全部撤回；**幽灵物品**（有指令无所有者、
  或有实体无位置）必须为零

## 2. 验收标准

- **守恒**：每台机器产出的物品实例数 = CE 语义下应有的数量；地上 + 怪身 + 包内 **按身份去重后无重复**
- 覆盖所有 CE 蓝图中带 `MF_ADOPT_ITEM` / `MF_OUTSOURCE_ITEM_TO_MACHINE` / `MF_MONSTER_TAKE_ITEM` 的 feature
  （列出它们，逐个构造验证）
- 递归失败对抗：强制子机器失败，验证父机器回滚后无残留
- 携带怪死前/死后存读档（U01 已统一合同，本轮验证在该合同下仍守恒）
