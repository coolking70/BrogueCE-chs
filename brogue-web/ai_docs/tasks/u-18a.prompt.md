## 1. 分两阶段，第一阶段是合同

**阶段 A（必做）：逐调用者真值表**。对每个消费者：

| 消费者（web 位置） | CE 对应（函数/行号） | CE 用的判据（旗标组合、是否看四层、是否看怪物/物品/已知记忆） | web 现用判据 | 偏差 | 影响面（生成？AI？玩家？） |

至少覆盖：玩家移动（`canMoveTo`/玩家行走）、怪物移动（`monsterAvoids` 及其各分支）、气味图、安全图（逃跑）、
waypoint、Dijkstra 各 cost 图、生成落位（物品/怪物/楼梯候选/机器）、视线/FOV 的 opaque、自动探索。
对抗格：门（开/关/锁）、密门（未发现/已发现）、网、深水、浅水、熔岩、深渊、四层叠加（DUNGEON+LIQUID+SURFACE+GAS）。

**阶段 B：按表修偏差**。
- 优先修**不移动生成流**的消费者（AI/玩家/气味/逃跑/waypoint）
- **移动生成流的消费者**（生成落位、楼梯候选）：先单变量归因，再决定。若范围大，**本轮只交阶段 A 的合同 +
  非生成修复**，生成侧写成下一轮（U18a-2）的精确施工清单——**这是允许的，不算失败**
- 若决定本轮就动生成：先 drift 记录 → 单变量归因 → 独立守卫 → 再重捕获（W-24/U05a 做法）
