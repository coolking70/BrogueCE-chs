# V-2b-8 autoGenerator MT_* 接线轮

> **本轮在 Codex Cloud 运行。门禁跑法与本地轮次不同——见 §7。**

## 0. 本轮的核心不是数据，是一个缺了很久的形参

这 8 条 FLAVOR 蓝图（58/59/60/61/62/63/64/71）在 CE 里**不经抽签**，
而是由 `autoGeneratorCatalog` 的 `MT_*` 列**强制建造**。

web 的 `AutoGenerator.ts` **已经有 MT_* 数值映射**（`:117-123` 一带，
`MT_BLOODFLOWER_AREA: 58` 等），但整列登记为 `'no-machine'`（`:68`）——
因为 **web 的 `buildAMachine` 没有 CE 的 `bp` 形参**，永远走 `chooseBP` 抽签，
没法"点名建这条蓝图"。

**所以本轮的第一件事是给 `buildAMachine` 补上 `bp` 形参**（CE
`Architect.c` 的 `buildAMachine(bp, originX, originY, requiredFlags, ...)`，
`chooseBP = (bp <= 0)`——传正数即"强制用这条蓝图"）。

★ **这同时解掉另一笔账**：V-2b-4 登记的护符缺口①就是同一个形参
（CE `Architect.c:1747-1754` 用 `buildAMachine(MT_AMULET_AREA, …)` 强制建护符房）。
**本轮只补形参与 autoGenerator 接线，不要顺手改护符来源** ——
护符双轨的处置是独立决策（V-2b-4 已裁决"直投不退位"），动它要另开一轮。

## 1. 四件事

### 1.1 `buildAMachine` 的 `bp` 形参

按 CE 直译。注意 `chooseBP = (bp <= 0)` 的语义：只有不传（或传 ≤0）才抽签。
强制指定时**不再过配额**（CE 的护符房、autoGenerator 机器都不受 reward 配额限制——
自行回 CE 复核这一点并在报告里给行号）。

### 1.2 autoGenerator 的 MT_* 接线

把 `'no-machine'` 那一列改成真实调用。CE 依据：`Architect.c` 的
`runAutogenerators` 里对带 `MT_*` 的条目调 `buildAMachine`。
自行定位行号并在报告里给出。

### 1.3 载体（4 地形 + 6 DF）

- 地形：`BLOODFLOWER_STALK`、`BONES`、`HAVEN_BEDROLL`；
  **`SACRED_GLYPH` 已是 web 既有 TerrainType**，只是不在 `TERRAIN_MAP` 里——
  补映射即可，不要新建枚举（`MACHINE_GLYPH` 才是另一个 tile，V-2b-0 已澄清过）。
- DF：`DF_BLOODFLOWER_PODS_GROW_INITIAL`、`DF_DEEP_WATER_POOL`、`DF_HAY`、
  `DF_JUNK`、`DF_REMNANT`、`DF_URINE`。
  ⚠️ **闭包**：`c_4b` E2/E3 钉死无悬空 `subsequentDF`。链上的也要补，条数可能多于 6。

### 1.4 八条蓝图（CE 逐字）

58 Bloodwort · 59 Shrine · 60 Idyll · 61 Swamp · 62 Camp · 63 Remnant ·
64 Dismal · 71 Sentinels

**接线成功的判据不是"数据落了"，而是"生成期真的建出来了"。**
V-1c 以来 thematic 类机器在生产数据里一直绝迹（`v_1c` Q1b 有反转断言钉着），
本轮要让它们真实出现——报告里给**实测建成台数**（多 seed × D1-26）。
若某条仍建不出来，查清原因，不要只说"数据已落"。

## 2. 基线重捕获（最后一步）

成因至少三股：①`bp` 形参让 autoGenerator 开始建机器；②八条蓝图入池；
③新地形/DF。沿用受控单变量分离。基线重捕获实测约 53 秒，不贵。
**分不开就说分不开。**

## 7. 门禁跑法（云端专用，与本地不同）

**不要跑全量 `npx vitest run`** ——本地实测并行 15 分钟、CPU 合计 135 分钟，
会吃光云端窗口。

**改为：只跑 §3 授权清单里你实际改动过的那些文件**（逐个 `npx vitest run src/test/<file>`）。
全量门禁由验收方在本地跑。

`npm run build` **要跑**（快，且加完地形必须立刻验类型）。

若窗口紧张，优先级：**代码/数据 → 针对性测试 → 基线重捕获 → 报告**。
被截断时越靠后损失越小；验收方能从 diff 看出你走到哪一步。
