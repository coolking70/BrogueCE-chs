## 2. 第 1 件：`isProtected` 的消费点

CE 的 `ITEM_PROTECTED` 有两个消费点（**逐字核对**）：

- **护甲**（`Combat.c:425-431`）：攻击者带 `MA_HIT_DEGRADE_ARMOR` 且被打的是玩家时，
  若护甲**没有** `ITEM_PROTECTED` 且 `enchant1 + armor/10 > -10`，
  则 `enchant1--` 并重新 `equipItem`。**带保护则完全跳过。**
- **武器**（`Combat.c:1432-1440`）：`degradesAttackerWeapon` 且攻击者是玩家时，
  若武器**没有** `ITEM_PROTECTED`、且不是"针对该敌人的 Slaying 符文武器"、
  且 `enchant1 >= -10`，则降级。**带保护则完全跳过。**

（CE 那条注释很有意思：*"Can't damage a Weapon of Acid Mound Slaying by
attacking an acid mound... just ain't right!"*）

另有两处非战斗消费点：`Items.c:2395`（请查清语境）与
`Items.c:3630`（显示层：带保护的物品括号画成 `}`）。

**web 侧要做的**：
1. 查清 web 是否已有"酸怪腐蚀护甲 / 武器降级"的机制
   （grep `MA_HIT_DEGRADE_ARMOR` 的 web 对应、酸怪 `acid_mound` / `acidic_jelly` 的实现）；
2. **有机制** → 把 `isProtected` 接成豁免条件；
3. **无机制** → **不要自创腐蚀系统**。按惯例登记"无载体"，
   并说明激活路径。**判断要给证据（grep 结果 / 行号）。**

`Items.c:3630` 的显示层（`}` 括号）若 web 有对应显示，可一并接上。

## 3. 第 2 件：燃烧怪物的发光

UI-1 报告 §七写死的激活路径：
**`Game.updateVision` 里加一处 `paintLight(BURNING_CREATURE_LIGHT)`**，
条件 `burningDuration > 0 && !isFiery`。

CE 依据（`Light.c:250`，**自验**）：

```c
if (monst->status[STATUS_BURNING] && !(monst->info.flags & MONST_FIERY)) {
    paintLight(&lightCatalog[BURNING_CREATURE_LIGHT], monst->loc.x, monst->loc.y, false, false);
}
```

它在 `updateLighting()` 里（`Time.c:894` 调用），属**玩法光网格**，
**不是**改怪物的字形或颜色。

⚠️ **激活轮必须重核 `MONST_FIERY` 的 web 载体名**（UI-1 明确交代的）。
web 若没有对应的"本身是火焰生物"标志，**说明并登记**，不要硬套。

⚠️ **同时要翻转 `ui_1_rendering.test.ts` 里那条"无燃烧染色"的留痕测试**
（按留痕反转惯例：断言新事实，不是删断言）。
注意：翻转的是"燃烧现在有视觉了"，但**视觉形式仍必须是光、不是染色** ——
染色是 CE 没有的东西，UI-1 明令禁止过。
