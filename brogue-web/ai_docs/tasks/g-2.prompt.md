## 一、本轮定位

G-1 把气体搬进了 GAS 层、换上了 CE 的体积模型与扩散/消散算法，
但**气体的来源仍然是 web 自创的那几个 `addGas` 调用点**。
本轮把 CE 的 DF 目录接上——让气体按 CE 的方式产生。

G-1 已经把路铺好了：`DungeonFeature` 的 GAS 分支（volume 累加）已接、
镜像对账路径已备、`Game` 侧 `gasVolumeAdded > 0 → syncGasMirror` 分支已埋
（今天不可达，接线后自动成为活路径）。**本轮很多条目"tile 列填上即自动生效"。**

的 tile 列填上即走 GAS 分支。**先验证 G-1 的"填上即自动生效"这个预测成立**，
再决定要不要额外接线——**这是本轮第一件事，也是对 G-1 预测的验收**。

### 2. 未迁移的 GAS tile：先盘点再决定做哪些

G-1 列出六个未迁移：`ROT_GAS` / `STENCH_SMOKE_GAS` / `PARALYSIS_GAS` /
`METHANE_GAS` / `DARKNESS_CLOUD` / `HEALING_CLOUD`。

**★ 按项目规矩先做载体盘点**（`SESSION_HANDOFF.md`「这一轮做了会不会是空壳？」）：
每一个都要回答"web 今天有没有东西会产生它"。**没有载体的只迁 tile 不接效果，
或者干脆只登记**——不要造出又一个"掷骰 11 次全部缓办"的空转链
（C-4c 的硫矿就是前车之鉴）。
效果落地（恶心/麻痹/黑暗/疗养）**归 G-3，本轮不做**。

### 3. 蒸汽源（F-0 §5.3-9）

CE：水体自身 `chanceToIgnite = 100`，被点燃 → `DF_STEAM_ACCUMULATION`，
**15 体积/回合持续**。
web 现状：火的邻格是水 → 30% `addGas(50)` **一次性**（G-1 已折算为 325 口径）。

接上 CE 的持续蒸汽源后，**可以退役 `Gas.updateFires` 里那条 web 自创分支**。
退役前后的蒸汽曲线对比要实测报出来。

### 4. `DF_GAS_FIRE` 与"燃气烧完地上留火"

G-1 §十一.2：`GAS_FIRE` tile 迁移后接线，`promoteTile` 的缓办撤除，
"燃气烧完地上留火（80%/回合自熄）"完整成形。
**注意 G-1 已核实 `DF_GAS_FIRE` 的 layer 是 SURFACE（`Globals.c:741`）不是 GAS。**

### 5. 甲烷爆轰、dewar 引爆

`TM_EXPLOSIVE_PROMOTE` 载体落地后 `exposeTileToFire` 的爆轰分支即活；
dewar 是 20000 体积。**同样先盘点载体**——没有载体就只登记。
