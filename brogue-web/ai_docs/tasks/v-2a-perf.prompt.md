# V-2a 收尾轮：armor_model_effect 跑不完（唯一挡住合并的事）

## 0. 背景：本轮不是修缺陷，是修测试载体

V-2a 补完轮已验收通过：行为断言零红、类型门禁绿、前厅合同按 CE 语义定向豁免（验收方独立复核 `blueprint_center` + `p1_33` 共 11/11 绿）。

**唯一挡住合并的**是 `src/test/armor_model_effect.test.ts` 的聚合用例跑不完：

| | 耗时 |
|---|---|
| 文件内显式 timeout | 360 s |
| 实测（执行方，单跑） | 823–923 s |
| 验收方全量门禁 | 超时，从未跑到断言 |

**这不是行为回归。** 同文件的"板甲+3"小用例绿，模型行为无异常迹象。成因是 V-2a 恢复了机器内容物后，每局生成期 substantive RNG 抽取从约 30 万涨到 70–80 万，而该用例建 100 局 × 400 回合 —— 生成成本是它的**附带开销**，不是它要测的东西（它测的是护甲模型 legacy vs wired 的命中率/受伤量差异）。

## 1. 首选修法：把生成成本从用例里拿掉

该用例不需要真实地牢。改用已确立的哨兵形态②：`createHeadlessGame(seed, 'test')` 的完全隔离合成层 + 重播种。这样既不动样本量、也不动 CE 保真度，直接消掉 700k 抽取的大头。

**验收条件**：改造后测得的聚合量（命中率 / 累计受伤 / 死亡次数）必须落在改造前已确立的区间内。若合成层让数字显著偏移（说明该用例确实依赖真实地牢的地形分布），**不要硬改** —— 走第 2 节的退路，并在报告里写明偏移了多少、为什么。

## 2. 退路：拉长 timeout

若第 1 节判定不可行，把该用例的 `timeout` 从 `360_000` 改为 `1_500_000`，并在紧邻处写一行注释说明：这是 V-2a 内容回归后的既定成本（30 万 → 70–80 万抽取/局），不是性能缺陷。

**不接受**缩减样本量（20 seed → 10）—— 那降低统计功效，属于放宽守卫。
