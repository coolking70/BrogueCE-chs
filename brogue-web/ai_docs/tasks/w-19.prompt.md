## 3. ⚠️ 与 W-8 登记的克隆缺口的关系

W-8（`6582cf4`）登记了一个既有缺口：web 的 `trySplitMonster` **从目录重建再复制部分字段**，
而 CE 的 `cloneMonster` 是 `*newMonst=*monst` **整体复制**——所以分裂体不继承燃烧等状态。

变形同样要"重置"一批字段（能力/速度/状态/携带生物）。
⇒ **本轮的"哪些字段重置、哪些保留"要按 CE 逐项核实**，别套用 web 现有的部分复制逻辑。
如果本轮建的字段处理能顺带说明 W-8 那个缺口的修法，**写进报告**，但**不在本轮修 W-8 的分裂**
（那是 W-20 复制轮要复查的，W-0 写了"W-19 后复查字段复制"）。

## 5. 教训（已连续二十六轮验证）

闭包走四条边；退池留形 = 加引擎过滤不改数据；覆盖门换样本不改期望；
**「建成 0 台」≠「RNG 足迹为 0」**；驳回给登记位置并区分仍有效/已过期；
**代码事实为真 ≠ 它是本次失败的成因**；CE 里"看起来不一致"的数值先查是不是承重的；
**验收方写的 CE 事实可能是错的，一律自行核实**；
**撞上守卫时改代码，不改守卫、不绕扫描器**；
**复用前轮原语发现不够通用就如实登记前轮缺口**；
**前轮的留痕登记可能正是为你预约的**，动手前 grep 相关注释；
**照搬上一轮的做法前，先确认 CE 在这里是不是也这么做**；
**公式有定点/舍入细节时，编译 CE 原函数取黄金值**；
**自己 W-0 的规格也可能写得不准**；
**注释写的是意图，执行路径里可能有例外**；
📌 **"看起来不重要"的 CE 判定位置可能是关键**（W-18：催眠的解除代码早于命中掷骰，所以 miss 也解除）。
