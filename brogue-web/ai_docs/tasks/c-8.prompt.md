## 1. 现象（验收方实测，可稳定复现）

**`seed20260916` 的 D21 是一张"到了就出不去"的层**：
从**上行楼梯**出发只能到达 **23 格**（全层可走格约 996 + 23，分成两块）。
玩家从 D20 下楼抵达 D21 后落在上行楼梯处，**够不到下行楼梯** —— 这是**卡死局**。

四条既有闸门同时抓到它（都在报红，本轮要让它们回绿）：
`c_3` T12、`p1_26`、`p1_29`、`p1_33` a)。
`c_3` 的失败消息明确写着：**「密门视作通路口径下仍存在不可达层（真回归，非假阳性）」**。

### 1.1 关键背景：**这不是某一轮的回归，是潜伏已久的生成器漏洞**

- 在**当前 main 上跑 `c_3` T12（15 seed × D1-D26 = 390 层）：坏层 = 0**，全绿；
- 但在 `round/v-1a` 分支上，同一套闸门抓到了这 1 层。

V-1a 是**纯物品生成轮**，它没有改地形代码 —— 它只是移动了 RNG 流位置，
于是同一个 seed 掷出了**另一张地形布局**，而**那张布局暴露了生成器本来就有的洞**。

也就是说：**main 现在的"坏层 = 0"是运气，不是保证。**
换任何一个会移动生成流的轮次，都可能再掷出一张坏图。
（这与 `project_conventions.md` 里「挑 seed 的测试」是同一类现象。）

### 1.2 已知的定位线索（验收方未独立复核，**请你验证**）

V-1a 的执行方对 `generateTerrain` 挂快照实测，报告称：
**在 `generateTerrain` 的返回点，上行楼梯所在连通块就已经只有 23 格**。
若属实，则断连**产生于 `generateTerrain` 内部**（carve / 加环 / 湖泊 /
`finishWalls(false)` 一带），与机器阶段、物品阶段无关。

**请独立复核这一点**，不要直接采信。

## 2. 本轮要求：**先诊断，再动手**

### 2.1 诊断阶段（必须留下可复核的证据）

用 `seed20260916` / D21 作复现样本，在 `generateTerrain` 的**各个阶段之间**
挂连通性快照，定位**究竟是哪一步把关卡切成两块**。至少覆盖：
房间 carve、加环（C-0 的 `addLoops`）、湖泊（P1-29 域）、
`finishWalls`、以及任何会**写墙/改地形**的步骤。

产出一张**阶段 → 连通块数量/最大块大小**的表，把切断点钉死。
**没有这张表，本轮判不合格。**

再跑一个**广度测量**：多少 seed × 多少层里会出现坏层（建议 ≥ 30 seed × D1-D26），
给出**发生率**。这决定了这个洞的严重程度。

### 2.2 与 CE 对照

CE 的做法是**在放置时否决**，不是事后修补：
`levelIsDisconnectedWithBlockingMap` 在 `Architect.c` 多处被用来
**拒绝会切断关卡的地形/机器放置**（见 `:724`、`:1197`、`:1451`、`:1823` 附近，
自行核对确切语义与调用点）。

请查清：
- CE 在**哪些步骤**上做了这个否决；
- **web 对应的步骤有没有做**、做得对不对；
- 差在哪。

若结论是"web 缺了某个否决",那修复方向就是**补上那个否决**,
而不是自创一个"事后把两块连起来"的修补器 —— 后者是 CE 没有的结构,
按用户裁决（「优先还原 CE 的逻辑结构，避免原创差异引起后续连锁反应」）**不可取**。

### 2.3 修复的硬约束：**尽量不消耗 RNG**

⚠️ **这条很重要，它决定下一轮能不能顺利合并。**

`round/v-1a` 分支上有一轮**已完成、已达成 CE 量级**的工作
（附魔卷轴 25.9→14.9、life 药水 18.7→6.3），正**因为本漏洞被卡住不能合并**。

若你的修复在**已经连通的关卡上零 RNG 消耗**（例如：否决逻辑只在
"该放置会切断关卡"时才改变行为，而判定本身不掷骰），
那么 `generation_baseline` **不变**，V-1a 可以直接合并。

**请优先设计成这样。** 若做不到，明说原因，并在报告里写清
"基线必须重捕获、V-1a 需重新测量"。
