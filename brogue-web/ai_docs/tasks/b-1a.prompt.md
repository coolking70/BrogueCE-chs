## 二、范围

### 1. 两层分离的未知态模型（B-0 §一.1）

CE 把"鉴定"拆在两处（自己打开 `Rogue.h:1424-1437` 与 `1361-1386` 核实）：
- **层 1 全局种类表** `itemTable`：`identified` / `called` / `callTitle` /
  `magicPolarity` / `magicPolarityRevealed`——"这个**种类**认不认识"；
- **层 2 物品实例旗标**：12 个鉴定相关位——"这**一件**鉴定到什么程度"。

web 现在只有一个内存 `identifiedItems` Set。**按 CE 的两层建模。**

### 2. 揭示规则（CE 的被动鉴定）

B-0 实测 **web 的被动揭示恒为 0**。CE 的门槛（自己找准确数值与出处）：
附魔要**杀够敌人数**、护甲要**穿够回合**、戒指要**戴够回合**才揭示。
`shuffleFlavors()` / `resetItemTableEntry`（`Items.c:8775/8782`）开局清零。

### 3. ★ 反泄露（P1-49，三处，B-0 已定位）

- 未知武器的 `displayName` **直接拼 `+2`**；
- `DetailGenerator` 对未识别装备显示**基础/实际伤害**与**"被诅咒"**；
- 未识别魔杖的详情面板**漏充能**。

**这是本轮最直接的玩家可见修复**：未鉴定的东西不该泄露它的属性。

## 六、门禁

1. **`generation_baseline` 保持绿**（§四，本轮最重要的一条）。
2. **反泄露的实测**：三处泄露各给"修复前泄露了什么 / 修复后显示什么"的对照。

零断言失败）——**先单跑复核再下结论**，报告里区分"真失败"与"超时"。

## 七、测试要求

1. 每条断言必须能在某个具体的错误实现下失败。
2. **对抗性测试至少七条**，必须含：
   - 未鉴定武器仍泄露 `+N`
   - 未识别装备仍显示实际伤害 / "被诅咒"
   - 未识别魔杖仍显示充能
   - 层 1（种类）与层 2（实例）被合并成一层
   - 揭示门槛写错（少杀一个敌人也揭示 / 够了却不揭示）
   - 开局没有清零（上一局的鉴定态漏进新局）
   - **RNG 流被移动**（回归哨兵，对应 §四）
3. **反向验证（强制）**：至少四条真的改坏、贴真实失败输出、还原。
