# U22b：发现屏按 CE 规则显示（修正 U22 任务书的错误要求）

> **本地执行（Windows 轨）。X-0 路线；U22 的修正轮。**

## 0. 背景：验收方任务书写错了 CE 事实

U22 任务书要求"未鉴定显示外观名、不泄漏真名"。U22 执行方核对 CE 后指出——**CE 发现屏会显示所有种类的真名**，
执行方按任务书做了"隐藏真名"。**验收方复核 CE 确认执行方是对的，任务书错了。**本轮按 CE 修回。

CE `IO.c` 约 :4271 `printDiscoveries` / :4372 `printDiscoveriesScreen`（**请自行核实**）：
- 只列 5 类：SCROLLS、RINGS、POTIONS、STAFFS、WANDS（布局：卷轴+戒指一列、药水一列、法杖+魔杖一列）
- 每种都显示**真名**（`theTable[i].name`，大写）
- 已鉴定：白色 + 物品字形；未鉴定：暗灰色 + 已揭示的善/恶魔法符号（`magicCharDiscoverySuffix`）+
  **" (N%)"——该种类在同类未鉴定种类频率中的占比**（`frequency*100/totalFrequency`，整数除法；frequency 0 不显示）
- 这不泄漏"哪个外观对应哪个种类"——它只告诉玩家种类清单与概率

## 1. 范围

- 按上述规则改 U22 的 `Discoveries.ts` / `ReferenceOverlay.vue`（U22 已合并在 main 上，请先读它的实现与报告）
- **种类集合**：用 web 当前**实际可生成**的目录（退池项不列）计算频率；CE 有而 web 没有的种类（如部分戒指/药水）
  **不显示匿名占位**，在报告里列出缺失清单（归各物品轮）——U22 的"匿名项"做法撤回
- 背包详情等其他界面的"不泄漏外观↔种类映射"规则**保持不变**（那部分 U22 是对的）
- 频率百分比的整数截断与 CE 一致，写黄金值测试
