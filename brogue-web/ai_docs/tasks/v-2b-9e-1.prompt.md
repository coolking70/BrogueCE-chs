## 1. 本轮要补的机制

**web 至今没有区域机器 interior 生长。** `buildAMachine` 的 `else` 分支注释自陈：

> `BP_ROOM（web 全部非前厅蓝图的形态，CE :1080-1118）`

即所有非前厅蓝图都走 `findGateRoom`。而 CE 有两条 interior 来源：

| CE 位置 | 分支 | 服务对象 |
|---|---|---|
| `Architect.c:1080-1118` | `findSuitableRoom` | **`BP_ROOM`** |
| **`Architect.c:1145-1205`** | **随机选点 + 距离图外壳生长** | **既非 `BP_ROOM` 也非 `BP_VESTIBULE`** |

### CE 区域分支的结构（`:1145-1205`，自行复核行号）

```
locationFailsafe = 10;
do {
    zeroOutGrid(interior); tryAgain = false;
    if (chooseLocation) randomMatchingLocation(&originLoc, FLOOR, NOTHING, -1);
    calculateDistances(distanceMap, originX, originY, T_PATHING_BLOCKER, NULL, true, false);
    totalFreq = rand_range(roomSize[0], roomSize[1]);
    // 外壳序收集（for k<1000，按 distanceMap[x][y] == k，sCols/sRows 已洗牌）
    //   命中 HAS_ITEM | HAS_MONSTER | IS_IN_MACHINE ⇒ tryAgain = true 并跳出三重循环
    // :1196-1201 的 BP_TREAT_AS_BLOCKING / BP_REQUIRE_BLOCKING 复核 ⇒ tryAgain = true
} while (chooseBP && tryAgain && --locationFailsafe);
```

⚠️ **失败语义是 `tryAgain` 换位重试**（受 `locationFailsafe = 10` 约束），
**不是硬失败**。9b 曾把 `:1196` 的复核嫁接到 BP_ROOM 路径并写成 `return null`，
造成 Kennel 8 seed × D1-26 建成 0 台的回归——**不要重蹈**。

### web 已有的同构件

`fillVestibuleInterior` 是它的兄弟：Dijkstra 扫距 + 外壳序收集 + 洗牌的 `sCols`/`sRows`。
**大量结构可复用**，但注意差异：
- 前厅从传入 `origin` 出发；区域机器要 `randomMatchingLocation` **随机选点**
- 前厅的 cost 用 web 的 `PDS_FORBIDDEN` 约定；区域用 `T_PATHING_BLOCKER`
- 前厅失败 `return null`（CE 字面）；区域失败 `tryAgain` 重试
- 中止条件：前厅是 `HAS_ITEM`；区域是 `HAS_ITEM | HAS_MONSTER | IS_IN_MACHINE`

`randomMatchingLocation` web 已有（`AutoGenerator.ts` 导出）。**先核它的签名与 CE 是否一致。**

`interiorSatisfiesBlockingFlags` 也已有（B 轮前由 9b 留下，当前只被前厅路径消费）。
**本轮把它接到区域路径**，并按留痕反转改写它头注里"零活载体"的措辞。

## 2. ⚠️ 爆炸半径：21 条蓝图会改变选址

当前这 21 条既无 `BP_ROOM` 也无 `BP_VESTIBULE`，全都错走了 `findGateRoom`：

```
freq>0（活跃抽签）：key_throwing_tutorial_cage(28,8) key_statuary(43,10)
                    key_worm_trap(50,7) key_turret_trap(56,10)
                    key_thief_area(33,10) ce_34_environment(34,13)
                    ce_39_environment(39,3)
freq=0（autoGen 强制或未解锁）：reward_statuary(15) trap_paralysis_revealed(67)
                    trap_paralysis_hidden(68) area_trick_statue(69) area_worm(70)
                    ce_58_bloodwort(58) ce_60_idyll(60) ce_61_swamp(61)
                    ce_62_camp(62) ce_63_remnant(63) ce_64_dismal(64)
                    ce_71_sentinels(71) ce_65_environment(65) ce_66_environment(66)
```

⚠️ **58-64 / 71 是 V-2b-8 好不容易才让它们真正建起来的**（当时实测 3 seed × 78 层
建成 30 台，翻转了 V-1c 以来 thematic 绝迹的状态）；B2 刚实测 CE 71 建成 5 台 / 15 只哨兵。
**路由一改，这些全都换了选址方式。**

⇒ **照 B1 的做法先测后改**：改路由**之前**先跑一遍多 seed × D1-D26，
统计这 21 条各自的建成台数；改完用**同样样本**复测，给前后对照表。
**任何一条从非零掉到零，都要查清原因再决定是缺陷还是合法漂移。**

## 6. 对抗性要求

每条新断言回答「这条用例在什么实现缺陷下会翻红？」，**至少要覆盖**：

1. **路由**：把区域蓝图错送进 `findGateRoom`（即回到现状）会不会红？
2. **失败语义**：把 `tryAgain` 重试写成硬 `return null` 会不会红？
   （这正是 9b 的回归形态——Kennel 被饿死）
3. **中止条件**：漏掉 `HAS_MONSTER` 或 `IS_IN_MACHINE` 会不会红？
4. **blocking 复核**：把"连通/断连"判据抄反会不会红？
   ⚠️ 注意 9b 留下的那条用例舞台有缺陷——它用 `new Grid(15,15)` 而
   `blockingMap` 按 `y * DCOLS + x` 索引。**用 `DCOLS × DROWS` 尺寸的舞台**。
