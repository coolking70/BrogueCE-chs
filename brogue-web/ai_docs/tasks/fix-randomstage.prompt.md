## 0. 环境能力必答（本轮的第二产物）

上一次云端轮次（`audit-seedluck`）报告说：**工作区没有本地 Vitest，`npx` 访问
npm registry 收到 HTTP 403**，因此一个测试都没跑成。之后环境加了 setup script
（`cd brogue-web && npm ci`）并开启了代理网络访问。

**请在报告里如实回答下面四条**（无论成败）：

1. `node_modules` 在你开始时**是否已存在**（setup script 生效了吗）？
2. `npx vitest run src/test/<单个文件>` **能不能跑起来**？若不能，贴原始错误。
3. 能跑的话，**单个测试文件耗时多少**？（挑本轮涉及的三个文件各报一次）
4. 你这次的**总可用时长**大概是多少？有没有被窗口截断的迹象？

这四条比本轮的代码改动更重要——**即使一条都没改成，只要把它们答清楚，本轮就算有价值。**

## 1. 本轮要做什么

修 5 处「用随机地图当测试舞台」的测试。它们的共同病灶：
**前提锚依赖两局随机生成的巧合不相等 / 依赖生成器恰好产出某种对象**，
生成流一动就可能红——而红的是**前提**，不是被测性质。

来源是 `ai_docs/reports/audit-seedluck.report.md` 的风险清单第 2 项分组
（该报告已合并进仓库，**先读它**）。五处：

| # | 位置 | 病灶 | 建议修法（报告原话） |
|---|---|---|---|
| 1 | `p1_31_35_placement_snapshot.test.ts:255-276` | 用 seed42 / seed777 两张随机图制造 stale loopMap，断言两者环路图**不等** | 用人工构造的两张必异网格，或直接污染一个确定格再读档 |
| 2 | `p1_31_35_placement_snapshot.test.ts:292-305` | 同上，waypoint 坐标必须不同 | 人工写入一个不可能由重建产生的 sentinel waypoint |
| 3 | `p2_1_tick_architecture.test.ts:182-194` | 取**首只活着且未关笼的生成怪** | 直接 spawn 一个已知怪，切断生成器依赖 |
| 4 | `p2_1_tick_architecture.test.ts:197-223` | 取**首只速度为 100 的生成怪**（文件注释记载前身曾被怪池变化击中） | 直接 spawn `movementSpeed=100` 的怪 |
| 5 | `b_4b_item_placement.test.ts:335-361` | 取**首个 `quantity>1` 的金币堆和首个合格邻格** | 人工放置 quantity>1 金币；或遍历全部金币并加命中数守卫 |

**核心要求:被测性质一个都不许弱化。** 去耦只换「怎么搭舞台」，不换「断言什么」。
改完每条都要说明：原断言测的是什么、现在还测不测同一件事。

## 2. 硬约束

- **只改这三个测试文件**：`p1_31_35_placement_snapshot.test.ts`、
  `p2_1_tick_architecture.test.ts`、`b_4b_item_placement.test.ts`。
  **不许改 `src/engine/`、`src/data/`、`src/entities/` 任何生产代码**——
  这 5 条全是测试舞台问题，若你认为必须动生产代码，**停下来在报告里说明原因**，不要动手。
- **不要跑全量门禁**（`npx vitest run` 不带文件参数，本地实测 9–26 分钟，会吃光窗口）。
  **只跑这三个文件**，每个都要跑到绿。
- **不要碰 `src/test/fixtures/generation_baseline.json`**。本轮零生产改动 ⇒
  生成流不应移动 ⇒ 基线不该变。**若你发现基线红了，那说明你改到了不该改的地方，停下来报告。**
- `BrogueCE-master/` 只读。

## 3. 反向验证（每条都要）

去耦最容易犯的错是**把舞台搭得太"顺"，顺到测试再也抓不住缺陷**。
对每一条，做一次**故障注入**：把被测机制改坏，确认对应断言翻红，然后还原。

在报告里给出：注入了什么、翻红的断言名与错误消息首行、还原后复绿。
（`grep` 确认无注入残留。）
