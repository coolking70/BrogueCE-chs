# 任务 P1-24：淹死 / 熔岩烧死的怪物根本没死

工作目录已是 `brogue-web/`。C 原版在 `../BrogueCE-master/src/brogue/`（唯一事实来源，**只读**）。

**授权反驳条款有效**：本任务书的事实陈述可能有错，CE 源码优先；若我要求你实现 CE 里不存在的机制，请拒绝并在报告中指出。前几轮开发方多次纠正过我，这很有价值。

## 病灶（验收方探针实测，已记入 `ai_docs/dev_roadmap_2026Q3.md` 的 P1-24）

`Creature.die()`（`src/entities/Creature.ts:157`）只做两件事：

```ts
protected die() {
    this.char = '%';
    this.color = 0x880000;
}
```

**它不把 hp 归零**，而 `Monster` 没有覆盖它。

`Game.applyEnvironmentalEffects()` 的**深水**与**熔岩**两个分支把 `entity.die()` 当作唯一致死手段（其余分支如蒸汽、蔓延死亡都是先 `hp -= N` 再判 `hp <= 0`，不受影响）。结果：怪物"淹死/被烧死"之后满血留在 `this.monsters` 里，`playerTurnEnded` 的 `filter(m => m.hp > 0)` 永远清不掉它。

验收方实测（种子 20260914，一只 6 HP 老鼠）：
```
[深水] 结算后 hp 6->6 char='%' 清扫前在列表=true 清扫后仍在列表=true
[熔岩] 结算后 hp 6->6 char='%' 清扫前在列表=true 清扫后仍在列表=true
```
即：显示成尸体 `%`、继续行动继续攻击，且死亡消息每回合重播一次。

## 必做

1. 让 `die()` 成为**真正的致死收口**（至少把 hp 归零），并**复核全部 `entity.die()` 调用点**的语义——有些调用点是在 `hp -= N` 之后才调的，别把它们改坏或造成重复结算。
2. 死亡消息**不得每回合重播**。
3. `Player` 走的是 `triggerGameOver`，不是 `die()`——确认修改不会影响玩家路径。

## ★ 与 P4-4 的交互（必须处理，且必须有测试）

P4-4 的 `Game.triggerDeathFeatures()` 是**按 `hp <= 0` 扫描**的。修好 `die()` 之后，淹死/烧死的膨胀怪会**开始**触发死亡地形——这在 CE 是正确行为（CE `killCreature` 只在 `MB_IS_FALLING` 时抑制 `MA_DF_ON_DEATH`，见 Combat.c:1963-1965），但会产生两个需要你判断的场景：

- **在水里死的 bloat 会放毒气**：CE 怎么处理？请自己读 `spawnDungeonFeature` 与 `DF_BLOAT_DEATH` 的地形条件后再决定，并在报告说明依据。
- **在水里/岩浆里死的 explosive bloat 会点火**：P4-4 的 `igniteForced` 是**无视地形可燃性**的强制点火。请自行判断"水里燃起大火"是否为 CE 行为，并给出依据。

**必须有一条测试**明确锁住你的结论——无论结论是"照常触发"还是"水中抑制"，都要有断言，不许含糊带过。
