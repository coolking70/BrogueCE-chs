## 病灶

`src/test/p4_9_safety_map.test.ts` 在**全量** `npm test` 中间歇性翻红，**单独跑该文件则稳定全过**。实测约 30% 的运行会红。

**这不是测试脆弱的小问题。** flaky 会训练所有人"红了就重跑"，而红灯一旦变成背景音，真回归就再也拦不住了——这正是 P1-26 退役相位快照要治的同一个病。

更要紧的是：**翻红的主力是 T7「决定性：同种子同局面 → 全图逐格相等 + 轨迹逐位相等（链路零随机）」**。它是一条**决定性守卫**，它红意味着"同样的输入跑两遍得到了不同结果"。真实失败输出：

```
FAIL  T7 决定性：同种子同局面 → 全图逐格相等 + 轨迹逐位相等（链路零随机）
AssertionError: expected 967921860 to be 16587880
  p4_9_safety_map.test.ts:342   const a = run();  const b = run();
```

另有若干次翻红的是 T2（密封走廊解析解），说明**该文件里不止一条测试受影响**。

## 验收方已排除的四个假设（别重复走）

| 假设 | 实测 | 结论 |
|---|---|---|
| vitest 文件级并行导致跨文件状态污染 | `--no-file-parallelism` 下**照样翻红** | 排除 |
| 实体 id 计数器跨局递增影响排序/平手 | 连跑 6 次同场景，id 从 49→229 递增，**safety map hash 完全稳定** | 排除 |
| safety map 链路消耗了随机数 | `updateSafetyMap` 前后 RNG 计数 41→41，**消耗 0 次** | 排除 |
| `timeSystem` 单例未重置 | `Game.ts:396` 有 `timeSystem.currentTick = 0` | 排除 |

**尚未排除的方向**（供参考，不要盲信）：
- T7 的 `run()` 里跑了 4 个回合的 `moveOnce`——**怪物行动、waypoint 滚动刷新（P4-10）、气味图更新（P4-8）都在这条路径上**，其中任何一处的模块级残留或未播种随机都可能让两次 `run()` 分叉。验收方的探针没有跑回合，所以测不到这一段。
- 除 `rng` / `timeSystem` 之外是否还有别的模块级单例跨局残留（logger？waypoint 系统？气味 `turnNumber`？）。

## 必做

1. **定位真因**。建议先把 T7 的 `run()` 拆开、逐步二分（只建场景 → 加 1 回合 → 加 4 回合），确定分叉出现在哪一步；再查该步涉及的全部模块级状态。
2. **根治**，不要靠"重跑就好了"或放宽断言蒙混。若真因是某个单例未重置，就重置它；若是未播种随机，就收编进 `rng`（参考 P2-0 的做法）。
3. **T7 与 T2 必须保持原有的断言强度**——它们是决定性守卫与解析解守卫，不许削弱。若你认为某条断言本身有缺陷，**停下来在报告里说明**，不要自行放宽。
4. **验证**：修好后连跑 **10 次全量** `npm test`，全部绿才算过。报告里贴出 10 次的结果。
