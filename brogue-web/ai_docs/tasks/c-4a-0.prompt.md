## 一、这一轮为什么存在

C-4（`promoteTile` + DF 目录）投不出去，因为它预设了一个 web 没有的底座：

CE 的 `promoteTile(x, y, layer, useFireDF)` **第三个形参就是层**。提升的本质是
"把某一层的地形换成它的 `promoteType`，其他层不动"。CE 每格有四层地形同时存在
（`Rogue.h` `enum dungeonLayers`：`DUNGEON / LIQUID / GAS / SURFACE`）。

web 的 `Grid.ts:Cell` 只有 `terrain: TerrainType` 一个字段。草长在地上是
`terrain = GRASS`——**把地板信息盖掉了**。于是"烧完草还原成什么"在 web 里无解：
只能猜 `FLOOR`，湖岸的草会烧成地板，桥上的草会把桥烧没。

**本轮只做结构迁移，不改任何行为。** 行为变更留给 C-4a 及之后。
之所以单独成轮，正是因为"纯机械变换"可以用**行为逐位不变**这个极强的判据兜底；
和属性表混在一起做就没有这个兜底了。

## 二、要做什么

### 1. `Cell` 增加分层

```ts
export enum DungeonLayer { DUNGEON = 0, LIQUID, GAS, SURFACE, COUNT }
```
（顺序照 CE `Rogue.h`，**注意 CE 的顺序是 DUNGEON / LIQUID / GAS / SURFACE，
GAS 在 SURFACE 前面**，不是直觉的顺序。请自己打开 Rogue.h 确认，我可能记错。）

`Cell` 增加 `layers: TerrainType[]`，长度 4，初值全 `NOTHING`。

### 2. `cell.terrain` 改成 getter，**签名与语义对现有 224 处调用点完全不变**

照 CE `highestPriorityLayer()`（在 `.c` 里，自己 grep 定位）：遍历四层，
取 `layers[tt] != NOTHING` 且 `drawPriority` **最小**者（CE 注释写明"数字越小优先级越高"）。
全空则返回 `NOTHING`。

**`terrain` 必须仍然可读**。全库 143 处非测试引用 + 81 处测试引用一行都不许改
——它们能不改就通过，正是本轮"行为不变"的证据。

### 3. `setTerrain` 的语义：**本轮刻意保持"每格只有一层非空"**

```
setTerrain(x, y, t) =  把 t 写进它的归属层，并把其余三层置 NOTHING
```

这样 `terrain` getter 恒等于 `t`，**与今天的覆盖式赋值逐位等价**。

我知道这让分层看起来是空架子。**这是有意的**：本轮的产物是结构
（Cell 形状、存档 schema、层感知的读写入口、drawPriority 表、归属表），
全部在一个完美的门禁下落地。C-4a 再把"清空其余三层"换成"只清 CE 会清的"，
那时属性表已经在手，分歧可以一个个讲清楚。

### 4. 另开一个**本轮生产代码零调用点**的入口

```ts
setTerrainLayer(x, y, layer, t)   // 只写该层，不动其他层
```
仅由测试行使。**写一条显式留痕测试**，断言"`src/` 生产代码中 `setTerrainLayer`
的调用点数为 0"（用源码扫描实现，像 i18n gate 那样）。C-4a 会把它翻转过来。

### 5. ★ 干跑测量（本轮最有价值的交付物之一）

加一个**仅测试可见**的计数器：在 `setTerrain` 里，当"其余三层里存在非 NOTHING 的层"
而被清掉时，记一次，连同 (被清的层, 被清的地形, 新写入的地形) 一起累计。

然后跑 **15 种子 × D1-D26** 的完整生成，**报告这张表**：
哪些 (层, 旧地形 → 新地形) 组合发生了、各多少次。

这就是"C-4a 放开清空之后会出现多少处分歧"的实测答案。
**不要去修它们**，本轮只测量。

### 6. 存档

`toSnapshot` / `loadSnapshot` 与 `LevelState.baselineTerrains` 都存了 `terrain`。
改为存 `layers`。**旧存档必须仍能读**：读到只有 `terrain` 字段的旧格式时，
走 `setTerrain` 语义还原（即 t 进归属层、其余置空）。写一条断言钉死这条向后兼容。
