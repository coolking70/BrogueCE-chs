## 1. 现象（验收方实测，证据确凿）

场景（现有测试 `src/test/p4_8_scent_map.test.ts` 的 T5）：
一条**笔直走廊**，玩家在 `(54,15)` **原地等待并持续留味**，
一只 **HUNTING 状态**的 rat 从 `(46,15)` 出发，中间隔一扇**关着的门** `(52,15)`。
鼠只需走 **7 格**，有 **10 个回合**，速度与玩家相同。

**实测成功率约 10%**：
- 在 B-4a 之前的 main 上跑 12 个不同 seed → **1 次成功**；
- 在 B-4a 分支上跑 40 个 seed → **5 次成功**（12.5%）。

两边统计一致，说明与 B-4a/B-4b 的改动无关，是**长期存在的行为**。

**玩家侧的表现**：怪物很容易跟丢你。这是目前登记的缺陷里
**唯一玩家能直接感知的行为问题**，所以单开一轮。

## 3. 本轮要求：**先查清，再动手**

这一轮的产出**首先是诊断**，其次才是修复。

### 3.1 诊断阶段（必须做，且必须留下可复核的证据）

写一个一次性测量脚本，把 T5 那个场景跑 **N ≥ 30 个 seed**，对**每一次失败**记录：

1. 鼠每回合的**位置**、**状态**（ASLEEP=0 / WANDERING=1 / HUNTING=2 / FLEEING=3）；
2. 鼠**脚下与 8 邻格的气味值**；
3. 鼠**是从哪条路径退出 HUNTING 的**——web 有两条（见 `Monster.ts` 约 1403-1425）：
   - ①**气味死路**：`scentDirection` 无路 + `isLocalScentMaximum` + 不在玩家视野内
     → WANDERING（CE `Monsters.c:3475-3484`）；
   - ②**感知丢失**：`awareOfTarget` 的 `awareness*3` 硬截断 或 3% 掉落
     → 经 `updateMonsterState` 转 WANDERING（CE `Monsters.c:1776-1779`）。
   **分别统计两条路径各占多少次失败**——这是本轮最关键的一个数字。

把统计表贴进最终回复。**没有这张表，本轮判不合格。**

### 3.2 然后判定性质

拿到数据后回答：**这是 web 与 CE 的偏差，还是 CE 本身就这样？**

- 若是 **web 偏差** → 定位到具体哪一行与 CE 不符，改之；
- 若 **CE 本身也这样**（即 CE 的鼠在同样场景下也只有约 10% 成功率）
  → **不要"修好"它**，那会变成偏离 CE。改为：
  把结论写清楚，并把 `p4_8` T5 的结局断言改成**如实反映该概率**的形态
  （例如多 seed 成功率落在实测带内），让测试不再制造"追踪行为正确"的假象。

判定 CE 行为时，**优先读源码推理**，不要只凭直觉。相关 CE 位置：
`Monsters.c:2842 scentDirection`、`:3244` 与 `:3473` 两个调用点、
`:3466-3484` 的放弃分支、`Time.c:764 updateScent`、
`Movement.c:2875 addScentToCell`、`Rogue.h:1947 T_OBSTRUCTS_SCENT`。

**特别注意 `scentDistance` 的定义**（自己在 CE 里找），以及
`getFOVMask` 用 `T_OBSTRUCTS_SCENT` 算遮罩时门的开合状态——
门在 CE 里带 `TM_PROMOTES_ON_STEP` → `DF_OPEN_DOOR`，
**玩家踩上去会把它变成开门**，开门是否还挡气味、以及玩家走过之后门的状态如何，
直接决定走廊西侧还能不能收到新气味。这条验收方没查，**请你查清并写进报告**。
