## 4. 实现要求

### 4.1 `negationBlast`（CE `Items.c:4827-4879`）

签名 `negationBlast(emitterName, distance)`，卷轴侧 `distance = DCOLS`。
逐条照抄，**不要凭直觉简化**：

1. 消息 `"%s emits a numbing torrent of anti-magic!"`；
2. `colorFlash(&pink, 0, IN_FIELD_OF_VIEW, 3 + distance/5, distance, ...)`
   —— web 若无 `colorFlash` 载体，**跳过并在反驳节登记**，不要自造视觉系统；
3. **先 `negate(&player)`**（玩家自己也吃）；
4. 遍历怪物：命中条件是 `IN_FIELD_OF_VIEW` **且**
   `dx*dx + dy*dy <= distance*distance`（**欧氏距离平方**，不是切比雪夫、不是曼哈顿）；
   注意 CE 注释 `// This can be fatal.` —— `diesIfNegated` 的怪物会当场死；
5. 遍历**地面物品**（`floorItems`），同样的 FOV + 距离² 条件，先
   `flags &= ~(ITEM_MAGIC_DETECTED | ITEM_CURSED)`，再按 category 分派。

**CE 物品字段 → web 字段映射（你必须逐条核对 `Item.ts` 的真实字段名，
验收方只给语义，不保证名字）：**

| CE | 语义 | web 侧应改什么 |
|---|---|---|
| `ITEM_MAGIC_DETECTED` 清除 | 探知标记消失 | `magicDetected = false` |
| `ITEM_CURSED` 清除 | 解除诅咒 | `isCursed = false` |
| WEAPON/ARMOR：`enchant1 = enchant2 = charges = 0` | 附魔归零 | 注意 `Item.ts:88-89` 注明武器/护甲/戒指的 `charges` 被**复用为熟悉度倒计时**（CE `Items.c:275/285/353`）。CE 这里确实把 charges 清零 —— 照抄，并在代码注释里点明这个复用关系 |
| WEAPON/ARMOR：清 `ITEM_RUNIC \| ITEM_RUNIC_HINTED \| ITEM_RUNIC_IDENTIFIED \| ITEM_PROTECTED` + `identify()` | 符文消失并自动鉴定 | `runicType` / `runicKnown` / `isProtected`（B-1a 的 `isProtected` 已存在，见 `scroll_effects.test.ts:71`）|
| STAFF：`charges = 0` | | |
| WAND：`charges = 0` + `ITEM_MAX_CHARGES_KNOWN` | | `Item.ts:103` 有「魔杖已放电次数（CE enchant2）」字段，注意别搞混 charges 与放电计数 |
| RING：`enchant1 = 0` + `ITEM_IDENTIFIED` + `updateIdentifiableItems()` | CE 注释明说：揭示它现在是 +0，但**不必然**揭示是哪种戒指 | 这条语义细节别丢 |
| CHARM：`charges = charmRechargeDelay(kind, enchant1)` | | web 若无护身符系统，登记 deferral |

**只作用于地面物品，不含玩家背包** —— CE 遍历的是 `floorItems`。
若你认为 CE 另有一处对背包生效，**拿行号来反驳**。

### 4.3 `crystalize(radius)`（CE `Items.c:4904-4935`），卷轴侧 `crystalize(9)`

消息（`Items.c:8008`）：`"the scroll emits a wave of turquoise light that pierces the nearby walls!"`。

逐条：

1. 全图双重循环，条件 = 欧氏距离² `<= radius*radius` **且** `!(flags & IMPREGNABLE)`；
2. 仅当该格 **DUNGEON 层**的 tile 带 `T_OBSTRUCTS_PASSABILITY | T_OBSTRUCTS_VISION` 才处理
   —— **读的是 `layers[DUNGEON]`，不是 `cell.terrain` 的最高优先级结果**。
   C-4a-0 已把 `Cell.layers[4]` 与 `DungeonLayer` 搬进 `Grid.ts`，`terrain` 是
   取最高绘制优先级的 getter。这里必须直接读 `layers[DungeonLayer.DUNGEON]`，
   否则地面上盖了 SURFACE 层的墙会被漏判。
3. 命中格 `layers[DUNGEON] = FORCEFIELD`，然后 `spawnDungeonFeature(DF_SHATTERING_SPELL, true, false)`；
4. 若该格有怪物：`MONST_ATTACKABLE_THRU_WALLS` 的怪 → `inflictLethalDamage` + `killCreature`；
   否则 → `freeCaptivesEmbeddedAt(i, j)`。web 无对应载体的，登记 deferral 并说明；
5. **边界格**（`i==0 || i==DCOLS-1 || j==0 || j==DROWS-1`）覆写成 `CRYSTAL_WALL`
   —— CE 注释 `// boundary walls turn to crystal`。这一步在 DF 之后，**顺序别调**；
6. 收尾 `updateVision(false)`。web 的 `updateVision()` 已由 C-7 收尾轮挂进
   `playerTurnEnded`，但 crystalize **当场**改了视线阻挡，必须**立即**重算，
   不能等回合结算。

**新增地形条目**（CE 原文见 `Globals.c:477`/`:478`/`:338`，逐字核对）：

- `FORCEFIELD`：`T_OBSTRUCTS_PASSABILITY | T_OBSTRUCTS_GAS | T_OBSTRUCTS_DIAGONAL_MOVEMENT`，
  `TM_STAND_IN_TILE | TM_VANISHES_UPON_PROMOTION | TM_PROMOTES_ON_CREATURE`，
  `promoteType = DF_FORCEFIELD_MELT`，`promoteChance = -200`（**负值**，C-4c 的
  `promoteTile` 对负 chance 有专门语义 —— 去 `Promotion.ts` 核对 web 是否照抄了，
  没照抄就是本轮要补的洞），`glowLight = FORCEFIELD_LIGHT`。
- `FORCEFIELD_MELT`：同旗标，`promoteChance = -10000`。
- `CRYSTAL_WALL`：`T_OBSTRUCTS_PASSABILITY | T_OBSTRUCTS_ITEMS | T_OBSTRUCTS_GAS |
  T_OBSTRUCTS_SURFACE_EFFECTS | T_OBSTRUCTS_DIAGONAL_MOVEMENT`，
  `TM_STAND_IN_TILE | TM_REFLECTS_BOLTS`，`fireType = DF_PLAIN_FIRE`，
  `glowLight = CRYSTAL_WALL_LIGHT`。

每个新条目都要带 CE `Globals.c` 行号注释（`TerrainCatalog.ts` 现有条目的格式照抄）。
