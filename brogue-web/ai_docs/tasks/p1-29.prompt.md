## 病灶：这是当前就存在的严重 bug，不是还原度不足

验收方实测（5 种子 × D1–D26 = 130 层，按 `Game.canMoveTo` 的真实移动规则从上楼梯泛洪）：

```
16/130 层的下楼梯从上楼梯走不到
扣除 5 层 D26（本身不生成下楼梯）→ 真正坏掉 11/130 ≈ 8.5%
最坏：seed 20260913 D1 从上楼梯只能走到 1 格（345 格孤岛）—— 开局即卡死
      seed 20260916 D14 只够到 20/350
      seed 20260916 D8  只够到 31/337
      seed 31337   D13 只够到 25/323
```

**大约每 12 层就有一层，玩家根本下不去。**

根因：web 铺湖泊时没有连通性验证，直接把深水盖上去（深水在 `canMoveTo` 里不可进入）。

## CE 的做法（已核实）

`designLakes()`（Architect.c:2638-2688）：

```c
for (lakeMaxHeight = 15, lakeMaxWidth = 30; lakeMaxHeight >= 10; lakeMaxHeight--, lakeMaxWidth -= 2) {
    fillGrid(grid, 0);
    createBlobOnGrid(grid, &lakeX, &lakeY, &lakeWidth, &lakeHeight, 5, 4, 4, lakeMaxWidth, lakeMaxHeight, 55, "ffffftttt", "ffffttttt");

    for (k = 0; k < 20; k++) {              // ★ 20 次放置尝试
        x = rand_range(1 - lakeX, DCOLS - lakeWidth - lakeX - 2);
        y = rand_range(1 - lakeY, DROWS - lakeHeight - lakeY - 2);

        if (!lakeDisruptsPassability(grid, lakeMap, -x, -y)) {   // ★ 验证连通
            ...把湖拷进 lakeMap...
            break;
        }
    }
    // 20 次全不通过 → 直接跳过这个湖，继续下一个更小的
}
```

`lakeDisruptsPassability()`（Architect.c:2588-2636）的判据：**把候选湖假想放上去之后，所有"干地"是否仍属同一个 flood-fill 连通块**。任一干地格未被泛洪到，即判定"破坏连通性"，拒绝该位置。

注意 CE 这里泛洪的是**假想放置后的地图**，且只关心"非湖、非阻挡"的干地——不是在真实 `pmap` 上做。

## 本轮范围

### 必做

1. 给 web 的湖泊放置加上**连通性验证**：候选位置若会切断关卡，就换位置重试；重试若干次仍不行就**跳过这个湖**（CE 语义，别硬塞）。
2. 验收判据：上一轮 P1-26 建立的那条留痕断言——「下楼梯不可达的层数恰好等于 N」——**本轮必须把它改成严格 0，并让它真的绿**。这条测试在上一轮是允许你修改的唯一既有断言。
3. 重试次数、尺寸循环等参数**照 CE**（20 次尝试；若 web 的湖泊生成结构与 CE 不同构，用最接近的对应物并在报告说明）。

### 你需要自己判断的事

web 的湖泊生成在 `Architect.ts` 的 `designEnvironmentOvelays`（约 333 行），结构与 CE 的 `designLakes` **不一定同构**。请先读懂 web 现有实现，再决定是：
- (a) 在现有结构上加验证闸门（改动小，但可能只是打补丁）；还是
- (b) 按 CE 重写 `designLakes` / `fillLakes`（更忠实，但改动大、会波及更多）。

**你选，但必须在报告里说明理由与影响面。** 本轮的硬指标只有一个：**不可达层数归零**。

## 测试要求

1. **P1-26 的不可达层数断言改为严格 0 并通过** —— 这是本轮的核心验收。
2. 扩大取样复验：**至少 10 个种子 × D1–D26**，断言零层不可达。报告里贴出实测汇总。
3. **对抗性测试至少三条**：
   - 把验证闸门短路（总是接受候选位置）→ 不可达层数必须回升
   - 重试耗尽后仍强行放置（而非跳过）→ 必须被捕获

4. **反向验证（强制）**：至少两条真的改坏、跑出真实失败输出、粘进报告、再还原。
5. **决定性**：同种子必须生成同一张图，要有测试锁住。
6. **不得靠"少放湖"蒙混**：报告里必须给出修复前后的**湖泊总面积/水格数对比**，证明是"换位置放下了"而不是"干脆不放了"。若确实有湖因 20 次尝试全失败而被跳过，如实报告其频率。
