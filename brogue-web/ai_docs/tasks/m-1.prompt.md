## 1. 背景

CE 有 **8 种戒指**（`ringTable`，`Globals.c:1656-1665`），
web 的 `src/data/arcana.json` 只有 **6 种**：

```
regeneration / awareness / stealth / transference / wisdom / clairvoyance
```

**缺 `light` 与 `reaping`**。这两种在 CE 里是正常参与生成的普通戒指，
web 缺失意味着玩家永远遇不到它们 —— 属内容缺口，不是设计取舍。

本轮把这两条补进目录。

## 2. 要做的事

### 2.1 补两条数据

`src/data/arcana.json` 的 `rings` 数组按现有条目结构新增两条
（现有结构见 `ring_of_regeneration`：
`id / name / minDepth / maxDepth / weight / color / description / frequency`）。

CE 侧的取值（**逐字核对 `Globals.c:1656-1665`**）：

| | CE `marketValue` | CE `frequency` |
|---|---|---|
| `light` | 600 | 1 |
| `reaping` | 700 | 1 |

`range` 两者都是 `{1,3,1}`。**CE 八种戒指的 `frequency` 全部是 1**
（验收方已核对 `Globals.c:1656-1665`，但仍请自验）。

⚠️ web 的 `frequency` 字段语义与 CE 的 `itemTable.frequency` 对齐
（B-4a 已把 `chooseKind` 接成基表频率加权）。
**若你核对后发现上表与 CE 不符，以 CE 为准并在反驳节写明。**

### 2.2 效果文案（描述字段）

CE 的描述原文在同表内，**请逐条核对后再翻译**：

- **`light`**：扩大在深层昏暗环境下的视野半径；
  ⚠️ CE 原文特别注明 **"It will not make you more noticeable to enemies"**
  —— **不会**让你更容易被敌人发现（这一条容易想当然地写反，请照 CE 原文）。
- **`reaping`**：每次击中敌人时为你的**法杖与护符**（staffs **and** charms）充能；
  诅咒版本反而会随每次命中抽干它们。

`description` 字段写中文（与现有六条的风格一致）。

### 2.3 效果是否需要接线

查清这两种戒指在 web 是否**已有消费点**
（`ring_of_light` 的视野加成、`ring_of_reaping` 的充能）：

- **已有消费点** → 补数据即可；
- **无消费点** → **不要自创效果实现**。按本项目惯例：
  数据补上但**登记为"无载体"**，并在报告里写清激活路径。
  （参考 D2 的处理方式与 `invented_content_pool.test.ts` 的既有做法。）

**判断依据要给证据**（grep 结果 / 文件行号），不要凭直觉下结论。
