# 第一件：P1-31 玩家出生/换乘落位在楼梯格上

## 病灶

CE 落位时**明确避开楼梯**（RogueMain.c:839-869）：

```c
if (stairDirection == 1)       player.loc = rogue.upLoc;
else if (stairDirection == -1) player.loc = rogue.downLoc;

placedPlayer = false;
for (dir = 0; dir < 4 && !placedPlayer; dir++) {
    loc = posNeighborInDirection(player.loc, dir);
    if (!cellHasTerrainFlag(loc, T_PATHING_BLOCKER)
        && !(pmapAt(loc)->flags & (HAS_MONSTER | HAS_STAIRS | IS_IN_MACHINE))) {
        placedPlayer = true;
    }
}
if (!placedPlayer) {
    loc = getQualifyingPathLocNear(player.loc, true, T_DIVIDES_LEVEL, 0,
                                   T_PATHING_BLOCKER,
                                   (HAS_MONSTER | HAS_STAIRS | IS_IN_MACHINE), false);
}
player.loc = loc;
```

即：先把 `player.loc` 置为楼梯坐标，**随后在 4 邻域找一个不阻挡通行、
且没有怪物/楼梯/机器的格子落位**；4 邻域都不合格则退到 `getQualifyingPathLocNear`
继续找。**玩家从不站在楼梯上。**

web 直接取楼梯坐标（`Game.ts:851-855` 附近）：
```ts
this.player.loc.x = stairsUpPos.x;
this.player.loc.y = stairsUpPos.y;
```
验收方实测 5 个种子，**开局玩家格地形码全部是 13（STAIRS_UP）**。

## 已经造成的后果

P4-9 的 safety map 因此**整张图退化成平面**：`buildSafetyMap` 里楼梯禁入循环把
玩家格的 `playerCostMap` 从 1 覆盖回 −1，唯一种子零入队、第一段 Dijkstra 零传播，
`safetyNextStep` 在 60 个抽查格上给出方向 **0 个**（逃跑怪全部原地不动）。

P4-9 当时采取的是**局部规避**：把玩家格修正移到楼梯禁入循环之后。
那是**项目里唯一一处明知偏离 CE 还留着的地方**，回退条件就是本条修复。

## 必做

1. 按 CE 实现落位：4 邻域搜索，排除阻挡通行 / 怪物 / 楼梯 / 机器；
   4 邻域不合格则退到"附近合格点"的搜索（web 若无等价函数，用最接近的实现
   并在报告说明）。
2. **回退 P4-9 的有意偏离**：`src/engine/Map/SafetyMap.ts` 的 `buildSafetyMap` 里
   那处"玩家格修正移到楼梯禁入循环之后"的顺序调整，恢复成 CE 的严格顺序。
   该处代码有注释标明是 P4-9 §十三 登记的偏离与回退条件，照它做。
3. 复核 P4-9 的 T8（零改造关卡上的梯度断言）**仍然通过**——这是本条修复没有
   破坏 safety map 的证据。

# 第二件：P1-35 读档后环路偏好静默失效

## 病灶

`Game.loadSnapshot` 从存档重建网格后，**既不恢复也不重算 `loopMap`**
（快照 schema 里也没有这个字段）。读档后 `isInLoop` 返回的是**读档前那一局**的
环路图——与当前地图无关。safety map 的 `IN_LOOP -= 10` 偏好因此按错误的环路图
生效，怪物逃跑路线偏离。**不崩溃、不报错，静默失效。**

这与刚修好的 P1-34 是**同一个不变式的两处漏洞**：
**`loopMap` 必须始终等于当前网格的 `analyzeLoopMap` 结果。**
P1-34 补的是 `generateTestDepth` 那处，修法见
`ai_docs/p1_34_flaky_determinism_report.md`，照同样的方式处理即可。

## 必做

1. 在 `loadSnapshot` 重建网格之后补 `this.loopMap = analyzeLoopMap(this.grid)`。
   `analyzeLoopMap` 是纯函数、零 RNG 消耗，不影响读档的随机流。
2. **顺带复核**：存档往返还有没有别的"生成期派生态"既没被恢复也没被重算？
   已知候选：**waypoint 系统**（`WaypointSystem` 的 `coordinates` / `distanceMaps`，
   P4-10）、**气味图**（`scentTurnNumber`，P4-8）。
   逐个核查并在报告中列出结论；**能顺手补的就补，需要大改的只登记不做**。
