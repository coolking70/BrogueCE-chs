## 2. ⚠️ JS 里"整体复制"的陷阱

CE 的 `*newMonst=*monst` 是 C 结构体按值复制。**在 JS 里用展开运算符或 `Object.assign`
是浅拷贝**——对象里的 `Map` / `Set` / 数组 / 嵌套对象会**被两个实体共享引用**。
之后改克隆体的状态，原体跟着变。

W-0 原话"**不得复制共享 Map/Set 引用**"。⇒ **逐个列出 Monster 上的可变容器字段，
每个都要确认克隆后是独立副本**。给出反向验证：改克隆体的某个状态，原体不变。

同样注意：
- **id 必须新分配**（W-0："快照 id 唯一"），存读档后也唯一
- **leader 指针**、**携物**（W-0："携物不复制"）等**引用型字段**按 CE 语义处理，不能盲目复制

## 5. 教训（已连续二十七轮验证）

闭包走四条边；退池留形 = 加引擎过滤不改数据；覆盖门换样本不改期望；
**「建成 0 台」≠「RNG 足迹为 0」**；驳回给登记位置并区分仍有效/已过期；
**代码事实为真 ≠ 它是本次失败的成因**；CE 里"看起来不一致"的数值先查是不是承重的；
**验收方写的 CE 事实可能是错的，一律自行核实**；
**撞上守卫时改代码，不改守卫、不绕扫描器**；
**复用前轮原语发现不够通用就如实登记前轮缺口**；
**前轮的留痕登记可能正是为你预约的**，动手前 grep 相关注释；
**照搬上一轮的做法前，先确认 CE 在这里是不是也这么做**；
**公式有定点/舍入细节时，编译 CE 原函数取黄金值**；
**自己 W-0 的规格也可能写得不准**；**注释写的是意图，执行路径里可能有例外**；
**"看起来不重要"的 CE 判定位置可能是关键**；
📌 **C 的按值复制在 JS 里是浅拷贝**——结构体整体复制时逐个核对可变容器。
