# V-2b-5 休眠唤醒 + horde 接线轮

## 0. 本轮做什么

CE 的「休眠怪」是机器叙事的核心：雕像破壳而出、墙里钻出蠕虫、炮塔从墙上冒头——
它们在建机器时就已生成，但处于**休眠态**（不在回合调度里、不占格、玩家看不见），
由取钥匙 / 踩触发格触发的 DF 唤醒。web 目前**完全没有这个概念**。

本轮解锁 **8 条**蓝图（勘察报告排的 7 条 + **41 号**——它在 V-2b-3 被推迟，
当时只差 `ALTAR_SWITCH`，本轮正好补上）：

| # | CE 名 | 需要的机制 |
|---|---|---|
| 21 | Statue in the doorway — bursts to reveal monster | HORDE + DORMANT |
| 29 | Rat trap | DORMANT |
| **41** | Explosive situation（V-2b-3 推迟项） | 仅差 `ALTAR_SWITCH` |
| 43 | Statuary（钥匙版） | HORDE + DORMANT |
| 50 | Worms in the walls（钥匙版） | DORMANT |
| 56 | Gauntlet | HORDE + DORMANT |
| 69 | Statue comes alive | HORDE + DORMANT |
| 70 | Worms in the walls（踩触发版） | DORMANT |

## 1. 休眠子系统（CE 三处）

### 1.1 落位时置休眠 — `Architect.c:1655-1660`

```c
if (feature->flags & MF_MONSTERS_DORMANT) {
    toggleMonsterDormancy(monst);
    if (!(feature->flags & MF_MONSTER_SLEEPING) && monst->creatureState != MONSTER_ALLY) {
        monst->creatureState = MONSTER_TRACKING_SCENT;
    }
}
monst->machineHome = machineNumber;   // :1661 怪记住生成它的机器
```

注意那个**否定条件**：不带 `MF_MONSTER_SLEEPING` 的休眠怪，醒来时是
`TRACKING_SCENT`（直接追人）而不是 sleeping。别漏掉。

### 1.2 `toggleMonsterDormancy` — `Monsters.c`

双向开关。**醒来方向**的要点：
- 从 `dormantMonsters` 链表移除、`prependCreature(monsters, …)` 加回正常表；
- 清 `HAS_DORMANT_MONSTER` 格标记；
- **若该格已被占（`HAS_MONSTER | HAS_PLAYER`）则重新选址**
  （`getQualifyingPathLocNear`，带一串 avoided flags）。这一支很容易漏，
  漏了就会出现两只怪叠在同一格。

**睡下方向**同理反向。请完整读该函数再动手，不要只实现醒来那半。

### 1.3 唤醒触发 — `Architect.c:3487-3494`（在 `spawnDungeonFeature` 里）

```c
if (feat->flags & DFF_ACTIVATE_DORMANT_MONSTER) {
    for (creatureIterator it = iterateCreatures(dormantMonsters); hasNextCreature(it);) {
        creature *monst = nextCreature(&it);
        if (monst->loc.x == x && monst->loc.y == y || blockingMap[monst->loc.x][monst->loc.y]) {
            toggleMonsterDormancy(monst);
        }
    }
}
```

⚠️ **唤醒条件是「在原点格」*或*「在 blockingMap 里」** —— 不是只唤醒原点那一只。
DF 铺开多大一片，那片里的休眠怪就全醒。漏掉后半句，雕像群就只会活一个。

### 1.4 web 现状（验收方已量，可复核不必重新发现）

| 件 | 现状 |
|---|---|
| `DFF_ACTIVATE_DORMANT_MONSTER` 旗标 | 已定义（`DungeonFeatureCatalog.ts:42`），**3 条 DF 条目已带它**，但 `spawnDungeonFeature` **零消费** |
| `MF_MONSTERS_DORMANT` | 数据里 **1 个载体**（`reward_statuary`，V-2b-4 落的），引擎**零消费** |
| 休眠怪概念本身 | 引擎侧**完全没有** |

⚠️ **这条会动生成流且容易混进别的成因**：`reward_statuary` 已经带着
`MF_MONSTERS_DORMANT` 但没人消费，本轮一接线，**那条既有蓝图的行为就变了**。
基线归因时把它**单列**，不要混进"八条新蓝图入池"。

**对抗性要求一（沿用）**：若出现"疑似断言过期"的诊断，必须回答
**"如果结论反过来——是实现错——我会看到什么现象？我确认过没看到吗？"**

**对抗性要求二（本轮新增）**：休眠子系统的测试很容易写成"自己证明自己"——
造一个休眠怪、调唤醒、断言它醒了。这种用例在实现写反时也可能通过。
对每个新断言，回答一句：**"这条用例在什么实现缺陷下会翻红？"**
答不上来的用例，说明它只是在描述实现、不是在守卫它。
（上一轮你自己发现 E1 是测量不是守卫并如实标注——就按那个标准。）
